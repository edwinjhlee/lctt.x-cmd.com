Linus Torvalds 是一個糟糕的老闆嗎？ ​

1999 年 8 月 10 日，加利福尼亞州聖何塞市，在 LinuxWorld Show 上 Linus Torvalds 在一個坐滿 Linux 愛好者的禮堂中發表了一篇演講。圖片來自：James Niccolai

這取決於所處的領域。在軟件開發的世界中，他也是個普通人。問題是，這種情況是否應該繼續下去？

Linus Torvalds 是 Linux 的發明者，我認識他超過 20 年了。我們不是密友，但是我們欣賞彼此。

最近，因為 Linus Torvalds 的管理風格，他正遭到嚴厲的炮轟。Linus 無法忍受胡來的人。“代碼的質量有多好？”是他在 Linux 內核的開發過程中評判人的一種方式。

沒有什麼比這個更重要了。正如 Linus 今年（2015年）早些時候在 Linux.conf.au 會議上説的那樣，“我不是一個友好的人，我也不在意你。對我重要的是『我所關心的技術和內核』。”

現在我也可以和這種只關心技術的人打交道了。如果你不能，你應當避免參加 Linux 內核會議，因為在那裏你會遇到許多有這種精英思想的人。這不代表我認為在 Linux 領域所有東西都是極好的，並且不應該受到其他影響而帶來改變。我能夠和一個精英待在一起；而在一個男性做主導的大城堡中遇到的問題是，女性經常受到蔑視和無禮的對待。

這就是我看到的最近關於 Linus 管理風格所引發爭論的原因 -- 或者更準確的説，他對於個人管理方面是完全冷漠的 -- 就像是在軟件開發世界的標準操作流程一樣。與此同時，我看到了揭示了這個事情需要改變的另外一個證據。

第一次是在 Linux 4.3 發佈的時候出現的這個情況，Linus 使用 Linux 內核郵件列表來狠狠的數落了一個插入了一些網絡方面的代碼的開發者——這些代碼很“爛”，“生成了如此爛的代碼。這看起來太糟糕了，並且完全沒有理由這樣做。”他繼續咆哮了半天。這裏使用“爛”這個詞，相對他早期使用的“愚蠢的”這個同義詞來説還算好的。

但是，事情就是這樣。Linus 是對的。我讀了代碼後，發現代碼確實很爛，並且開發者只是為了用新的“overflow_usub()” 函數而用的。

現在，一些人把 Linus 的這種謾罵的行為看作他脾氣不好而且恃強凌弱的證據。我見過一個完美主義者，在他的領域中，他無法忍受這種糟糕。

許多人告訴我，這不是一個專業的程序員應當有的行為。羣眾們，你曾經和最優秀的開發者一起工作過嗎？據我所知道的，在 Apple，Microsoft，Oracle 這就是他們的行為。

我曾經聽過 Steve Jobs 攻擊一個開發者，就像要把他撕成碎片那樣。我也被一個 Oracle 的高級開發者攻擊一屋子的新開發者嚇到過，就像食人魚穿過一羣金魚那樣。

在 Robert X. Cringely 關於 PC 崛起的經典書籍《意外帝國（Accidental Empires）》，中，他這樣描述了微軟的軟件管理風格，比爾·蓋茨像計算機系統一樣管理他們，“比爾·蓋茨的是最高等級，從他開始每一個等級依次遞減，上級會向下級叫嚷，刺激他們，甚至羞辱他們。”

Linus 和所有大型的商業軟件公司的領導人不同的是，Linus 説在這裏所有的東西是向全世界公開的。而其他人是在自己的會議室中做東西的。我聽有人説 Linus 在那種公司中可能會被開除。這是不可能的。他會處於他現在所處的地位，他在編程世界的最頂端。

但是，這裏有另外一個不同。如果 Larry Ellison （Oracle 的首席執行官）向你發火，你就別想在這裏幹了。如果 Linus 向你發火，你會在郵件中收到他的責罵。這就是差別。

你知道的，Linus 不是任何人的老闆。他完全沒有僱傭和解聘的權利，他只是負責着有 10000 個貢獻者的一個項目而已。他僅僅能做的就是從心理上傷害你。

這説明，在開源軟件開發圈和商業軟件開發圈中同時存在一個非常嚴重的問題。不管你是一個多麼好的編程者，如果你是一個女性，你的這個身份就是對你不利的。

這種情況並沒有在 Sarah Sharp 的身上有任何好轉，她現在是一個 Intel 的開發者，以前是一個頂尖的 Linux 程序員。在她Blog上10月份的一個帖子中，她解釋道：“我最終發現，我不能夠再為 Linux 社區做出貢獻了。因為在那裏，我雖然能夠得到技術上的尊重，卻得不到個人的尊重……我不想專職於同那些有着輕微的性別歧視或開同性戀玩笑的人一起工作。”

誰會責怪她呢？我不會。很抱歉，我必須説，Linus 就像所有我見過的軟件經理一樣，是他造成了這種不利的工作環境。

他可能會説，確保 Linux 的貢獻者都表現出專業精神和相互尊重不應該是他的工作。除了代碼以外，他不關心任何其他事情。

就像 Sarah Sharp 寫的那樣：

我對於 Linux 內核社區做出的技術努力表示最大尊重。他們在那維護一些最高標準的代碼，以此來平衡並且發展一個項目。他們專注於優秀的技術，以及超過負荷的維護人員，他們有不同的文化背景和社會規範，這些意味着這些 Linux 內核維護者説話非常直率、粗魯，或者為了完成他們的任務而不講道理。頂尖的 Linux 內核開發者經常為了使別人改正行為而向他們大喊大叫。

這種事情發生在我身上，但它不是一種有效的溝通方式。

許多高級的 Linux 內核開發者支持那些技術上和人性上不講道理的維護者的權利。即使他們自己是非常友好的人，他們不想看到 Linux 內核交流方式改變。

她是對的。

我和其他觀察者不同的是，我不認為這個問題對於 Linux 或開源社區在任何方面有特殊之處。作為一個從事技術商業工作超過五年和有着 25 年技術工作經歷的記者，我見多了這種不成熟的小孩子行為。

這不是 Linus 的錯誤。他不是一個經理，他是一個有想像力的技術領導者。看起來真正的問題是，在軟件開發領域沒有人能夠用一種支持的語氣來對待團隊和社區。

展望未來，我希望像 Linux 基金會這樣的公司和組織，能夠找到一種方式去授權社區經理或其他經理來鼓勵並且強制實施民主的行為。

非常遺憾的是，我們不能夠在我們這種純技術或純商業的領導人中找到這種管理策略。它不存在於這些人的基因中。
