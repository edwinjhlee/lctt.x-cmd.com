Manjaro 和 Arch Linux 有何不同，哪個更好？ ​

Manjaro 還是 Arch Linux？如果説 Manjaro 是基於 Arch 的，那麼它和 Arch 又有什麼不同呢？請在這篇比較文章中閲讀 Arch 和 Manjaro 的不同之處吧。

大多數適合初學者的 Linux 發行版都是基於 Ubuntu 的。隨着 Linux 用户經驗的增加，一些人開始嘗試使用更高級的發行版，主要是在“Arch 領域”。

這個所謂的 “Arch 領域”以兩個發行版為主。Arch Linux 本身和 Manjaro。還有其他基於 Arch 的 Linux 發行版，但都沒有這兩個發行版受歡迎。

如果你在 Arch 和 Manjaro 之間感到困惑，那麼這個比較應該能幫助你。

Manjaro 和 Arch Linux：它們有什麼不同或相似之處？ ​

我試圖在各個方面比較這兩種發行版。請記住，我並沒有只關注差異，我還指出了它們的相似之處。

兩者都是滾動發佈的版本，但不是同一種類型 ​

在 Arch 和 Manjaro 中，沒有像 Ubuntu 或 Fedora 那樣每隔幾個月或幾年就會有一次“發佈”。只要保持你的 Arch 或 Manjaro 系統的更新，你將永遠擁有最新版本的操作系統和軟件包。你不需要像以往一樣擔心升級你的安裝版本。

如果你打算在某個時候進行全新安裝，請記住，Manjaro 和 Arch 都會定期更新它的安裝 ISO。這被稱為 ISO 刷新，它確保新安裝的系統不必安裝過去幾個月中所有可用的新系統更新。

但 Arch 和 Manjaro 的滾動發佈模式是有區別的。

除了社區維護的 Arch 用户軟件庫Arch User Repository（AUR）之外，Manjaro 也維護着自己的獨立軟件庫，這些軟件庫也包含了非 Arch 提供的軟件包。那些原本由 Arch 官方軟件庫提供的流行軟件包將首先進行徹底的測試（必要時打上補丁），然後 Manjaro 再次發佈，這通常比 Arch 晚兩週左右，發佈到 Manjaro 自己的穩定軟件庫供公眾使用。

適應這個測試過程的一個後果是，Manjaro 永遠不會像 Arch 一樣那麼激進嚐鮮。但這樣一來，就使得 Manjaro 比 Arch 稍微穩定一些，也不容易破壞你的系統。

包管理 - Pacman 和 Pamac ​

Arch 和 Manjaro 都提供了基於命令列的軟件包管理工具 Pacman，它是用 C 語言編寫的，使用 tar 來打包應用程序。換句話説，你可以使用相同的 pacman 命令來管理兩個發行版的軟件包。

除了 Pacman，Manjaro 還開發了一個名為 Pamac 的 GUI 應用程序，用於在 Manjaro 上輕鬆安裝軟件。這使得使用 Manjaro 比使用 Arch 更容易。

請注意，你也可以在 Arch Linux 中從 AUR 安裝 Pamac，但該工具是 Manjaro 的組成部分。

Manjaro 硬件檢測工具（MHWD） ​

Pamac 並不是 Manjaro 團隊開發的唯一幫助用户的 GUI 工具。Manjaro 還有一個專門的工具，用於檢測硬件併為其推薦驅動程序。

這個硬件檢測工具非常有用，可以説是 Manjaro 受到社區喜愛的主要原因之一。它使得檢測、安裝、使用或從一個驅動切換到另一個驅動都非常簡單，讓硬件兼容性成為了過去。

驅動程序支持 ​

Manjaro 為 GPU 驅動提供了極大的支持。我們都知道多年來 Linux 在安裝驅動程序（特別是 Nvidia）方面存在問題。

當安裝 Manjaro 時，它給出了從開源（自由）或非開源（非自由）圖形驅動安裝開始的選項。當你選擇“非自由”時，它會自動檢測你的顯卡，併為其安裝最合適的驅動程序，因此 GPU 可以開箱即用。

由於有了上一節中看到的硬件檢測工具，甚至在安裝 Manjaro 時，安裝顯卡驅動會更加容易。

如果你有一個帶有 Nvidia Optimus 卡（混合 GPU）的系統，它與 Manjaro 配合良好。你會有很多方式來讓它工作。

在 Arch Linux 中，你必須為你的機器安裝（如果你能找到）合適的驅動程序。

訪問 Arch 用户軟件庫（AUR） ​

Arch 用户軟件庫（AUR）是一個面向基於 Arch 的 Linux 發行版用户的社區驅動的軟件庫。AUR 的創建是為了組織和分享來自社區的新軟件包，並幫助加快流行軟件包被納入社區軟件庫。

大量進入官方軟件庫的新軟件包都是從 AUR 開始的。在 AUR 中，用户能夠貢獻自己的軟件包構建（PKGBUILD 和相關文件）。

你可以在 Arch 和 Manjaro 中使用 AUR。

桌面環境 ​

好吧！你可以在任何 Linux 發行版上使用幾乎所有的桌面環境。Arch 和 Manjaro 也不例外。

然而，一個專門的桌面風格或版本可以讓用户更容易地在桌面環境裏獲得順暢的體驗。

默認的 Arch ISO 並不包含任何桌面環境。例如，你想在 Arch Linux 上安裝 KDE，你必須在安裝 Arch Linux 時或在之後下載安裝它。

而 Manjaro 則為 Xfce、KDE 和 GNOME 等桌面環境提供了不同的 ISO。Manjaro 社區還維護着 MATE、Cinnamon、LXDE、LXQt、OpenBox 等桌面環境的 ISO。

安裝程序 ​

Manjaro 是基於 Arch Linux 的，它是兼容 Arch 的，但它不是 Arch。它甚至不是隻有一個圖形安裝程序的預配置版本的 Arch。Arch 並不具備通常的舒適的開箱即用，這也是為什麼大多數人喜歡更簡單的東西。Manjaro 為你提供了簡單的入口，但支持你成為經驗豐富的用户或資深用户。

文檔和支持 ​

Arch 和 Manjaro 都有自己的維基頁面和支持論壇來幫助各自的用户。

雖然 Manjaro 有一個不錯的維基文檔，但 Arch 維基則不可同日而語。你可以在 Arch 維基中找到關於 Arch Linux 各方面的詳細信息。

目標受眾 ​

關鍵的區別在於 Arch 針對的是抱着自己動手的態度的用户，他們願意閲讀文檔，自己解決問題。

而 Manjaro 則是針對那些沒有那麼多經驗或者不想花時間組裝操作系統的 Linux 用户。

結論 ​

有些人經常説 Manjaro 是給那些不會安裝 Arch 的人用的。但我認為這是不對的。不是每個人都想從頭配置 Arch，或者沒有太多時間。

Manjaro 絕對是一隻野獸，但與 Arch 截然不同。快速、強大，並總是保持更新，Manjaro 提供了 Arch 操作系統的所有優點，但特別強調穩定性、用户友好性和可訪問性，既適合新手，也適合有經驗的用户。

Manjaro 並不像 Arch Linux 那樣極簡主義。在 Arch 中，你從一個空白的畫布開始，手動調整每個設置。當默認的 Arch 安裝完成後，你在命令列就有了一個正在運行的 Linux 實例。想要一個圖形化桌面環境？那就自己來吧 —— 有很多選擇。選擇一個，安裝，然後配置它。你可以從中學到很多東西，特別是如果你是 Linux 新手的話。你會對系統是如何組合在一起的，以及為什麼要以這樣的方式安裝東西有很好的理解。

我希望你現在對 Arch 和 Manjaro 有了更好的理解。現在，你明白了它們是相似而不同的了吧。

我已經發表了我的看法。不要猶豫，請在評論區分享你的觀點。在 Arch 和 Manjaro 之間，你更喜歡哪一個，為什麼。
