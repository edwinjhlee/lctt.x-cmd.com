Debian OpenSSL Bug - 後門還是安全事故? ​

之前，Ed 寫了篇文章《軟件透明度》，主旨是如果軟件開發的過程是透明的，那麼軟件對惡意的後門（以及無心的安全漏洞）就更具抵抗性。

軟件透明的因素包括公開源代碼，可以閲讀源代碼或為一個項目反饋的問題做出貢獻，以及參與內部開發討論。他提到一種情況，在這兒我想詳細討論一下：在2008年，Debian項目（一個用於web服務器的很流行的linux發行版），宣稱Debian中OpenSSL的偽隨機數生成器遭到破解，已經不安全了。

首先，瞭解一些背景信息：偽隨機數生成器（PRNG）就是一個程序，假定代號為F。給定一個隨機種子s，則會得到一個看起來隨機的長的二進制序列F(s)。如果我和你都使用同樣的種子s，兩個人會得到同樣的二進制序列。但是如果我隨機選擇一個s，也不告訴你s是什麼，你根本不能夠推測F(s)的結果，如你所期望的，F(s)就是隨機的。OpenSSL中的PRNG試圖從系統中抓取不可預測的信息（稱之為"熵"）,比如當前進程ID，或者很有可能是不同的內存內容（比如，由其它一些進程控制或可能控制的未初始化的內存）等等。把這些東西轉換成種子s，就會得到隨機比特流F(s)。

2006年，為了解決一個用於查找軟件內存存取bug的工具的警告問題，一名Debian維護者決定註釋掉OpenSSL PRNG裏的兩行代碼。但是這兩行代碼非常重要，它們負責抓取幾乎所有的不可預測的熵，以作為OpenSSL PRNG的種子。沒有這些代碼，PRNG只有總共32,767個選擇可作為種子s，因而也只有這麼多的F(s)供選擇。

這樣一來，很多依賴於OpenSSL隨機數生成器的程序，其實並沒有它們以為的那麼多的隨機選擇。比如，一個這樣的程序要為SSL（安全網絡瀏覽）和SSH（安全遠程登錄）生成秘鑰。嚴格來説，這些秘鑰必須是隨機的：如果你可以猜到我的秘鑰，你就可以破解我使用該秘鑰保護的任何東西。這意味着你有能力讀取加密的通訊信息，登錄到遠程服務器，或者偽造看起來似乎是真實的信息。這個漏洞是2006年第一次引入，而且進入到Ubuntu中(另一個流行的linux發行版，廣泛應用於網絡服務器)。漏洞影響到數以千計的服務器而且存在了很長一段時間，因為只是給受影響的服務器打補丁還不足以解決問題，必須替換掉任何在漏洞存在情況下生成的秘鑰。

順便説一句，為偽隨機數生成器尋找熵是個著名的難題。事實上，在今天來看要解決這個問題依然是個巨大的挑戰。隨機錯誤難以檢測，因為當你盯着輸出看時，每次運行程序結果都不一樣，就像隨機的一樣。弱隨機性很難發現，但是它可以使（貌似）安全的加密系統失效。不過，Debian中的那個漏洞很醒目，被發現後在安全社區引起了很多嘲笑。

於是有人問，這是個故意設置的後門嗎？似乎不大可能。做出這個更改的代碼維護者 Kurt Roeckx，後來成為Debian項目的主管。這意味着他是個可靠的傢伙，不是為了插入漏洞而由NSA偽造出來的身份。想進入Debian項目組的核心，需要做出巨大的努力，那真是出了名的難進。這樣看來，錯誤根本不是有意為之，而是一系列失誤導致的，而且後果嚴重。

漏洞確實是在一個透明的環境下發生的。所做的任何一件事都是公開的。但是漏洞還是引入了，而且長時間未被注意到。部分原因在於，透明引起了很多混亂，導致本應發現這個顯而易見的漏洞的人們也都沒太在意。 另外，也因為漏洞本身太過微妙，一個隨意的觀察者很難發現修改帶來的影響。

這是否意味着軟件透明沒什麼幫助？ 我可不這麼認為。許多人都贊同透明軟件要比不透明軟件更安全。但是這也並不表示漏洞不會產生，或者認為有其他人都看着呢而我們自己就可以掉以輕心。

至少，多年以後，透明可以讓我們回顧，究竟是什麼導致了某個漏洞--本文例子中，就是工程上的紕漏，而非人為破壞。
