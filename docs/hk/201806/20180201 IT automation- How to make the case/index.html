IT 自動化：如何去實現 ​

想要你的整個團隊都登上 IT 自動化之旅嗎？ IT 執行者們分享了他們的戰略。

在任何重要的項目或主動變更剛開始的時候，IT 的管理者在前進的道路上面臨着普遍的抉擇。

第一條路徑看上去是提供了一個從 A 到 B 的最短路徑：簡單的把項目強制分配給每個人去執行，本質來説就是你要麼按照要求去做要麼就不要做了。

第二條路徑可能看上去會不是很直接，因為要通過這條路徑你需要花時間去解釋項目背後的策略以及原因。你會沿着這條路線設置停靠站點而不是從起點到終點的馬拉松：“這就是我們正在做的 —— 和為什麼我們這麼做。”

猜想一下哪條路徑會贏得更好的結果？

如果你選的是路徑 2，你肯定是以前都經歷過這兩條路徑——而且經歷了第一次的結局。讓人們參與到重大變革中總會是最明智的選擇。

IT 領導者也知道重大的變革總會帶來嚴重的恐慌、懷疑，和其他的挑戰。IT 自動化確實是很正確的改變。這個術語對某些人來説是很可怕的，而且容易被曲解。幫助人們理解你的公司需要 IT 自動化的必要性的原因以及如何去實現是達到你的目標和策略的重要步驟。

[閲讀我們的相關文章，IT自動化最佳實踐：持久成功的7個關鍵點。]

考慮到這一點，我們諮詢了許多 IT 管理者關於如何在你的組織中實現 IT 自動化。

1、向人們展示它的優點 ​

我們要面對的一點事實是：自我利益和自我保護是本能。利用人們的這種本能是一個吸引他們的好方法：向他們展示自動化策略將如何讓他們和他們的工作獲益。自動化將會是軟件管道中的一個特定過程意味着將會減少在半夜呼叫團隊同事來解決故障？它將能讓一些人丟棄技術含量低的技能，用更有策略、高效的有序工作代替手工作業，這將會幫助他們的職業生涯更進一步？

“向他們傳達他們能得到什麼好處，自動化將會如何讓他們的客户和公司受益，”來自 ADP 全球首席技術官 vipual Nagrath 的建議。“將現在的狀態和未來光明的未來進行對比，展現公司將會變得如何穩定，敏捷，高效和安全。”

這樣的方法同樣適用於 IT 領域之外的其他領域；只要在向非技術領域的股東們解讀利益的時候解釋清楚一些術語即可，Nagrath 説道。

設置好前後的情景是一個不錯的幫助人們理解的更透徹的故事機。

“你要描述一幅人們能夠聯想到的當前狀態的畫面，” Nagrath 説。“描述現在是什麼工作，但也要重點強調是什麼導致團隊的工作效率不夠敏捷。”然後再闡釋自動化過程將如何提高現在的狀態。

2、將自動化和特定的商業目標綁定在一起 ​

一個強有力的案列的一部分要確保人們理解你不只是在追逐潮流趨勢。如果只是為了自動化而自動化，人們會很快察覺到進而會更加抵制的——也許在 IT 界更是如此。

“自動化需要商業需求的驅動，例如收入和運營開銷，” Cyxtera的副總裁和首席信息安全官 David Emerson 説道。“沒有自動化的努力是自我辯護的，而且任何技術專長都不應該被當做一種手段，除非它是公司的一項核心能力。”

像 Nagrath 一樣，Emerson 建議將達到自動化的商業目標和獎勵措施掛鈎，用迭代式的循序漸進的方式推進這些目標和相關的激勵措施。

3、 將自動化計劃分解為可管理的條目 ​

即使你的自動化策略字面上是“一切都自動化”，對大多數組織來説那也是很艱難的，而且可能是沒有靈活性的。你需要制定一個強有力的方案，將自動化目標分解為可管理的目標計劃。而且這將能夠創造很大的靈活性來適應之後漫長的道路。

“當制定一個自動化方案的時候，我建議詳細的闡明推進自動化進程的獎勵措施，而且允許迭代朝着目標前進來介紹和證明利益處於一個低風險水平，”Emerson 説道。

GA Connector 的創始人 Sergey Zuev 分享了一個為什麼自動化如此重要的快節奏體驗的報告——它將怎樣為你的策略建立一個強壯持久的論點。Zuevz 應該知道：他的公司的自動化工具將公司的客户關係應用數據導入谷歌分析。但實際上是公司的內部經驗使顧客培訓進程自動化從而出現了一個閃耀的時刻。

“起初， 我們曾嘗試去建立整個培訓機制，結果這個項目擱淺了好幾個月，”Zuev 説道。“認識到這將無法繼續下去之後，我們決定挑選其中的一個能夠有巨大的時效的領域，而且立即啓動。結果我們只用了一週就實現了其中的電子郵件序列的目標，而且我們已經從被褻瀆的體力勞動中獲益。”

4、 出售主要部分也有好處 ​

循序漸進的方法並不會阻礙構建一個宏偉的藍圖。就像以個人或者團隊的水平來制定方案是一個好主意，幫助人們理解全公司的利益也是一個不錯的主意。

“如果我們能夠加速達到商業需求所需的時間，那麼一切質疑將會平息。”

AHEAD 的首席技術官 Eric Kaplan 贊同通過小範圍的勝利來展示自動化的價值是一個贏得人心的聰明策略。但是那些所謂的“小的”的價值揭示能夠幫助你提高人們的整體形象。Kaplan 指出個人和組織間的價值是每個人都可以容易聯繫到的領域。

“最能展現的地方就是你能夠節約多少時間，”Kaaplan 説。“如果我們能夠加速達到商業需求所需的時間，那麼一切質疑將會消失。”

時間和可伸縮性是業務和 IT 同事的強大優勢，都複製業務的增長，可以把握。

“自動化的結果是靈活伸縮的——每個人只需較少的努力就能保持和改善你的 IT 環境”，紅帽的全球服務副總裁 John Allessio 最近提到。“如果增加人力是提升你的商業的唯一途徑，那麼靈活伸縮就是白日夢。自動化減少了你的人力需求而且提供了 IT 演進所需的靈活性和韌性。”(詳細內容請參考他的文章，[DevOps 團隊對 CIO 的真正需求是什麼。])

5、 推廣你的成果。 ​

在你自動化策略的開始時，你可能是在目標和要達到目標的預期利益上制定方案。但隨着你的自動化策略的不斷演進，沒有什麼能夠比現實中的實際結果令人信服。

“眼見為實，”ADP 的首席技術官 Nagrath 説。“沒有什麼比追蹤記錄能夠平息質疑。”

那意味着，不僅僅要達到你的目標，還要準時的完成——這是迭代的循序漸進的方法論的另一個不錯的解釋。

而量化的結果如比利潤的提高或者成本的節省可以大聲宣揚出來，Nagrath 建議他的 IT 領導者同行在講述你們的自動化故事的時候不要僅僅止步於此。

為自動化提供案例也是一個定性的討論，通過它我們能夠促進問題的預防，歸總商業的連續性，減傷失敗或錯誤，而且能夠在他們處理更有價值的任務時承擔更多的責任。
