什麼是 Git 遴選（cherry-pick）？ ​

瞭解 git cherry-pick 命令是什麼，為什麼用以及如何使用。

當你和一羣程序員一起工作時，無論項目大小，處理多個 Git 分支之間的變更都會變得很困難。有時，你不想將整個 Git 分支合併到另一個分支，而是想選擇並移動幾個特定的提交。這個過程被稱為 “遴選cherry-pick”。

本文將介紹“遴選”是什麼、為何使用以及如何使用。

那麼讓我們開始吧。

什麼是遴選？ ​

使用遴選（cherry-pick）命令，Git 可以讓你將任何分支中的個別提交合併到你當前的 Git HEAD 分支中。

當執行 git merge 或者 git rebase 時，一個分支的所有提交都會被合併。cherry-pick 命令允許你選擇單個提交進行整合。

遴選的好處 ​

下面的情況可能會讓你更容易理解遴選功能。

想像一下，你正在為即將到來的每週衝刺實現新功能。當你的代碼準備好了，你會把它推送到遠程分支，準備進行測試。

然而，客户並不是對所有修改都滿意，要求你只呈現某些修改。因為客户還沒有批准下次發佈的所有修改，所以 git rebase 不會有預期的結果。為什麼會這樣？因為 git rebase 或者 git merge 會把上一個衝刺的每一個調整都納入其中。

遴選就是答案！因為它只關注在提交中添加的變更，所以遴選只會帶入批准的變更，而不添加其他的提交。

還有其他幾個原因可以使用遴選：

  • 這對於 bug 修復是必不可少的，因為 bug 是出現在開發分支中對應的提交的。
  • 你可以通過使用 git cherry-pick 來避免不必要的工作，而不用使用其他選項例如 git diff 來應用特定變更。
  • 如果因為不同 Git 分支的版本不兼容而無法將整個分支聯合起來，那麼它是一個很有用的工具。

使用 cherry-pick 命令 ​

在 cherry-pick 命令的最簡單形式中，你只需使用 SHA 標識符來表示你想整合到當前 HEAD 分支的提交。

要獲得提交的哈希值，可以使用 git log 命令：

$ git log --oneline

當你知道了提交的哈希值後，你就可以使用 cherry-pick 命令。

語法是：

$ git cherry-pick <commit sha>

例如：

$ git cherry-pick 65be1e5

這將會把指定的修改合併到當前已簽出的分支上。

如果你想做進一步的修改，也可以讓 Git 將提交的變更內容添加到你的工作副本中。

語法是：

$ git cherry-pick <commit sha> --no-commit

例如：

$ git cherry-pick 65be1e5 --no-commit

如果你想同時選擇多個提交，請將它們的提交哈希值用空格隔開：

$ git cherry-pick hash1 hash3

當遴選提交時，你不能使用 git pull 命令，因為它能獲取一個倉庫的提交並自動合併到另一個倉庫。cherry-pick 是一個專門不這麼做的工具；另一方面，你可以使用 git fetch，它可以獲取提交，但不應用它們。毫無疑問，git pull 很方便，但它不精確。

自己嘗試 ​

要嘗試這個過程，啓動終端並生成一個示例項目：

$ mkdir fruit.git
$ cd fruit.git
$ git init .

創建一些數據並提交：

$ echo "Kiwifruit" > fruit.txt
$ git add fruit.txt
$ git commit -m 'First commit'

現在，通過創建一個項目的復刻來代表一個遠程開發者：

$ mkdir ~/fruit.fork
$ cd !$
$ echo "Strawberry" >> fruit.txt
$ git add fruit.txt
$ git commit -m 'Added a fruit"

這是一個有效的提交。現在，創建一個不好的提交，代表你不想合併到你的項目中的東西：

$ echo "Rhubarb" >> fruit.txt
$ git add fruit.txt
$ git commit -m 'Added a vegetable that tastes like a fruit"

返回你的倉庫，從你的假想的開發者那裏獲取提交的內容：

$ cd ~/fruit.git
$ git remote add dev ~/fruit.fork
$ git fetch dev
remote: Counting objects: 6, done.
remote: Compressing objects: 100% (2/2), done.
remote: Total 6 (delta 0), reused 0 (delta 0)
Unpacking objects: 100% (6/6), done...
$ git log –oneline dev/master
e858ab2 Added a vegetable that tastes like a fruit
0664292 Added a fruit
b56e0f8 First commit

你已經從你想像中的開發者那裏獲取了提交的內容，但你還沒有將它們合併到你的版本庫中。你想接受第二個提交，但不想接受第三個提交，所以使用 cherry-pick。

$ git cherry-pick 0664292

第二次提交現在在你的倉庫裏了：

$ cat fruit.txt
Kiwifruit
Strawberry

將你的更改推送到遠程服務器上，這就完成了！

避免使用遴選的原因 ​

在開發者社區中，通常不鼓勵所以遴選。主要原因是它會造成重複提交，而你也失去了跟蹤你的提交歷史的能力。

如果你不按順序地遴選了大量的提交，這些提交會被記錄在你的分支中，這可能會在 Git 分支中導致不理想的結果。

遴選是一個強大的命令，如果沒有正確理解可能發生的情況，它可能會導致問題。不過，當你搞砸了，提交到錯誤的分支時，它可能會救你一命（至少是你當天的工作）。
