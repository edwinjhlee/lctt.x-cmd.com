Microsoft Linux 沒來，但微軟用更聰明的辦法贏了 ​

老文新評 #062 · ZDNet · 2020-10-12

2020 年 10 月，TechRepublic 的 Jack Wallen 寫了一篇相當激進的長文——"微軟應該直接發佈自己的 Linux 桌面"，不是 WSL、不是 Linux 子系統，而是 OEM 出廠預裝的完整 Linux 發行版，名字都幫你想好了：Microsoft Linux。

6 年後看這事，他猜對了一半——微軟確實在 WSL、Azure、VS Code、PowerShell、Edge 這些層面深度擁抱了 Linux。但 OEM 出廠預裝 Microsoft Linux？沒發生。微軟選了另一條路。

2020 年的微軟處於一個微妙的轉型期：Azure 已經是雲市場老二、Windows 桌面市場開始被 Chromebook 和 Mac 蠶食、WSL 已經迭代到第二代（帶真 Linux 內核）、VS Code 成為最流行的跨平台編輯器。那一年也是疫情爆發期，遠程辦公突然成為主流，Linux 桌面首次真正進入主流企業視野。Wallen 這篇文章正是在這個時間窗口提出「微軟應該 all-in Linux」——結合 Eric Raymond 當時那條「桌面戰爭終戰」的論點。

文章講了啥 ​

Wallen 的核心論點可以拆成幾條：

  • Azure 是新搖錢樹，Windows 不是：微軟已經在雲上贏了，沒必要為 Windows 桌面續命
  • 微軟應該"登月式飛躍"：不是"在 Linux 內核上跑 Windows 界面"，而是直接發佈完整的 Microsoft Linux 發行版
  • OEM 全切換：大賣場 PC 出廠直接裝 Microsoft Linux，沒有"半途而廢的餘地"
  • 保留 Windows Defender：用户需要防釣魚/惡意 URL，Defender 應該原生集成到 Linux 版
  • 保留 Microsoft 365：通過 SaaS 提供，用户感受不到 Windows 沒了
  • 桌面環境二選一或定製：GNOME/KDE/Pantheon/Xfce 任選，UI 可以做成"看起來像 Windows"

核心收益：用户得到更穩定更安全的桌面、IT 不用天天修 Windows 漏洞、Linux 社區終於主導桌面。

這些觀點今天還成立嗎？ ​

當時的判斷現在 (2026)評分
微軟會發完整 Linux 桌面發行版沒發生，微軟選了"嵌入 Linux 到 Windows"路線❌
Azure 才是微軟的未來Azure 現在是雲市場第二，Office 365 + Azure 主導營收✅
OEM 出廠裝 Linux 能主導桌面Steam Deck 證明了 Linux 桌面可行，但 OEM 沒跟⚠️
Windows Defender 應該上 LinuxMicrosoft Defender for Linux 已存在，但定位不同⚠️
用户能接受"看起來像 Windows 的 Linux"WSL + Windows 11 實現了類似體驗⚠️

現在 (2026) 再讀這篇文章 ​

Wallen 錯在他假設微軟會做"激進的戰略轉向"，但微軟選了更聰明的漸進路線——把 Linux 嵌入 Windows（WSL）、把 Windows 服務搬到 Linux（SQL Server、Edge、Defender）、把 Linux 體驗帶給所有人（VS Code、GitHub Codespaces）。

OEM 沒出廠預裝 Microsoft Linux，但Microsoft Surface 現在默認帶 WSL，Windows 11 也能跑 Linux GUI 應用。從用户體驗角度，"我既能跑 Windows 軟件又能用 Linux 工具"這個目標已經達成，只是實現路徑不同。

更重要的是，Wallen 當年沒看到的變量：AI Agent 時代到來。2026 年的開發者並不在意「用 Windows 還是 Linux」，他們在乎「AI Agent 能不能跑在本地」。微軟押對的是 GitHub Copilot + VS Code + Azure AI 這條路，不是操作系統本身。

Wallen 2020 年提出「Microsoft Linux」——路徑沒押對，但 Azure + WSL + VS Code 這套「嵌入 Linux」路線微軟走得更好。
