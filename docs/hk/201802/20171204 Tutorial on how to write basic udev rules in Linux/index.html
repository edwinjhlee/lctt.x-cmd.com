在 Linux 中如何編寫基本的 udev 規則 ​

讀者對象 ​

理解 udev 背後的基本概念，學習如何寫簡單的規則。

要求 ​

  • root 權限

難度 ​

中等

約定 ​

  • # - 要求給定的命令使用 root 權限或者直接以一個 root 用户或者使用 sudo 命令去運行。
  • $ - 要求給定的命令以一個普通的非特權用户運行。

介紹 ​

在 GNU/Linux 系統中，雖然設備的底層支持是在內核層面處理的，但是，它們相關的事件管理是在用户空間中通過 udev 來管理的。確切地説是由 udevd 守護進程來完成的。學習如何去寫規則，並應用到發生的這些事件上，將有助於我們修改系統的行為並使它適合我們的需要。

規則如何組織 ​

udev 規則是定義在一個以 .rules 為擴展名的文件中。那些文件主要放在兩個位置：/usr/lib/udev/rules.d，這個目錄用於存放系統安裝的規則；/etc/udev/rules.d/ 這個目錄是保留給自定義規則的。

定義那些規則的文件的命名慣例是使用一個數字作為前綴（比如，50-udev-default.rules），並且以它們在目錄中的詞彙順序進行處理的。在 /etc/udev/rules.d 中安裝的文件，會覆蓋安裝在系統默認路徑中的同名文件。

規則語法 ​

如果你理解了 udev 規則的行為邏輯，它的語法並不複雜。一個規則由兩個主要的節構成：match 部分，它使用一系列用逗號分隔的鍵定義了規則應用的條件，而 action 部分，是當條件滿足時，我們執行一些動作。

測試案例 ​

講解可能的選項的最好方法莫過於配置一個真實的案例，因此，我們去定義一個規則作為演示，當鼠標被連接時禁用觸摸板。顯然，在該規則定義中提供的屬性將反映我的硬件。

我們將在 /etc/udev/rules.d/99-togglemouse.rules 文件中用我們喜歡的文本編輯器來寫我們的規則。一條規則定義允許跨多個行，但是，如果是這種情況，必須在一個換行字符之前使用一個反斜線（\）表示行的延續，就和 shell 腳本一樣。這是我們的規則：

ACTION=="add" \
, ATTRS{idProduct}=="c52f" \
, ATTRS{idVendor}=="046d" \
, ENV{DISPLAY}=":0" \
, ENV{XAUTHORITY}="/run/user/1000/gdm/Xauthority" \
, RUN+="/usr/bin/xinput --disable 16"

我們來分析一下這個規則。

操作符 ​

首先，對已經使用以及將要使用的操作符解釋如下：

== 和 != 操作符 ​

== 是相等操作符，而 != 是不等於操作符。通過使用它們，我們可以確認規則上應用的鍵是否匹配各自的值。

分配操作符 = 和 := ​

= 是賦值操作符，是用於為一個鍵賦值。當我們想要賦值，並且想確保它不會被其它規則所覆蓋，我們就需要使用 := 操作符來代替，使用這個操作符分配的值，它就不能被改變。

+= 和 -= 操作符 ​

+= 和 -= 操作符各自用於從一個指定的鍵定義的值列表中增加或者移除一個值。

我們使用的鍵 ​

現在，來分析一下在這個規則中我們使用的鍵。首先，我們有一個 ACTION 鍵：通過使用它，當在一個設備上發生了特定的事件，我們將指定我們要應用的規則的具體內容。有效的值有 add、remove  以及 change。

然後，我們使用 ATTRS 關鍵字去指定一個屬性去匹配。我們可以使用 udevadm info 命令去列出一個設備屬性，提供它的名字或者 sysfs 路徑即可：

udevadm info -ap /devices/pci0000:00/0000:00:1d.0/usb2/2-1/2-1.2/2-1.2:1.1/0003:046D:C52F.0010/input/input39

上面截取了運行這個命令之後的輸出的一部分。正如你從它的輸出中看到的那樣，udevadm 從我們提供的指定路徑開始，並且提供了所有父級設備的信息。注意設備的屬性都是以單數的形式報告的（比如，KERNEL），而它的父級是以複數形式出現的（比如，KERNELS）。父級信息可以做為規則的一部分，但是同一時間只能有一個父級可以被引用：不同父級設備的屬性混合在一起是不能工作的。在上面我們定義的規則中，我們使用了一個父級設備屬性：idProduct 和 idVendor。

在我們的規則中接下來做的事情是，去使用 ENV 關鍵字：它既可以用於設置也可以用於去匹配環境變量。我們給 DISPLAY 和 XAUTHORITY 分配值。當我們使用 X 服務器程序進行交互去設置一些需要的信息時，這些變量是非常必要的：使用 DISPLAY 變量，我們指定服務器運行在哪個機器上，用的是哪個顯示和屏幕；使用 XAUTHORITY 提供了一個文件路徑，其包含了 Xorg 認證和授權信息。這個文件一般位於用户的家目錄中。

最後，我們使用了 RUN 字：它用於運行外部程序。非常重要：這裏沒有立即運行，但是一旦所有的規則被解析，將運行各種動作。在這個案例中，我們使用 xinput 實用程序去改變觸摸板的狀態。我不想解釋這裏的 xinput 的語法，它超出了本文的範圍，只需要注意這個觸摸板的 ID 是 16。

規則設置完成之後，我們可以通過使用 udevadm test 命令去調試它。這個命令對調試非常有用，它並不真實去運行 RUN 指定的命令：

$ udevadm test --action="add" /devices/pci0000:00/0000:00:1d.0/usb2/2-1/2-1.2/2-1.2:1.1/0003:046D:C52F.0010/input/input39

我們提供給命令的是使用 --action 選項，以及設備的 sysfs 路徑的模擬動作。如果沒有報告錯誤，説明我們的規則運行的很好。要在真實的環境中去使用它，我們需要重新加載規則：

# udevadm control --reload

這個命令將重新加載規則文件，但是，它只對重新加載之後發生的事件有效果。

我們通過創建一個 udev 規則瞭解了基本的概念和邏輯，這只是 udev 規則中眾多的選項和可能的設置中的一小部分。udev 手冊頁提供了一個詳盡的列表，如果你想深入瞭解，請參考它。
