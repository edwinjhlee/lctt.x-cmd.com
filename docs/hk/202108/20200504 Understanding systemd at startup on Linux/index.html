理解 systemd 啓動時在做什麼 ​

systemd 啓動過程提供的重要線索可以在問題出現時助你一臂之力。

在本系列的第一篇文章《學着愛上 systemd》，我考察了 systemd 的功能和架構，以及圍繞 systemd 作為古老的 SystemV 初始化程序和啓動腳本的替代品的爭論。在這第二篇文章中，我將開始探索管理 Linux 啓動序列的文件和工具。我會解釋 systemd 啓動序列、如何更改默認的啓動目標（即 SystemV 術語中的運行級別）、以及在不重啓的情況下如何手動切換到不同的目標。

我還將考察兩個重要的 systemd 工具。第一個 systemctl 命令是和 systemd 交互、向其發送命令的基本方式。第二個是 journalctl，用於訪問 systemd 日誌，後者包含了大量系統歷史數據，比如內核和服務的消息（包括指示性信息和錯誤信息）。

務必使用一個非生產系統進行本文和後續文章中的測試和實驗。你的測試系統需要安裝一個 GUI 桌面（比如 Xfce、LXDE、Gnome、KDE 或其他）。

上一篇文章中我寫道計劃在這篇文章創建一個 systemd 單元並添加到啓動序列。由於這篇文章比我預期中要長，這些內容將留到本系列的下一篇文章。

使用 systemd 探索 Linux 的啓動 ​

在觀察啓動序列之前，你需要做幾件事情得使引導和啓動序列開放可見。正常情況下，大多數發行版使用一個開機動畫或者啓動畫面隱藏 Linux 啓動和關機過程中的顯示細節，在基於 Red Hat 的發行版中稱作 Plymouth 引導畫面。這些隱藏的消息能夠向尋找信息以排除程序故障、或者只是學習啓動序列的系統管理員提供大量有關係統啓動和關閉的信息。你可以通過 GRUB（大統一引導加載器Grand Unified Boot Loader）配置改變這個設置。

主要的 GRUB 配置文件是 /boot/grub2/grub.cfg ，但是這個文件在更新內核版本時會被覆蓋，你不會想修改它的。相反，應該修改用於改變 grub.cfg 默認設置的 /etc/default/grub 文件。

首先看一下當前未修改的 /etc/default/grub 文件的版本：

[root@testvm1 ~]# cd /etc/default ; cat grub
GRUB_TIMEOUT=5
GRUB_DISTRIBUTOR="$(sed 's, release .*$,,g' /etc/system-release)"
GRUB_DEFAULT=saved
GRUB_DISABLE_SUBMENU=true
GRUB_TERMINAL_OUTPUT="console"
GRUB_CMDLINE_LINUX="resume=/dev/mapper/fedora_testvm1-swap rd.lvm.
lv=fedora_testvm1/root rd.lvm.lv=fedora_testvm1/swap rd.lvm.lv=fedora_
testvm1/usr rhgb quiet"
GRUB_DISABLE_RECOVERY="true"
[root@testvm1 default]#

GRUB 文檔 的第 6 章列出了 /etc/default/grub 文件的所有可用項，我只關注下面的部分：

  • 我將 GRUB 菜單倒計時的秒數 GRUB_TIMEOUT，從 5 改成 10，以便在倒計時達到 0 之前有更多的時間響應 GRUB 菜單。
  • GRUB_CMDLINE_LINUX 列出了引導階段傳遞給內核的命令列參數，我刪除了其中的最後兩個參數。其中的一個參數 rhgb 代表 “紅帽圖形化引導Red Hat Graphical Boot”，在內核初始化階段顯示一個小小的 Fedora 圖標動畫，而不是顯示引導階段的信息。另一個參數 quiet，屏蔽顯示記錄了啓動進度和發生錯誤的消息。系統管理員需要這些信息，因此我刪除了 rhgb 和 quiet。如果引導階段發生了錯誤，屏幕上顯示的信息可以指向故障的原因。

更改之後，你的 GRUB 文件將會像下面一樣：

[root@testvm1 default]# cat grub
GRUB_TIMEOUT=10
GRUB_DISTRIBUTOR="$(sed 's, release .*$,,g' /etc/system-release)"
GRUB_DEFAULT=saved
GRUB_DISABLE_SUBMENU=true
GRUB_TERMINAL_OUTPUT="console"
GRUB_CMDLINE_LINUX="resume=/dev/mapper/fedora_testvm1-swap rd.lvm.
lv=fedora_testvm1/root rd.lvm.lv=fedora_testvm1/swap rd.lvm.lv=fedora_
testvm1/usr"
GRUB_DISABLE_RECOVERY="false"
[root@testvm1 default]#

grub2-mkconfig 程序使用 /etc/default/grub 文件的內容生成 grub.cfg 配置文件，從而改變一些默認的 GRUB 設置。grub2-mkconfig 輸出到 STDOUT，你可以使用程序的 -o 參數指明數據流輸出的文件，不過使用重定向也同樣簡單。執行下面的命令更新 /boot/grub2/grub.cfg 配置文件：

由於數據流可能長達幾十萬甚至幾百萬行，我在這裏截斷了它。（我的主要工作站上列出的日誌長度是 1,188,482 行。）請確保是在你的測試系統嘗試的這個命令。如果系統已經運行了一段時間 —— 即使重啓過很多次 —— 還是會顯示大量的數據。查看這些日誌數據，因為它包含了很多信息，在進行問題判斷時可能非常有用。瞭解這個數據文件在正常的引導和啓動過程中的模樣，可以幫助你在問題出現時定位問題。

我將在本系列之後的文章討論 systemd 日誌、journalctl 命令、以及如何整理輸出的日誌數據來尋找更詳細的信息。

內核被 GRUB 加載到內存後，必須先將自己從壓縮後的文件中解壓出來，才能執行任何有意義的操作。解壓自己後，內核開始運行，加載 systemd 並轉交控制權。

引導boot階段到此結束，此時 Linux 內核和 systemd 正在運行，但是無法為用户執行任何生產性任務，因為其他的程序都沒有執行，沒有命令列解釋器提供命令列，沒有後台進程管理網絡和其他的通信鏈接，也沒有任何東西能夠控制計算機執行生產功能。

現在 systemd 可以加載所需的功能性單元以便將系統啓動到選擇的目標運行狀態。

目標 ​

一個 systemd 目標target代表一個 Linux 系統當前的或期望的運行狀態。與 SystemV 啓動腳本十分類似，目標定義了系統運行必須存在的服務，以及處於目標狀態下必須激活的服務。圖表 1 展示了使用 systemd 的 Linux 系統可能的運行狀態目標。就像在本系列的第一篇文章以及 systemd 啓動的手冊頁（man bootup）所看到的一樣，有一些開啓不同必要服務的其他中間目標，包括 swap.target、timers.target、local-fs.target 等。一些目標（像 basic.target）作為檢查點使用，在移動到下一個更高級的目標之前保證所有需要的服務已經啓動並運行。

除非開機時在 GRUB 菜單進行更改，systemd 總是啓動 default.target。default.target 文件是指向真實的目標文件的符號鏈接。對於桌面工作站，default.target 通常是 graphical.target，等同於 SystemV 的運行等級 5。對於服務器，默認目標多半是 multi-user.target，就像 SystemV 的運行等級 3。emergency.target 文件類似單用户模式。目標和服務service都是一種 systemd 單元。

下面的圖表，包含在本系列的上一篇文章中，比較了 systemd 目標和古老的 SystemV 啓動運行等級。為了向後兼容，systemd 提供了 systemd 目標別名，允許腳本和系統管理員使用像 init 3 一樣的 SystemV 命令改變運行等級。當然，SystemV 命令被轉發給 systemd 進行解釋和執行。

探索當前的目標 ​

許多 Linux 發行版默認安裝一個 GUI 桌面界面，以便安裝的系統可以像工作站一樣使用。我總是從 Fedora Live USB 引導驅動器安裝 Xfce 或 LXDE 桌面。即使是安裝一個服務器或者其他基礎類型的主機（比如用於路由器和防火牆的主機），我也使用 GUI 桌面的安裝方式。

我可以安裝一個沒有桌面的服務器（數據中心的典型做法），但是這樣不滿足我的需求。原因不是我需要 GUI 桌面本身，而是 LXDE 安裝包含了許多其他默認的服務器安裝沒有提供的工具，這意味着初始安裝之後我需要做的工作更少。

但是，僅僅因為有 GUI 桌面並不意味着我要使用它。我有一個 16 端口的 KVM，可以用於訪問我的大部分 Linux 系統的 KVM 接口，但我和它們交互的大部分交互是通過從我的主要工作站建立的遠程 SSH 連接。這種方式更安全，而且和 graphical.target 相比，運行 multi-user.target 使用更少的系統資源。

首先，檢查默認目標，確認是 graphical.target：

[root@testvm1 ~]# systemctl get-default
graphical.target
[root@testvm1 ~]#

然後確認當前正在運行的目標，應該和默認目標相同。你仍可以使用老方法，輸出古老的 SystemV 運行等級。注意，前一個運行等級在左邊，這裏是 N（意思是 None），表示主機啓動後沒有修改過運行等級。數字 5 是當前的目標，正如古老的 SystemV 術語中的定義：

[root@testvm1 ~]# runlevel
N 5
[root@testvm1 ~]#

注意，runlevel 的手冊頁指出運行等級已經被淘汰，並提供了一個轉換表。

你也可以使用 systemd 方式，命令的輸出有很多行，但確實用 systemd 術語提供了答案：

切換到不同的目標 ​

切換到 multi-user.target 很簡單：

[root@testvm1 ~]# systemctl isolate multi-user.target

顯示器現在應該從 GUI 桌面或登錄界面切換到了一個虛擬控制台。登錄並列出當前激活的 systemd 單元，確認 graphical.target 不再運行：

[root@testvm1 ~]# systemctl list-units --type target

務必使用 runlevel 確認命令輸出了之前的和當前的“運行等級”：

[root@testvm1 ~]# runlevel
5 3

更改默認目標 ​

為了強調一些有助於解釋 systemd 如何管理啓動過程的重要事項，我縮短了這個列表。你應該可以在虛擬機看到完整的目錄和鏈接列表。

default.target 項是指向目錄 /lib/systemd/system/graphical.target 的符號鏈接（軟鏈接），列出那個目錄查看目錄中的其他內容：

[root@testvm1 system]# ll /lib/systemd/system/ | less

你應該在這個列表中看到文件、目錄、以及更多鏈接，但是專門尋找一下 multi-user.target 和 graphical.target。現在列出 default.target（指向 /lib/systemd/system/graphical.target 的鏈接）的內容：

[root@testvm1 system]# cat default.target
#  SPDX-License-Identifier: LGPL-2.1+
#
#  This file is part of systemd.
#
#  systemd is free software; you can redistribute it and/or modify it
#  under the terms of the GNU Lesser General Public License as published by
#  the Free Software Foundation; either version 2.1 of the License, or
#  (at your option) any later version.

[Unit]
Description=Graphical Interface
Documentation=man:systemd.special(7)
Requires=multi-user.target
Wants=display-manager.service
Conflicts=rescue.service rescue.target
After=multi-user.target rescue.service rescue.target display-manager.service
AllowIsolate=yes
[root@testvm1 system]#

graphical.target 文件的這個鏈接描述了圖形用户接口需要的所有必備條件。我會在本系列的下一篇文章至少探討其中的一些選項。

為了使主機啓動到多用户模式，你需要刪除已有的鏈接，創建一個新鏈接指向正確目標。如果你的 PWD 不是 /etc/systemd/system，切換過去：

[root@testvm1 system]# rm -f default.target
[root@testvm1 system]# ln -s /lib/systemd/system/multi-user.target default.target

列出 default.target 鏈接，確認其指向了正確的文件：

[root@testvm1 system]# ll default.target
lrwxrwxrwx 1 root root 37 Nov 28 16:08 default.target -&gt; /lib/systemd/system/multi-user.target
[root@testvm1 system]#

如果你的鏈接看起來不一樣，刪除並重試。列出 default.target 鏈接的內容：

[root@testvm1 system]# cat default.target
#  SPDX-License-Identifier: LGPL-2.1+
#
#  This file is part of systemd.
#
#  systemd is free software; you can redistribute it and/or modify it
#  under the terms of the GNU Lesser General Public License as published by
#  the Free Software Foundation; either version 2.1 of the License, or
#  (at your option) any later version.

[Unit]
Description=Multi-User System
Documentation=man:systemd.special(7)
Requires=basic.target
Conflicts=rescue.service rescue.target
After=basic.target rescue.service rescue.target
AllowIsolate=yes
[root@testvm1 system]#

default.target（這裏其實是指向 multi-user.target 的鏈接）其中的 [Unit] 部分現在有不同的必需條件。這個目標不需要有圖形顯示管理器。

重啓，你的虛擬機應該啓動到虛擬控制台 1 的控制台登錄，虛擬控制台 1 在顯示器標識為 tty1。現在你已經知道如何修改默認的目標，使用所需的命令將默認目標改回 graphical.target。

首先檢查當前的默認目標：

[root@testvm1 ~]# systemctl get-default
multi-user.target
[root@testvm1 ~]# systemctl set-default graphical.target
Removed /etc/systemd/system/default.target.
Created symlink /etc/systemd/system/default.target → /usr/lib/systemd/system/graphical.target.
[root@testvm1 ~]#

輸入下面的命令直接切換到 graphical.target 和顯示管理器的登錄界面，不需要重啓：

[root@testvm1 system]# systemctl isolate default.target

我不清楚為何 systemd 的開發者選擇了術語 isolate 作為這個子命令。我的研究表明指的可能是運行指明的目標，但是“隔離”並終結其他所有啓動該目標不需要的目標。然而，命令執行的效果是從一個運行的目標切換到另一個——在這個例子中，從多用户目標切換到圖形目標。上面的命令等同於 SystemV 啓動腳本和 init 程序中古老的 init 5 命令。

登錄 GUI 桌面，確認能正常工作。

總結 ​

本文探索了 Linux systemd 啓動序列，開始探討兩個重要的 systemd 工具 systemdctl 和 journalctl，還説明了如何從一個目標切換到另一個目標，以及如何修改默認目標。

本系列的下一篇文章中將會創建一個新的 systemd 單元，並配置為啓動階段運行。下一篇文章還會查看一些配置選項，可以幫助確定某個特定的單元在序列中啓動的位置，比如在網絡啓動運行後。
