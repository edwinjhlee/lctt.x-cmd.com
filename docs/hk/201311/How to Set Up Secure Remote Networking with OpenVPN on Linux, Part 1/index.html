Linux上如何通過 OpenVPN 建立安全的遠程連接【上】 ​

一直以來，我們在互聯網上傳輸信息時，都謹慎地為這些信息加密，以防內容泄露出去，特別是在政府的干預下，為網絡上每個字節都進行加密已經變得空前重要了。在這種情況下，OpenVPN 是保障網絡信息安全的首選。今天我們就來學習一下如何架設 OpenVPN，使你可以在任何場所都能安全地訪問家裏的服務器。

VPN 小貼士：很多商業的 VPN 根本不值它們的售價，它們的安全性只比通過 SSL 保護的網站高一點點，原因是它們信任所有客户端。一個真正意義上的 VPN 用於在非可信網絡上連接兩個可信的終端。用户不能隨便找一台 PC 機就能登錄進 VPN，因為你的 VPN 如果能被一台受到病毒感染的 PC 登錄進來，不管它們建立的連接有多麼安全，都不是一件好事情。所以你必須在你的客户端和服務器端都要好好地配置一下 VPN 服務。

OpenVPN 快速入門 ​

你需要兩台不同子網下的計算機，比如同一網絡內一台使用網線的 PC 和一台使用無線 的 PC（或者是 VitualBox 虛擬機上的多台Linux客户機），並且你要知道它們的 IP 地址。這裏分別為這兩台計算機命名為“Studio”和“Shop”，都給它們裝上 OpenVPN。OpenVPN 支持大多數 Linux 發行版，所以你只要用你手頭的安裝包管理軟件就行。本文的包管理器是 Debian、Ubuntu 以及它們的衍生版中使用的 apt-get，下面安裝 OpenVPN：

$ sudo apt-get install openvpn openvpn-blacklist

上面的步驟安裝了 OpenVPN 服務器和一個用於檢查外泄密鑰黑名單的程序。請務必安裝這個黑名單檢查器，因為有一次 Debian 發佈了一個有漏洞的 OpenSSL 軟件，這個軟件裏的隨機碼生成器會產生不可信任的密鑰 —— 產生的這些密鑰不是真正的隨機數，它們可以被預測到。這件事發生在2008年，當時所有使用了這個軟件的人都需要替換掉他們的弱密鑰。即使5年過去了，我們還是建議使用這個黑名單檢查器。

現在讓我們測試下，先為兩台 PC 創建一個不加密的通道。首先互 ping 一下確保它們能連通，然後讓 OpenVPN 處於關閉狀態（我們會在後面手動啓動它）：

$ ps ax|grep openvpn

如果 openvpn 這個後台進程存在，那就 kill 了它。這裏假設“Studio”這台 PC 的 IP 是192.168.1.125，“Shop”的 IP 是192.168.2.125。

現在在“Studio”端開啓一個未加密的連接到“Shop”端：

$ sudo openvpn --remote 192.168.2.125 --dev tun0 --ifconfig 10.0.0.1 10.0.0.2

然後再開一個從“Shop”到“Studio”的連接：

$ sudo openvpn --remote 192.168.1.125 --dev tun0 --ifconfig 10.0.0.2 10.0.0.1

連接成功的話你會看到類似下面的信息：

Wed Oct 16 2013 ******* WARNING *******: all encryption and authentication 
features disabled -- all data will be tunnelled as cleartext
Wed Oct 16 2013 TUN/TAP device tun0 opened
Wed Oct 16 2013 do_ifconfig, tt->ipv6=0, tt->did_ifconfig_ipv6_setup=0
Wed Oct 16 2013 /sbin/ifconfig tun0 10.0.0.1 pointopoint 10.0.0.2 mtu 1500
Wed Oct 16 2013 UDPv4 link local (bound): [undef]
Wed Oct 16 2013 UDPv4 link remote: [AF_INET]192.168.2.125:1194
Wed Oct 16 2013 Peer Connection Initiated with [AF_INET]192.168.2.125:1194
Wed Oct 16 2013 Initialization Sequence Completed

看到“Initialization Sequence Completed”這句話時，説明你的操作成功了。這時你應該能夠 ping 通兩個隧道的 IP：ping 10.0.0.1 和 ping 10.0.0.2。當你建立隧道的時候，你無需在意你所在的網絡，你可以為你的隧道指定任何 IP 地址。關閉隧道請按 Ctrl+c。

現在你可以利用這個隧道打開一個 SSH 會話了。圖1顯示了通過 VPN 隧道登錄 SSH 的例子，這個圖也顯示了有趣的 Message of the Day（MOTD）圖片，圖片來自於Blog《在你的 Linux 系統上放一張奶牛的 MOTD 圖片》：

$ ssh carla@10.0.0.2

加密後的 VPN 隧道 ​

目前為止，我們玩得還不賴，但是沒有使用加密技術，一切都毫無意義，所以我們需要建立一個簡單的靜態密鑰配置文件。不像公鑰基礎設施（PKI），有着根認證中心、可撤消認證等安全措施，我們的加密機制沒有那麼強悍，但是對於僅僅想遠程到家裏的用户來説，已經足夠了。OpenVPN 有提供創建靜態密鑰的命令，我們可以建立目錄存儲密鑰、創建密鑰，並將文件設為對屬主只讀模式：

$ sudo mkdir /etc/openvpn/keys/
$ sudo openvpn --genkey --secret /etc/openvpn/keys/static.key
$ sudo chmod 0400 /etc/openvpn/keys/static.key

這是個明文密鑰，你可以利用文本編輯器打開密鑰文件讀取到它，文件名可以隨意，不一定非得叫“static.key”。將這個密鑰拷到需要通信的兩台電腦上，呵呵，這是對稱加密，而不是公鑰加密。

現在我們要在兩台電腦上完成基本的配置。（在非類 Ubuntu 的系統中，OpenVPN 沒有提供默認的配置文件，但是在 /usr/share/doc/openvpn/ 目錄下會為你提供一個配置文件的樣本。）在我的實驗中，“Studio”是服務器端，“Shop”是一台筆記本電腦，用於登錄到“Studio”中。我的服務器端的配置文件是 /etc/openvpn/studio.conf，它的配置信息如下：

# config for Studio
dev tun
ifconfig 10.0.0.1 10.0.0.2
secret /etc/openvpn/keys/static.key

將配置文件設為只有擁有者有讀寫權限：

$ sudo chmod 0600 /etc/openvpn/studio.conf

客户端的配置文件內容類似，只是多了服務器端的 IP 地址：

# config for Shop
dev tun
ifconfig 10.0.0.2 10.0.0.1
secret /etc/openvpn/keys/static.key
remote 192.168.1.125

注意 ifconfig 那行的 IP 地址的順序，本地的 IP 要放在遠程的 IP 之前。現在啓動服務器端的 OpenVPN，指定服務器端配置文件，客户端操作雷同：

$ sudo openvpn /etc/openvpn/studio.conf
$ sudo openvpn /etc/openvpn/shop.conf

成功建立連接後，你還會看到“Initialization Sequence Completed”這句話，但你不會再看到這句 WARNING（這句話會在你建立了未加密的隧道時出現）：

******* WARNING *******: all encryption and authentication features disabled

防火牆和動態 IP 地址 ​

OpenVPN 本身是比較容易配置的，最麻煩的是處理防火牆和動態 IP 地址。防火牆種類眾多，對於如何配置防火牆不攔截你的隧道，我把這個話題當作家庭作業留給你自己解決:P。OpenVPN 的端口是1194，你可以在防火牆上設置一個轉發規則，用於將消息轉發到你的目標服務器。

接下來處理另一件麻煩事：動態 IP 地址。Dyn.com可以提供一個廉價的方法，為你管理 ISP 分配給你的動態 IP，或者你也可以向你的 ISP 支付一筆費用，從而得到一個靜態 IP。

至此，你可以宣告工作完成了，接下來的任務就是手動開啓服務器端的 OpenVPN，讓它一直運行在那裏，等待你的登錄。你可以將你的筆記本拿到外面，並隨時隨地隨心所欲地連接到服務器。然而，關於 OpenVPN 的操作，我還有一些重要的知識點要講，比如如何為 OpenVPN 設置開機啓動，如何利用 Network Manager 自動建立連接，以及這篇 OpenVPN 教程中最重要的一塊：如何訪問你的遠程服務器上的資源。請看下一篇。
