為什麼 Fedora 一開始允許使用 CC0 許可證 ​

開源是一個具有挑戰性的概念。許多人認為，開源意味着可以任意的使用軟件，並且可以免費下載。這實際上取決於你如何被許可 —— 開發者分享代碼時使用的許可證決定了它。開源軟件可以是收費的，也可以限制你如何去使用它，在極少數情況下，甚至讓你陷入法律糾紛。

Fedora 項目最近決定拒絕所有使用 知識共享Creative Commons “公共領域專用” CC0 許可證的代碼，以避免這種情況的出現。CC0 將從新提交代碼中准許使用的許可證列表中剔除，但是，像藝術品一類的貢獻仍被允許所以它，甚至可能在個案的情況下對當前的軟件包進行逐一的處理。

如果 Fedora 反對一個軟件許可證，通常不會成為新聞。事實上，在那麼多的許可證當中，該項目拒絕了許多許可證。這種情況的意外之處在於，CC0 最初被認為是一個有效的許可證，現在只是由於更大的自由及開源（FOSS）社區內的觀點轉變而被重新分類。

CC0 是因為什麼讓 Fedora 決定停止支持它，這又是否意味着你不能在你自己的項目中使用它呢？

這一段描述讓最熟悉知識共享及其許可系列的人驚訝的是，Fedora 最初批准了 CC0 的軟件。畢竟，知識共享從一開始的目標是為藝術作品提供一系列明確的許可證。該組織的使命和許可證的要求在其名稱“知識共享”中就有所體現。

為了“克服分享信息和創造力的法律障礙”，提供一個自由的框架來為人們組織分享如音樂、醫學或教育材料的資源，知識共享組織的前身——開放內容項目Open Content Project，於 2001 年成立。然而，軟件從來不是它的組成要素。為什麼呢？因為那時，如 MIT、GPL 一類的重要的軟件許可證已經出現了十幾年。

很明顯，如果一家公司不遺餘力地警告你他們製造的東西不適合某種特定用途，你也許應該相信他們。知識共享的 FAQ 列出了一些反對在軟件上使用他們的許可證的令人信服的論據，但對於像 Fedora 項目這樣的用户來説，其中一個問題特別突出：專利權。

鑑於 CC0 許可證是為公共領域的作品準備的，而且通過使用它，創作者明確地“放棄了他或她在版權法下對作品的所有權利”，這似乎矛盾的。但是，問題在於，版權法並不適用於專利。事實上，仔細審視許可證的完整措辭後可以發現，它在一個令人擔憂的部分解決了這個問題，該部分內容如下：“宣告者擁有的任何商標或專利權都沒有被本文本放棄、拋棄、交出、租賃或以其他方式修改。”

換言之，即使被 CC0 許可的東西的作者可能願意放棄對它的權力，但他們仍然可以自由的為它申請專利。更糟糕的是，他們仍然保留着以他們認為合適的方式使用該專利的能力。

理論上來説，這意味着最初在 CC0 下提供的源代碼的人在發佈了代碼之後，他們可能會在之後斷言任何使用該代碼的人侵犯了他們的專利，並要求支付專利費。

這顯然會讓像 Fedora 這樣的項目擔憂。考慮一下這樣的情形：CC0 許可的代碼進入到一個系統的核心，然後被提供給數以百萬計的用户。突然間，不知道從哪裏冒出來的原創作者，聲稱侵犯了專利權，並要求付款。紅帽或 Fedora 的律師可以駁倒這種説法麼？也許吧。那麼，為了查明真相而使用 CC0 代碼值得麼？不值得。

要着重提到的是，這完全不是一個新問題。實際上，早在 2012 年，專利條款就阻止了開源倡議（OSI）許可證的審查委員會，他們無法最終確定 CC0 是否真正符合他們對開源許可證的定義。委員會未能達成一致意見，因為其成員認為將此類條款納入軟件許可將創造一個危險的先例。考慮到 Fedora 動盪的歷史，它最初接受 CC0 的決定着實讓人費解。
