關於 Linux 進程你所需要知道的一切 ​

在這篇指南中，我們會逐步對進程做基本的瞭解，然後簡要看看如何用特定命令[管理 Linux 進程][9]。

進程（process）是指正在執行的程序；是程序正在運行的一個實例。它由程序指令，和從文件、其它程序中讀取的數據或系統用户的輸入組成。

進程的類型 ​

在 Linux 中主要有兩種類型的進程：

  • 前台進程（也稱為交互式進程） - 這些進程由終端會話初始化和控制。換句話説，需要有一個連接到系統中的用户來啓動這樣的進程；它們不是作為系統功能/服務的一部分自動啓動。
  • 後台進程（也稱為非交互式/自動進程） - 這些進程沒有連接到終端；它們不需要任何用户輸入。

什麼是守護進程（daemon） ​

這是後台進程的特殊類型，它們在系統啓動時啓動，並作為服務一直運行；它們不會死亡。它們自發地作為系統任務啓動（作為服務運行）。但是，它們能被用户通過 init 進程控制。

[ ][10]

Linux 進程狀態

在 Linux 中創建進程 ​

（LCTT 譯註：此節原文不確，根據譯者理解重新提供）

在 Linux 中創建進程有三種方式：

fork() 方式 ​

使用 fork() 函數以父進程為藍本複製一個進程，其 PID號與父進程 PID 號不同。在 Linux 環境下，fork() 是以寫複製實現的，新的子進程的環境和父進程一樣，只有內存與父進程不同，其他與父進程共享，只有在父進程或者子進程進行了修改後，才重新生成一份。

system() 方式 ​

system() 函數會調用 /bin/sh –c command 來執行特定的命令，並且阻塞當前進程的執行，直到 command 命令執行完畢。新的子進程會有新的 PID。

exec() 方式 ​

exec() 方式有若干種不同的函數，與之前的 fork() 和 system() 函數不同，exec() 方式會用新進程代替原有的進程，系統會從新的進程運行，新的進程的 PID 值會與原來的進程的 PID 值相同。

Linux 如何識別進程？ ​

由於 Linux 是一個多用户系統，意味着不同的用户可以在系統上運行各種各樣的程序，內核必須唯一標識程序運行的每個實例。

程序由它的進程 ID（PID）和它父進程的進程 ID（PPID）識別，因此進程可以被分類為：

  • 父進程 - 這些是在運行時創建其它進程的進程。
  • 子進程 - 這些是在運行時由其它進程創建的進程。

init 進程 ​

init 進程是系統中所有進程的父進程，它是[啓動 Linux 系統][11]後第一個運行的程序；它管理着系統上的所有其它進程。它由內核自身啓動，因此理論上説它沒有父進程。

init 進程的進程 ID 總是為 1。它是所有孤兒進程的收養父母。（它會收養所有孤兒進程）。

查找進程 ID ​

你可以用 pidof 命令查找某個進程的進程 ID：

# pidof systemd
# pidof top
# pidof httpd

[ ][12]

查找 Linux 進程 ID

要查找當前 shell 的進程 ID 以及它父進程的進程 ID，可以運行：

$ echo $$
$ echo $PPID

[ ][13]

查找 Linux 父進程 ID

在 Linux 中啓動進程 ​

每次你運行一個命令或程序（例如 cloudcmd - CloudCommander），它就會在系統中啓動一個進程。你可以按照下面的方式啓動一個前台（交互式）進程，它會被連接到終端，用户可以發送輸入給它：

# cloudcmd

[ ][14]

啓動 Linux 交互進程

Linux 後台任務 ​

要在後台（非交互式）啓動一個進程，使用 & 符號，此時，該進程不會從用户中讀取輸入，直到它被移到前台。

# cloudcmd &
# jobs

[ ][15]

在後台啓動 Linux 進程

你也可以使用 [Ctrl + Z] 暫停執行一個程序並把它發送到後台，它會給進程發送 SIGSTOP 信號，從而暫停它的執行；它就會變為空閒：

# tar -cf backup.tar /backups/*  #press Ctrl+Z
# jobs

要在後台繼續運行上面被暫停的命令，使用 bg 命令：

# bg

要把後台進程發送到前台，使用 fg 命令以及任務的 ID，類似：

# jobs
# fg %1

[ ][16]

Linux 後台進程任務

你也可能想要閲讀：[如何在後台啓動 Linux 命令以及在終端分離（Detach）進程][17]

Linux 中進程的狀態 ​

在執行過程中，取決於它的環境一個進程會從一個狀態轉變到另一個狀態。在 Linux 中，一個進程有下面的可能狀態：

  • Running - 此時它正在運行（它是系統中的當前進程）或準備運行（它正在等待分配 CPU 單元）。
  • Waiting - 在這個狀態，進程正在等待某個事件的發生或者系統資源。另外，內核也會區分兩種不同類型的等待進程；可中斷等待進程（interruptible waiting processes） - 可以被信號中斷，以及不可中斷等待進程（uninterruptible waiting processes）- 正在等待硬件條件，不能被任何事件/信號中斷。
  • Stopped - 在這個狀態，進程已經被停止了，通常是由於收到了一個信號。例如，正在被調試的進程。
  • Zombie - 該進程已經死亡，它已經停止了但是進程表（process table）中仍然有它的條目。

如何在 Linux 中控制進程 ​

Linux 也有一些命令用於控制進程，例如 kill、pkill、pgrep 和 killall，下面是一些如何使用它們的基本事例：

$ pgrep -u tecmint top
$ kill 2308
$ pgrep -u tecmint top
$ pgrep -u tecmint glances
$ pkill glances
$ pgrep -u tecmint glances

#### 給進程發送信號

Linux 中控制進程的基本方法是給它們發送信號。你可以發送很多信號給一個進程，運行下面的命令可以查看所有信號：

```
$ kill -l
```
[
 ![列出所有 Linux 信號](http://www.tecmint.com/wp-content/uploads/2017/03/list-all-signals.png) 
][29]

*列出所有 Linux 信號*

要給一個進程發送信號，可以使用我們之前提到的 `kill`、`pkill` 或 `pgrep` 命令。但只有被編程為能識別這些信號時程序才能響應這些信號。

大部分信號都是系統內部使用，或者給程序員編寫代碼時使用。下面是一些對系統用户非常有用的信號：

*	SIGHUP 1 - 當控制它的終端被被關閉時給進程發送該信號。
*	SIGINT 2 - 當用户使用 `[Ctrl+C]` 中斷進程時控制它的終端給進程發送這個信號。
*	SIGQUIT 3 - 當用户發送退出信號 `[Ctrl+D]` 時給進程發送該信號。
*	SIGKILL 9 - 這個信號會馬上中斷（殺死）進程，進程不會進行清理操作。
*	SIGTERM 15 - 這是一個程序終止信號（kill 默認發送這個信號）。
*	SIGTSTP 20 - 它的控制終端發送這個信號給進程要求它停止（終端停止）；通過用户按 `[Ctrl+Z]` 觸發。

下面是當 Firefox 應用程序僵死時通過它的 PID 殺死它的 kill 命令事例：

```
$ pidof firefox
$ kill 9 2687
或
$ kill -KILL 2687
或
$ kill -SIGKILL 2687  
```

使用它的名稱殺死應用，可以像下面這樣使用 pkill 或 killall：

```
$ pkill firefox
$ killall firefox 
```

#### 更改 Linux 進程優先級

在 Linux 系統中，所有活躍進程都有一個優先級以及 nice 值。有比點優先級進程有更高優先級的進程一般會獲得更多的 CPU 時間。

但是，有 root 權限的系統用户可以使用 `nice` 和 `renice` 命令影響（更改）優先級。

在 top 命令的輸出中， NI 顯示了進程的 nice 值：

```
$ top  
```

[
 ![列出 Linux 正在運行的進程](http://www.tecmint.com/wp-content/uploads/2017/03/top-command.png) 
][30]

*列出 Linux 正在運行的進程*

使用 `nice` 命令為一個進程設置 nice 值。記住一個普通用户可以給他擁有的進程設置 0 到 20 的 nice 值。

只有 root 用户可以使用負的 nice 值。

要重新設置一個進程的優先級，像下面這樣使用 `renice` 命令：

```
$ renice +8  2687
$ renice +8  2103
```
