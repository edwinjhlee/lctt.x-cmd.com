服務器的 LinuxBoot：告別 UEFI、擁抱開源 ​

LinuxBoot 是私有的 UEFI 固件的開源 替代品。它發佈於去年，並且現在已經得到主流的硬件生產商的認可成為他們產品的默認固件。去年，LinuxBoot 已經被 Linux 基金會接受並納入開源家族。

這個項目最初是由 Ron Minnich 在 2017 年 1 月提出，它是 LinuxBIOS 的創造人，並且在 Google 領導 coreboot 的工作。

Google、Facebook、Horizon Computing Solutions、和 Two Sigma 共同合作，在運行 Linux 的服務器上開發 LinuxBoot 項目（以前叫 NERF）。

它的開放性允許服務器用户去很容易地定製他們自己的引導腳本、修復問題、構建他們自己的 運行時環境 和用他們自己的密鑰去 刷入固件，而不需要等待供應商的更新。

我們來討論一下它與 UEFI 相比在服務器硬件方面的其它優勢。

LinuxBoot 超越 UEFI 的優勢 ​

下面是一些 LinuxBoot 超越 UEFI 的主要優勢：

啓動速度顯著加快 ​

它能在 20 秒鐘以內完成服務器啓動，而 UEFI 需要幾分鐘的時間。

顯著的靈活性 ​

LinuxBoot 可以用在 Linux 支持的各種設備、文件系統和協議上。

更加安全 ​

相比 UEFI 而言，LinuxBoot 在設備驅動程序和文件系統方面進行更加嚴格的檢查。

我們可能爭辯説 UEFI 是使用 EDK II 而部分開源的，而 LinuxBoot 是部分閉源的。但有人提出，即便有像 EDK II 這樣的代碼，但也沒有做適當的審查級別和像 Linux 內核 那樣的正確性檢查，並且在 UEFI 的開發中還大量使用閉源組件。

另一方面，LinuxBoot 有非常小的二進制文件，它僅用了大約幾百 KB，相比而言，而 UEFI 的二進制文件有 32 MB。

嚴格來説，LinuxBoot 與 UEFI 不一樣，更適合於可信計算基礎。

LinuxBoot 有一個基於 kexec 的引導加載器，它不支持啓動 Windows/非 Linux 內核，但這影響並不大，因為主流的雲都是基於 Linux 的服務器。

LinuxBoot 的採用者 ​

自 2011 年， Facebook 發起了開源計算項目（OCP），它的一些服務器是基於開源設計的，目的是構建的數據中心更加高效。LinuxBoot 已經在下面列出的幾個開源計算硬件上做了測試：

  • Winterfell
  • Leopard
  • Tioga Pass

更多 OCP 硬件在這裏有一個簡短的描述。OCP 基金會通過開源系統固件運行一個專門的固件項目。

支持 LinuxBoot 的其它一些設備有：

  • QEMU 仿真的 Q35 系統
  • Intel S2600wf
  • Dell R630

上個月底（2018 年 9 月 24 日），Equus 計算解決方案 宣佈 發行它的 白盒開放式™ M2660 和 M2760 服務器，作為它們的定製的、成本優化的、開放硬件服務器和存儲平台的一部分。它們都支持 LinuxBoot 靈活定製服務器的 BIOS，以提升安全性和設計一個非常快的純淨的引導體驗。
