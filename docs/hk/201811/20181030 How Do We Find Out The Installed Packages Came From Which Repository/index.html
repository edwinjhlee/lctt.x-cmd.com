我們如何得知安裝的包來自哪個倉庫？ ​

有時候你可能想知道安裝的軟件包來自於哪個倉庫。這將幫助你在遇到包衝突問題時進行故障排除。

因為第三方倉庫擁有最新版本的軟件包，所以有時候當你試圖安裝一些包的時候會出現兼容性的問題。

在 Linux 上一切都是可能的，因為你可以安裝一個即使在你的發行版系統上不能使用的包。

你也可以安裝一個最新版本的包，即使你的發行版系統倉庫還沒有這個版本，怎麼做到的呢？

這就是為什麼出現了第三方倉庫。它們允許用户從庫中安裝所有可用的包。

幾乎所有的發行版系統都允許第三方軟件庫。一些發行版還會官方推薦一些不會取代基礎倉庫的第三方倉庫，例如 CentOS 官方推薦安裝 EPEL 庫。

下面是常用的倉庫列表和它們的詳細信息。

  • CentOS： EPEL、ELRepo 等是 Centos 社區認證倉庫。
  • Fedora： RPMfusion 倉庫 是經常被很多 Fedora 用户使用的倉庫。
  • ArchLinux： ArchLinux 社區倉庫包含了來自於 Arch 用户倉庫的可信用户審核通過的軟件包。
  • openSUSE： Packman 倉庫 為 openSUSE 提供了各種附加的軟件包，特別是但不限於那些在 openSUSE Build Service 應用黑名單上的與多媒體相關的應用和庫。它是 openSUSE 軟件包的最大外部軟件庫。
  • Ubuntu：個人軟件包歸檔（PPA）是一種軟件倉庫。開發者們可以創建這種倉庫來分發他們的軟件。你可以在 PPA 導航頁面找到相關信息。同時，你也可以啓用 Cananical 合作伙伴軟件倉庫。

倉庫是什麼？ ​

軟件倉庫是存儲特定的應用程序的軟件包的集中場所。

所有的 Linux 發行版都在維護他們自己的倉庫，並允許用户在他們的機器上獲取和安裝包。

每個廠商都提供了各自的包管理工具來管理它們的倉庫，例如搜索、安裝、更新、升級、刪除等等。

除了 RHEL 和 SUSE 以外大部分 Linux 發行版都是自由軟件。要訪問付費的倉庫，你需要購買其訂閲服務。

為什麼我們需要啓用第三方倉庫？ ​

在 Linux 裏，並不建議從源代碼安裝包，因為這樣做可能會在升級軟件和系統的時候產生很多問題，這也是為什麼我們建議從庫中安裝包而不是從源代碼安裝。

在 RHEL/CentOS 系統上我們如何得知安裝的軟件包來自哪個倉庫？ ​

這可以通過很多方法實現。我們會給你所有可能的選擇，你可以選擇一個對你來説最合適的。

方法-1：使用 yum 命令 ​

RHEL 和 CentOS 系統使用 RPM 包，因此我們能夠使用 Yum 包管理器 來獲得信息。

YUM 即 “Yellodog Updater, Modified” 是適用於基於 RPM 的系統例如 RHEL 和 CentOS 的一個開源命令列前端包管理工具。

yum 是從發行版倉庫和其他第三方庫中獲取、安裝、刪除、查詢和管理 RPM 包的一個主要工具。

apachetop 包來自 EPEL 倉庫。

方法-2：使用 yumdb 命令 ​

yumdb info 提供了類似於 yum info 的信息但是它又提供了包校驗和數據、類型、用户信息（誰安裝的軟件包）。從 yum 3.2.26 開始，yum 已經開始在 rpmdatabase 之外存儲額外的信息（user 表示軟件是用户安裝的，dep 表示它是作為依賴項引入的）。

方法-3：使用 rpm 命令 ​

RPM 命令 即 “Red Hat Package Manager” 是一個適用於基於 Red Hat 的系統（例如 RHEL、CentOS、Fedora、openSUSE & Mageia）的強大的命令列包管理工具。

這個工具允許你在你的 Linux 系統/服務器上安裝、更新、移除、查詢和驗證軟件。RPM 文件具有 .rpm 後綴名。RPM 包是用必需的庫和依賴關係構建的，不會與系統上安裝的其他包衝突。

在 Fedora 系統上我們如何得知安裝的包來自哪個倉庫？ ​

DNF 是 “Dandified yum” 的縮寫。DNF 是使用 hawkey/libsolv 庫作為後端的下一代 yum 包管理器（yum 的分支）。從 Fedora 18 開始 Aleš Kozumplík 開始開發 DNF，並最終在 Fedora 22 上得以應用/啓用。

dnf 命令 用於在 Fedora 22 以及之後的系統上安裝、更新、搜索和刪除包。它會自動解決依賴並使安裝包的過程變得順暢，不會出現任何問題。

在基於 Debian 的系統上我們如何得知安裝的包來自哪個倉庫？ ​

在基於 Debian 的系統例如 Ubuntu、LinuxMint 上可以使用兩種方法實現。

方法-1：使用 apt-cache 命令 ​

apt-cache 命令 可以顯示存儲在 APT 內部資料庫的很多信息。這些信息是一種緩存，因為它們是從列在 source.list 文件裏的不同的源中獲得的。這個過程發生在 apt 更新操作期間。

$ apt-cache policy python3
python3:
  Installed: 3.6.3-0ubuntu2
  Candidate: 3.6.3-0ubuntu3
  Version table:
     3.6.3-0ubuntu3 500
        500 http://in.archive.ubuntu.com/ubuntu artful-updates/main amd64 Packages
 *** 3.6.3-0ubuntu2 500
        500 http://in.archive.ubuntu.com/ubuntu artful/main amd64 Packages
        100 /var/lib/dpkg/status

python3 包來自 Ubuntu updates 倉庫。

方法-2：使用 apt 命令 ​

APT 命令 即 “Advanced Packaging Tool”，是 apt-get 命令的替代品，就像 DNF 是如何取代 YUM 一樣。它是具有豐富功能的命令列工具並將所有的功能例如 apt-cache、apt-search、dpkg、apt-cdrom、apt-config、apt-ket 等包含在一個命令（APT）中，並且還有幾個獨特的功能。例如我們可以通過 APT 輕鬆安裝 .dpkg 包，但我們不能使用 apt-get 命令安裝，更多類似的功能都被包含進了 APT 命令。apt-get 因缺失了很多未被解決的特性而被 apt 取代。
