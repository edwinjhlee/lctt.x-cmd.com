詳解 UEFI 模式下安裝 Linux ​

此頁面是免費瀏覽的，沒有煩人的外部廣告；然而，我的確花了時間準備，網站託管也花了錢。如果您發現此頁面幫到了您，請考慮進行小額捐款，以幫助保持網站的運行。謝謝！ 原著於 2013/10/19；最後修改於 2015/3/16

引言 ​

幾年來，一種新的固件技術悄然出現，而大多數普通用户對此並無所知。該技術被稱為 可擴展固件接口Extensible Firmware Interface（EFI）， 或更新一些的統一可擴展固件接口（Unified EFI，UEFI，本質上是 EFI 2.x），它已經開始替代古老的基本輸入/輸出系統Basic Input/Output System（BIOS）固件技術，有經驗的計算機用户或多或少都有些熟悉 BIOS。

本頁面是給 Linux 用户使用 EFI 技術的一個快速介紹，其中包括有關開始將 Linux 安裝到此類計算機上的建議。不幸的是，EFI 是一個龐雜的話題；EFI 軟件本身是複雜的，許多實現有系統特定的怪異行為甚至是缺陷。因此，我無法在一個頁面上描述在 EFI 計算機上安裝和使用 Linux 的一切知識。我希望你能將本頁面作為一個有用的起點，不管怎麼説，每個部分以及末尾參考文獻部分的鏈接可以指引你找到更多的文檔。

你的計算機是否使用 EFI 技術？ ​

EFI 是一種_固件_，意味着它是內置於計算機中處理低級任務的軟件。最重要的是，固件控制着計算機的引導過程，反過來説這代表着基於 EFI 的計算機與基於 BIOS 的計算機的引導過程不同。（有關此規律的例外之處稍後再説。）這種差異可能使操作系統安裝介質的設計超級複雜化，但是一旦安裝好並運行之後，它對計算機的日常操作幾乎沒有影響。請注意，大多數製造商使用術語 “BIOS” 來表示他們的 EFI。我認為這種用法很混亂，所以我避免了；在我看來，EFI 和 BIOS 是兩種不同類型的固件。

注意：蘋果公司的 Mac 使用的 EFI 在許多方面是不同尋常的。儘管本頁面的大部分內容同樣適用於 Mac，但有些細節上的出入，特別是在設置 EFI 引導加載程序的時候。這個任務最好在 OS X 上進行，使用 Mac 的 bless utility工具，我不在此做過多描述。

自從 2006 年第一次推出以來，EFI 已被用於基於英特爾的 Mac 上。從 2012 年底開始，大多數安裝 Windows 8 或更高版本系統的計算機就已經默認使用 UEFI 啓動，實際上大多數 PC 從 2011 年中期就開始使用 UEFI，雖然默認情況下它們可能無法以 EFI 模式啓動。2011 年前銷出的 PC 也有一些支持 EFI，儘管它們大都默認使用 BIOS 模式啓動。

如果你不確定你的計算機是否支持 EFI，則應查看固件設置實用程序和參考用户手冊關於 EFI、UEFI 以及 legacy booting 的部分。（可以通過搜索用户手冊的 PDF 文件來快速瞭解。）如果你沒有找到類似的參考，你的計算機可能使用老式的（“legacy”） BIOS 引導；但如果你找到了這些術語的參考，幾乎可以肯定它使用了 EFI 技術。你還可以嘗試_只_有 EFI 模式的引導加載器的安裝介質。使用 rEFInd 製作的 USB 閃存驅動器或 CD-R 鏡像是用來測試不錯的選擇。

在繼續之前，你應當瞭解大多數 x86 和 x86-64 架構的計算機上的 EFI 都包含一個叫做兼容支持模組Compatibility Support Module（CSM）的組件，這使得 EFI 能夠使用舊的 BIOS 風格的引導機制來引導操作系統。這會非常方便，因為它向後兼容；但是這樣也導致一些意外情況的發生，因為計算機不論以 EFI 模式引導還是以 BIOS （也稱為 CSM 或 legacy）模式引導，在控制時沒有標準的使用規範和用户界面。特別地，你的 Linux 安裝介質非常容易意外的以 BIOS/CSM/legacy 模式啓動，這會導致 Linux 以 BIOS/CSM/legacy 模式安裝。如果 Linux 是唯一的操作系統，也可以正常工作，但是如果與在 EFI 模式下的 Windows 組成雙啓動的話，就會非常複雜。（反過來問題也可能發生。）以下部分將幫助你以正確模式引導安裝程序。如果你在閲讀這篇文章之前就已經以 BIOS 模式安裝了 Linux，並且希望切換引導模式，請閲讀後續章節，哎呀：將傳統模式下安裝的引導轉為 EFI 模式下的引導。

UEFI 的一個附加功能值得一提：安全啓動Secure Boot。此特性旨在最大限度的降低計算機受到 boot kit 病毒感染的風險，這是一種感染計算機引導加載程序的惡意軟件。Boot kits 很難檢測和刪除，阻止它們的運行刻不容緩。微軟公司要求所有帶有支持 Windows 8 標誌的台式機和筆記本電腦啓用 安全啓動。這一配置使 Linux 的安裝變得複雜，儘管有些發行版可以較好的處理這個問題。不要將安全啓動和 EFI 或 UEFI 混淆；支持 EFI 的計算機不一定支持 安全啓動，而且支持 EFI 的 x86-64 的計算機也可以禁用 安全啓動。微軟同意用户在 Windows 8 認證的 x86 和 x86-64 計算機上禁用安全啓動功能；然而對裝有 Windows 8 的 ARM 計算機而言卻相反，它們必須不允許用户禁用 安全啓動。幸運的是，基於 ARM 的 Windows 8 計算機目前很少見。我建議避免使用它們。

你的發行版是否支持 EFI 技術？ ​

大多數 Linux 發行版已經支持 EFI 好多年了。然而，不同的發行版對 EFI 的支持程度不同。大多數主流發行版（Fedora，OpenSUSE，Ubuntu 等）都能很好的支持 EFI，包括對安全啓動的支持。另外一些“自行打造”的發行版，比如 Gentoo，對 EFI 的支持較弱，但它們的性質使其很容易添加 EFI 支持。事實上，可以向_任意_ Linux 發行版添加 EFI 支持：你需要安裝 Linux（即使在 BIOS 模式下），然後在計算機上安裝 EFI 引導加載程序。有關如何執行此操作的信息，請參閲哎呀：將傳統模式下安裝的引導轉為 EFI 模式下的引導部分。

你應當查看發行版的功能列表，來確定它是否支持 EFI。你還應當注意你的發行版對安全啓動的支持情況，特別是如果你打算和 Windows 8 組成雙啓動。請注意，即使正式支持安全啓動的發行版也可能要求禁用此功能，因為 Linux 對安全啓動的支持通常很差勁，或者導致意外情況的發生。

準備安裝 Linux ​

下面幾個準備步驟有助於在 EFI 計算機上 Linux 的安裝，使其更加順利：

1、 升級固件 ​

有些 EFI 是有問題的，不過硬件製造商偶爾會發布其固件的更新。因此我建議你將固件升級到最新可用的版本。如果你從論壇的帖子知道自己計算機的 EFI 有問題，你應當在安裝 Linux 之前更新它，因為如果安裝 Linux 之後更新固件，會有些問題需要額外的操作才能解決。另一方面，升級固件是有一定風險的，所以如果製造商提供了 EFI 支持，最好的辦法就是按它們提供的方式進行升級。

2、 瞭解如何使用固件 ​

通常你可以通過在引導過程之初按 Del 鍵或功能鍵進入固件設置實用程序。按下開機鍵後儘快查看相關的提示信息，或者嘗試每個功能鍵。類似的，ESC 鍵或功能鍵通常可以進入固件的內置引導管理器，可以選擇要進入的操作系統或外部設備。一些製造商把這些設置隱藏的很深。在某些情況下，如此頁面所述，你可以在 Windows 8 內做到這些。

3、調整以下固件設置 ​

  • 快速啓動 — 此功能可以通過在硬件初始化時使用快捷方式來加快引導過程。這很好用，但有時候會使 USB 設備不能初始化，導致計算機無法從 USB 閃存驅動器或類似的設備啓動。因此禁用快速啓動_可能_有一定的幫助，甚至是必須的；你可以讓它保持激活，而只在 Linux 安裝程序啓動遇到問題時將其停用。請注意，此功能有時可能會以其它名字出現。在某些情況下，你必須_啓用_ USB 支持，而不是_禁用_快速啓動功能。

  • 安全啓動 — Fedora，OpenSUSE，Ubuntu 以及其它的發行版官方就支持安全啓動；但是如果在啓動引導加載程序或內核時遇到問題，可能需要禁用此功能。不幸的是，沒辦法具體描述怎麼禁用，因為不同計算機的設置方法也不同。請參閲我的安全啓動頁面獲取更多關於此話題的信息。

    注意： 一些教程説安裝 Linux 時需要啓用 BIOS/CSM/legacy 支持。通常情況下，這樣做是錯的。啓用這些支持可以解決啓動安裝程序涉及的問題，但也會帶來新的問題。以這種方式安裝的教程通常可以通過“引導修復”來解決這些問題，但最好從一開始就做對。本頁面提供了幫助你以 EFI 模式啓動 Linux 安裝程序的提示，從而避免以後的問題。

  • CSM/legacy 選項 — 如果你想以 EFI 模式安裝，請_關閉_這些選項。一些教程推薦啓用這些選項，有時這是必須的 —— 比如，有些附加視頻卡需要在固件中啓用 BIOS 模式。儘管如此，大多數情況下啓用 CSM/legacy 支持只會無意中增加以 BIOS 模式啓動 Linux 的風險，但你並_不想_這樣。請注意，安全啓動和 CSM/legacy 選項有時會交織在一起，因此更改任一選項之後務必檢查另一個。

4、 禁用 Windows 的快速啓動功能 ​

這個頁面描述瞭如何禁用此功能，不禁用的話會導致文件系統損壞。請注意此功能與固件的快速啓動不同。

5、 檢查分區表 ​

使用 GPT fdisk、parted 或其它任意分區工具檢查磁盤分區。理想情況下，你應該創建一個包含每個分區確切起點和終點（以扇區為單位）的紙面記錄。這會是很有用的參考，特別是在安裝時進行手動分區的時候。如果已經安裝了 Windows，確定可以識別你的 EFI 系統分區（ESP），它是一個 FAT 分區，設置了“啓動標記”（在 parted 或 Gparted 中）或在 gdisk 中的類型碼為 EF00。

安裝 Linux ​

大部分 Linux 發行版都提供了足夠的安裝説明；然而我注意到了在 EFI 模式安裝中的幾個常見的絆腳石：

  • 確保使用正確位深的發行版 — EFI 啓動加載器和 EFI 自身的位深相同。現代計算機通常是 64 位，儘管最初幾代基於 Intel 的 Mac、一些現代的平板電腦和變形本、以及一些鮮為人知的電腦使用 32 位 EFI。雖然可以將 32 位 EFI 引導加載程序添加至 32 位發行版，但我還沒有遇到過正式支持 32 位 EFI 的 Linux 發行版。（我的 《在 Linux 上管理 EFI 引導加載程序》 一文概述了引導加載程序，而且理解了這些原則你就可以修改 32 位發行版的安裝程序，儘管這不是一個初學者該做的。）在 64 位 EFI 的計算機上安裝 32 位發行版最讓人頭疼，我不準備在這裏描述這一過程；在具有 64 位 EFI 的計算機上，你應當使用 64 位的發行版。
  • 正確準備引導介質 — 將 .iso 鏡像傳輸到 USB 閃存驅動器的第三方工具，比如 unetbootin，在創建正確的 EFI 模式引導項時經常失敗。我建議按照發行版維護者的建議來創建 USB 閃存驅動器。如果沒有類似的建議，使用 Linux 的 dd 工具，通過執行 dd if=image.iso of=/dev/sdc 在識別為 /dev/sdc 的 USB 閃存驅動器上創建一個鏡像。至於 Windows，有 WinDD 和 dd for windows，但我從沒測試過它們。請注意，使用不兼容 EFI 的工具創建安裝介質是錯誤的，這會導致人們進入在 BIOS 模式下安裝然後再糾正它們的誤區，所以不要忽視這一點！
  • 備份 ESP 分區 — 如果計算機已經存在 Windows 或者其它的操作系統，我建議在安裝 Linux 之前備份你的 ESP 分區。儘管 Linux 不應該 損壞 ESP 分區已有的文件，但似乎這時不時發生。發生這種事情時備份會有很大用處。只需簡單的文件級的備份（使用 cp，tar，或者 zip 類似的工具）就足夠了。
  • 以 EFI 模式啓動 — 以 BIOS/CSM/legacy 模式引導 Linux 安裝程序的意外非常容易發生，特別是當固件啓用 CSM/legacy 選項時。下面一些提示可以幫助你避免此問題：
    • 進入 Linux shell 環境執行 ls /sys/firmware/efi 驗證當前是否處於 EFI 引導模式。如果你看到一系列文件和目錄，表明你已經以 EFI 模式啓動，而且可以忽略以下多餘的提示；如果沒有，表明你是以 BIOS 模式啓動的，應當重新檢查你的設置。
    • 使用固件內置的引導管理器（你應該已經知道在哪；請參閲瞭解如何使用固件）使之以 EFI 模式啓動。一般你會看到 CD-R 或 USB 閃存驅動器兩個選項，其中一個選項包括 EFI 或 UEFI 字樣的描述，另一個不包括。使用 EFI/UEFI 選項來啓動介質。
    • 禁用安全啓動 - 即使你使用的發行版官方支持安全啓動，有時它們也不能生效。在這種情況下，計算機會靜默的轉到下一個引導加載程序，它可能是啓動介質的 BIOS 模式的引導加載程序，導致你以 BIOS 模式啓動。請參閲我的安全啓動的相關文章以得到禁用安全啓動的相關提示。
    • 如果 Linux 安裝程序總是無法以 EFI 模式啓動，試試用我的 rEFInd 引導管理器 製作的 USB 閃存驅動器或 CD-R。如果 rEFInd 啓動成功，那它保證是以 EFI 模式運行的，而且在基於 UEFI 的 PC 上，它只顯示 EFI 模式的引導項，因此若您啓動到 Linux 安裝程序，則應處於 EFI 模式。（但是在 Mac 上，除了 EFI 模式選項之外，rEFInd 還顯示 BIOS 模式的引導項。）
  • 準備 ESP 分區 — 除了 Mac，EFI 使用 ESP 分區來保存引導加載程序。如果你的計算機已經預裝了 Windows，那麼 ESP 分區就已存在，可以在 Linux 上直接使用。如果不是這樣，那麼我建議創建一個大小為 550 MB 的 ESP 分區。（如果你已有的 ESP 分區比這小，別擔心，直接用就行。）在此分區上創建一個 FAT32 文件系統。如果你使用 Gparted 或者 parted 準備 ESP 分區，記得給它一個“啓動標記”。如果你使用 GPT fdisk（gdisk，cgdisk 或 sgdisk）準備 ESP 分區，記得給它一個名為 EF00 的類型碼。有些安裝程序會創建一個較小的 ESP 分區，並且設置為 FAT16 文件系統。儘管這樣能正常工作，但如果你之後需要重裝 Windows，安裝程序會無法識別 FAT16 文件系統的 ESP 分區，所以你需要將其備份後轉為 FAT32 文件系統。
  • 使用 ESP 分區 — 不同發行版的安裝程序以不同的方式辨識 ESP 分區。比如，Debian 和 Ubuntu 的某些版本把 ESP 分區稱為“EFI boot partition”，而且不會明確顯示它的掛載點（儘管它會在後台掛載）；但是有些發行版，像 Arch 或 Gentoo，需要你去手動掛載。儘管將 ESP 分區掛載到 /boot 進行相應配置後可以正常工作，特別是當你想使用 gummiboot 或 ELILO（譯者注：gummiboot 和 ELILO 都是 EFI 引導工具）時，但是在 Linux 中最標準的 ESP 分區掛載點是 /boot/efi。某些發行版的 /boot 不能用 FAT 分區。因此，當你設置 ESP 分區掛載點時，請將其設置為 /boot/efi。除非 ESP 分區沒有，否則_不要_為其新建文件系統 — 如果已經安裝 Windows 或其它操作系統，它們的引導文件都在 ESP 分區裏，新建文件系統會銷燬這些文件。
  • 設置引導程序的位置 — 某些發行版會詢問將引導程序（GRUB）裝到何處。如果 ESP 分區按上述內容正確標記，不必理會此問題，但有些發行版仍會詢問。請嘗試使用 ESP 分區。
  • 其它分區 — 除了 ESP 分區，不再需要其它的特殊分區；你可以設置 根（/）分區，swap 分區，/home 分區，或者其它分區，就像你在 BIOS 模式下安裝時一樣。請注意 EFI 模式下_不需要設置_BIOS 啓動分區，所以如果安裝程序提示你需要它，意味着你可能意外的進入了 BIOS 模式。另一方面，如果你創建了 BIOS 啓動分區，會更靈活，因為你可以安裝 BIOS 模式下的 GRUB，然後以任意模式（EFI 模式 或 BIOS 模式）引導。
  • 解決無顯示問題 — 2013 年，許多人在 EFI 模式下經常遇到（之後出現的頻率逐漸降低）無顯示的問題。有時可以在命令列下通過給內核添加 nomodeset 參數解決這一問題。在 GRUB 界面按 e 鍵會打開一個簡易文本編輯器。大多數情況下你需要搜索有關此問題的更多信息，因為此問題更多是由特定硬件引起的。

在某些情況下，你可能不得不以 BIOS 模式安裝 Linux。但你可以手動安裝 EFI 引導程序讓 Linux 以 EFI 模式啓動。請參閲《 在 Linux 上管理 EFI 引導加載程序》 頁面獲取更多有關它們以及如何安裝的可用信息。

解決安裝後的問題 ​

如果 Linux 無法在 EFI 模式下工作，但在 BIOS 模式下成功了，那麼你可以完全放棄 EFI 模式。在只有 Linux 的計算機上這非常簡單；安裝 BIOS 引導程序即可（如果你是在 BIOS 模式下安裝的，引導程序也應隨之裝好）。如果是和 EFI 下的 Windows 組成雙系統，最簡單的方法是安裝我的 rEFInd 引導管理器。在 Windows 上安裝它，然後編輯 refind.conf 文件：取消註釋 scanfor 一行，並確保擁有 hdbios 選項。這樣 rEFInd 在引導時會重定向到 BIOS 模式的引導項。

如果重啓後計算機直接進入了 Windows，很可能是 Linux 的引導程序或管理器安裝不正確。（但是應當首先嚐試禁用安全啓動；之前提到過，它經常引發各種問題。）下面是關於此問題的幾種可能的解決方案：

  • 使用 efibootmgr — 你可以以 _EFI 模式_引導一個 Linux 急救盤，使用 efibootmgr 實用工具嘗試重新註冊你的 Linux 引導程序，如這裏所述。
  • 使用 Windows 上的 bcdedit — 在 Windows 管理員命令提示符窗口中，輸入 bcdedit /set {bootmgr}path \EFI\fedora\grubx64.efi 會用 ESP 分區的 EFI/fedora/grubx64.efi 文件作為默認的引導加載程序。根據需要更改此路徑，指向你想設置的引導文件。如果你啓用了安全啓動，需要設置 shim.efi，shimx64.efi 或者 PreLoader.efi（不管有哪個）為引導而不是 grubx64.efi。
  • 安裝 rEFInd — 有時候 rEFInd 可以解決這個問題。我推薦使用 CD-R 或者 USB 閃存驅動器進行測試。如果 Linux 可以啓動，就安裝 Debian 軟件包、RPM 程序，或者 .zip 文件包。（請注意，你需要在一個高亮的 Linux vmlinuz* 選項按兩次 F2 或 Insert 修改啓動選項。如果你的啓動分區是單獨的，這就更有必要了，因為這種情況下，rEFInd 無法找到根（/）分區，也就無法傳遞參數給內核。）
  • 使用修復引導程序 — Ubuntu 的引導修復實用工具可以自動修復一些問題；然而，我建議只在 Ubuntu 和 密切相關的發行版上使用，比如 Mint。有時候，有必要通過高級選項備份並替換 Windows 的引導。
  • 劫持 Windows 引導程序 — 有些不完整的 EFI 引導只能引導 Windows，就是 ESP 分區上的 EFI/Microsoft/Boot/bootmgfw.efi 文件。因此，你可能需要將引導程序改名（我建議將其移動到上級目錄 EFI/Microsoft/bootmgfw.efi），然後將首選引導程序複製到這裏。（大多數發行版會在 EFI 的子目錄放置 GRUB 的副本，例如 Ubuntu 的 EFI/ubuntu，Fedora 的 EFI/fedora。）請注意此方法是個醜陋的解決方法，有用户反映 Windows 會替換引導程序，所以這個辦法不是 100% 有效。然而，這是在不完整的 EFI 上生效的唯一辦法。在嘗試之前，我建議你升級固件並重新註冊自己的引導程序，Linux 上用 efibootmgr，Windows 上用 bcdedit。

有關引導程序的其它類型的問題 - 如果 GRUB（或者你的發行版默認的其它引導程序或引導管理器）沒有引導操作系統，你必須修復這個問題。因為 GRUB 2 引導 Windows 時非常挑剔，所以 Windows 經常啓動失敗。在某些情況下，安全啓動會加劇這個問題。請參閲我的關於 GRUB 2 的頁面獲取一個引導 Windows 的 GRUB 2 示例。還會有很多原因導致 Linux 引導出現問題，類似於 BIOS 模式下的情況，所以我沒有全部寫出來。

儘管 GRUB 2 使用很普遍，但我對它的評價卻不高 - 它很複雜，而且難以配置和使用。因此，如果你在使用 GRUB 的時候遇到了問題，我的第一反應就是用別的東西代替。我的用於 Linux 的 EFI 引導程序頁面有其它的選擇。其中包括我的 rEFInd 引導管理器，它除了能夠讓許多發行版上的 GRUB 2 工作，也更容易安裝和維護 - 但是它還不能完全代替 GRUB 2。

除此之外，EFI 引導的問題可能很奇怪，所以你需要去論壇發帖求助。儘量將問題描述完整。Boot Info Script 可幫助你提供有用的信息 - 運行此腳本，將生成的名為 RESULTS.txt 的文件粘貼到論壇的帖子上。一定要將文本粘貼到 [code] 和 [/code] 之間；不然會遭人埋怨。或者將 RESULTS.txt 文件上傳到 pastebin 網站上，比如 pastebin.com，然後將網站給你的 URL 地址發佈到論壇。

哎呀：將傳統模式下安裝的系統轉為 EFI 模式下引導 ​

警告：這些指南主要用於基於 UEFI 的 PC。如果你的 Mac 已經安裝了 BIOS 模式下的 Linux，但想以 EFI 模式啓動 Linux，可以_在 OS X_ 中安裝引導程序。rEFInd（或者舊式的 rEFIt）是 Mac 上的常用選擇，但 GRUB 可以做的更多。

論壇上有很多人看了錯誤的教程，在已經存在 EFI 模式的 Windows 的情況下，安裝了 BIOS 引導的 Linux，這一問題在 2015 年初很普遍。這樣配置效果很不好，因為大多數 EFI 很難在兩種模式之間切換，而且 GRUB 也無法勝任這項工作。你可能會遇到不完善的 EFI 無法啓動外部介質的情況，也可能遇到 EFI 模式下的顯示問題，或者其它問題。

如前所述，在解決安裝後的問題部分，解決辦法之一就是_在 Windows_ 上安裝 rEFInd，將其配置為支持 BIOS 模式引導。然後可以引導 rEFInd 並鏈式引導到你的 BIOS 模式的 GRUB。在 Linux 上遇到 EFI 特定的問題時，例如無法使用顯卡，我建議你使用這個辦法修復。如果你沒有這樣的 EFI 特定的問題，在 Windows 中安裝 rEFInd 和合適的 EFI 文件系統驅動可以讓 Linux 直接以 EFI 模式啓動。這個解決方案很完美，它和我下面描述的內容等同。

大多數情況下，最好將 Linux 配置為以 EFI 模式啓動。有很多辦法可以做到，但最好的是使用 Linux 的 EFI 引導模式（或者，可以想到，Windows，或者一個 EFI shell）註冊到你首選的引導管理器。實現這一目標的方法如下：

  1. 下載適用於 USB 閃存驅動器或 CD-R 的 rEFInd 引導管理器。

  2. 從下載的鏡像文件生成安裝介質。可以在任何計算機上準備，不管是 EFI 還是 BIOS 的計算機都可以（或者在其它平台上使用其它方法）。

  3. 如果你還沒有這樣做，請禁用安全啓動。因為 rEFInd CD-R 和 USB 鏡像不支持安全啓動，所以這很必要，你可以在以後重新啓用它。

  4. 在目標計算機上啓動 rEFInd。如前所述，你可能需要調整固件設置，並使用內置引導管理器選擇要引導的介質。你選擇的那一項也許在其描述中包含 UEFI 這樣的字符串。

  5. 在 rEFInd 上測試引導項。你應該至少看到一個啓動 Linux 內核的選項（名字含有 vmlinuz 這樣的字符串）。有兩種方法可以啓動它：

    • 如果你_沒有_獨立的 /boot 分區，只需簡單的選擇內核並按回車鍵。Linux 就會啓動。
    • 如果你_確定有_一個獨立的 /boot 分區，按兩次 Insert 或 F2 鍵。這樣會打開一個行編輯器，你可以用它來編輯內核選項。增加一個 root= 格式以標識根（/）文件系統，如果根（/）分區在 /dev/sda5 上，就添加 root=/dev/sda5。如果不知道根文件系統在哪裏，那你需要重啓並儘可能想到辦法。

    在一些罕見的情況下，你可能需要添加其它內核選項來代替或補充 root= 選項。比如配置了 LVM（LCTT 譯註：Logical Volume Manager，邏輯卷管理）的 Gentoo 就需要 dolvm 選項。

  6. Linux 一旦啓動，安裝你想要的引導程序。rEFInd 的安裝很簡單，可以通過 RPM、Debian 軟件包、PPA，或從rEFInd 下載頁面下載的二進制 .zip 文件進行安裝。在 Ubuntu 和相關的發行版上，引導修改程序可以相對簡單地修復你的 GRUB 設置，但你要對它有信心可以正常工作。（它通常工作良好，但有時候會把事情搞得一團糟。）另外一些選項都在我的 《在 Linux 上管理 EFI 引導加載程序》 頁面上。

  7. 如果你想在安全啓動激活的情況下引導，只需重啓並啓用它。但是，請注意，可能需要額外的安裝步驟才能將引導程序設置為使用安全啓動。有關詳細信息，請參閲我關於這個主題的頁面或你的引導程序有關安全啓動的文檔資料。

重啓時，你可以看到剛才安裝的引導程序。如果計算機進入了 BIOS 模式下的 GRUB，你應當進入固件禁用 BIOS/CSM/legacy 支持，或調整引導順序。如果計算機直接進入了 Windows，那麼你應當閲讀前一部分，解決安裝後的問題。

你可能想或需要調整你的配置。通常是為了看到額外的引導選項，或者隱藏某些選項。請參閲引導程序的文檔資料，以瞭解如何進行這些更改。
