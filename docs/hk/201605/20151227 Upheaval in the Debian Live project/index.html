Debian Live項目的劇變 ​

儘管圍繞 Debian Live 項目發生了很多戲劇性事件，關於 Debian Live 項目結束的公告的影響力甚至小於該項目首次出現時的公告。主要開發者的離開是最顯而易見的損失，而社區對他本人及其項目的態度是很令人困惑的，但是這個項目也許還是會以其他的形式繼續下去。所以 Debian 仍然會有更多的工具去創造啓動光盤和其他介質。儘管是用這樣一種有遺憾的方式，項目創始人 Dabiel Baumann 和 Debian CD 團隊以及安裝檢測團隊之間出現的長期爭論已經被「解決」了。　　　　　　　　　　　　　　　　　　　　　　　　　　　　　　　　　　　　　 在 11 月 9 日， Baumann 發表了題為「 Debian Live 項目的突然結束」的一篇公告。在那篇短文中，他一一列舉出了自從這個和他有關的項目被髮起以來近 10 年間發生的不同的事件，這些事件可以表明他在 Debian Live 項目上的努力一直沒有被重視或沒有被足夠重視。最具決定性的因素是因為在「包的含義」上存在衝突， R.Learmonth 申請了新的包名，而這侵犯了在 Debian Live 上使用的命名空間。

考慮到最主要的 Debian Live 包之一被命名為 live-build ，而 R.Learmonth 申請的新包名卻是 live-build-ng ，這簡直是對 live-build 的挑戰。 live-build-ng 意為一種圍繞 vmdebootstrap【譯者注：創造真實的和虛擬機Debian的磁盤映像】工具的外部包裝，這種包裝是為了創造 live 介質（光盤和USB的插入），也是 Debian Live 最需要的的部分。但是當 Baumann Learmonth 要求為他的包換一個不同的名字的時候，他得到了一個「有趣」的回覆：

應該注意到， live-build 不是一個 Debian 項目，它是一個聲稱自己是官方 Debian 項目的外部項目，這是一個需要我們解決的問題。
這不是命名空間的問題，我們要將以目前維護的 live-config 和 live-boot 包為基礎，把它們加入到 Debian 的本地項目。如果迫不得已的話，這將會有很多分支，但是我希望它不要發生，這樣的話我們就可以把這些包整合到 Debian 中並繼續以一種協作的方式去開發。
live-build 已經被 debian-cd 放棄，live-build-ng 將會取代它。至少在一個精簡的 Debian 環境中，live-build 會被放棄。我們（開發團隊）正在與 debian-cd 和 Debian Installer 團隊合作開發 live-build-ng 。

Debian Live 是一個「官方的」 Debian 項目（也可以是狹義的「官方」），儘管它因為思路上的不同產生過爭論。除此之外， vmdebootstrap 的維護者 Neil Willians 為脱離 Debian Live 項目提供瞭如下的解釋:

為了更好的支持 live-build 的代替者, vmdebootstrap 肯定會被推廣。為了能夠用 live-build 解決目前存在的問題，這項工作會由 debian-cd 團隊來負責。這些問題包括可靠性問題，以及不能很好的支持多種機器和 UEFI 等。 vmdebootstrap 也存在着這些問題，我們用來自於對 live-boot 和 live-config 的支持情況來確定 vmdebootstrap 的功能。

這些抱怨聽起來合情合理，但是它們可能已經在目前的項目中得到了解決。然而一些秘密的項目有很明顯的取代 live-build 的意圖。正如 Baumann 指出的，這些計劃沒有被髮布到 debian-live 的郵件列表中。人們首次從 Debian Live 項目中獲知這些計劃正是因為這一次的ITP事件，所以它看起來像是一個「秘密計劃」——有些事情在像 Debian 這樣的項目中得不到很好的安排。

人們可能已經猜到了，有很多帖子都支持 Baumann 重命名 live-build-ng 的請求，但是緊接着，人們就因為他要停止繼續在 Debian Live 上工作的決定而變得沮喪。然而 Learmonth 和 Williams 卻堅持認為取代 live-build 很有必要。Learmonth 給 live-build-ng 換了一個爭議性也許小一些的名字： live-wrapper 。他説他的目標是為 Debian Live 項目加入新的工具（並且「把 Debian Live 項目引入 Debian 裏面」），但是完成這件事還需要很大的努力。

我向已經被 ITP 問題所困擾的每個人道歉。我們已經告知大家 live-wrapper 還不足以完全替代 live-build 且開發工作仍在進行以收集反饋。儘管有了這部分的工作，我們收到的反饋缺並不是我們所需要的。

這種對於取代 live-build 的強烈反對或許已經被預知到了。自由軟件社區的溝通和交流很關鍵，所以，計劃去替換一個項目的核心很容易引起爭議——更何況是一個一直不為人所知的計劃。從 Banumann 的角度來説，他當然不是完美的，他因為上傳個不合適的 syslinux 包導致了 wheezy 的延遲發佈，並且從那以後他被從 Debian 開發者暫時降級為 Debian 維護者。但是這不意味着他應該受到這種對待。當然，這個項目還有其他人蔘與，所以不僅僅是 Baumann 受到了影響。

Ben Armstrong 是其他參與者中的一位，在這個事件中，他很圓滑地處理了一些事，並且想從這個事件中全身而退。他從一封郵件13開始，這個郵件是為了慶祝這個項目，以及他和他的團隊在過去幾年取得的成果。正如他所説， Debian Live 的下游項目列表是很令人振奮的。在另一封郵件中，他也指出了這個項目不是沒有生命力的：

如果 Debian CD 開發團隊通過他們的努力開發出可行的、可靠的、經過完善測試替代品，以及一個合適的取代 live-build 的候選者，這對於 Debian 項目有利無害。如果他們繼續做這件事，他們不會「用一個官方改良，但不可靠且幾乎沒有經過測試的待選者取代 live-build 」。到目前為止，我還沒有看到他們那樣做的跡象。其間， live-build 仍保留在存檔中——它仍然處於良好狀態，且沒有一種經過改良的繼任者來取代它，因此開發團隊沒有必要儘快刪除它。

11 月 24 號， Armstrong 也在他的Blog上發佈了一個有關 Debian Live 的新消息。它展示了從 Baumann 退出起兩週內的令人高興的進展。甚至有跡象表明 Debian Live 項目與 live-wrapper 開發者開展了合作。Blog上也有了一個計劃表，同時不可避免地尋求更多的幫助。這讓人們有理由相信圍繞項目發生的戲劇性事件僅僅是一個小摩擦——也許不可避免，但絕不是像現在看起來這麼糟糕。
