一週 GNOME 之旅：品味它和 KDE 的是是非非（第三節 GNOME應用） ​

應用 ​

這是一個基本扯平的方面。每一個桌面環境都有一些非常好的應用，也有一些不怎麼樣的。再次強調，Gnome 把那些 KDE 完全錯失的小細節給做對了。我不是想説 KDE 中有哪些應用不好。他們都能工作，但僅此而已。也就是説：它們合格了，但確實還沒有達到甚至接近100分。

Gnome 在左，KDE 在右。Dragon 播放器運行得很好，清晰的標出了播放文件、URL或和光盤的按鈕，正如你在 Gnome Videos 中能做到的一樣……但是在便利的文件名和用户的友好度方面，Gnome 多走了一小步。它默認顯示了在你的電腦上檢測到的所有影像文件，不需要你做任何事情。KDE 有 [Baloo][]（正如之前的 Nepomuk，LCTT 譯註：這是 KDE 中一種文件索引服務框架）為什麼不使用它們？它們能列出可讀取的影像文件……但卻沒被使用。

下一步……音樂播放器

這兩個應用，左邊的是 Rhythmbox ，右邊的是 Amarok，都是打開後沒有做任何修改直接截屏的。看到差別了嗎？Rhythmbox 看起來像個音樂播放器，直接了當，排序文件的方法也很清晰，它知道它應該是什麼樣的，它的工作是什麼：就是播放音樂。

Amarok 感覺就像是某個人為了展示而把所有的擴展和選項都儘可能地塞進一個應用程序中去，而做出來的一個技術演示產品（tech demos），或者一個庫演示產品（library demos）——而這些是不應該做為產品裝進去的，它只應該展示其中一點東西。而 Amarok 給人的感覺卻是這樣的：好像是某個人想把每一個感覺可能很酷的東西都塞進一個媒體播放器裏，甚至都不停下來想“我想寫啥來着？一個播放音樂的應用？”

看看默認佈局就行了。前面和中心都呈現了什麼？一個可視化工具和集成了維基百科——佔了整個頁面最大和最顯眼的區域。第二大的呢？播放列表。第三大，同時也是最小的呢？真正的音樂列表。這種默認設置對於一個核心應用來説，怎麼可能稱得上理智？

軟件管理器！它在最近幾年當中有很大的進步，而且接下來的幾個月中，很可能只能看到它更大的進步。不幸的是，這是另一個 KDE 做得差一點點就能……但還是在終點線前以臉戧地了。

Gnome 軟件中心可能是我的新的最愛的軟件中心，先放下牢騷等下再發。Muon, 我想愛上你，真的。但你就是個設計上的夢魘。當 VDG 給你畫設計草稿時（草圖如下），你看起來真漂亮。白色空間用得很好，設計簡潔，類別列表也很好，你的整個“不要分開做成兩個應用程序”的設計都很不錯。

接着就有人為你寫代碼，實現真正的UI，但是，我猜這些傢伙當時一定是喝醉了。

我們來看看 Gnome 軟件中心。正中間是什麼？軟件，軟件截圖和軟件描述等等。Muon 的正中心是什麼？白白浪費的大塊白色空間。Gnome 軟件中心還有一個貼心便利特點，那就是放了一個“運行”的按鈕在那兒，以防你已經安裝了這個軟件。便利性和易用性很重要啊，大哥。説實話，僅僅讓 Muon 把東西都居中對齊了可能看起來的效果都要好得多。

Gnome 軟件中心沿着頂部的東西是什麼，像個標籤列表？所有軟件，已安裝軟件，軟件升級。語言簡潔，直接，直指要點。Muon，好吧，我們有個“發現”，這個語言表達上還算差強人意，然後我們又有一個“已安裝軟件”，然後，就沒有然後了。軟件升級哪去了？

好吧……開發者決定把升級獨立分開成一個應用程序，這樣你就得打開兩個應用程序才能管理你的軟件——一個用來安裝，一個用來升級——自從有了新立得圖形軟件包管理器以來，首次有這種破天荒的設計，與任何已存的軟件中心的設計範例相違背。

我不想貼上截圖給你們看，因為我不想等下還得清理我的電腦，如果你進入 Muon 安裝了什麼，那麼它就會在屏幕下方根據安裝的應用名創建一個標籤，所以如果你一次性安裝很多軟件的話，那麼下面的標籤數量就會慢慢的增長，然後你就不得不手動檢查清除它們，因為如果你不這樣做，當標籤增長到超過屏幕顯示時，你就不得不一個個找過去來才能找到最近正在安裝的軟件。想想：在火狐瀏覽器中打開50個標籤是什麼感受。太煩人，太不方便！

我説過我會給 Gnome 一點打擊，我是認真的。Muon 有一點做得比 Gnome 軟件中心做得好。在 Muon 的設置欄下面有個“顯示技術包”，即：編輯器，軟件庫，非圖形應用程序，無 AppData 的應用等等（LCTT 譯註：AppData 是軟件包中的一個特殊文件，用於專門存儲軟件的信息）。Gnome 則沒有。如果你想安裝其中任何一項你必須跑到終端操作。我想這是他們做得不對的一點。我完全理解他們推行 AppData 的心情，但我想他們太急了（LCTT 譯註：推行所有軟件包帶有 AppData 是 Gnome 軟件中心的目標之一）。我是在想安裝 PowerTop，而 Gnome 不顯示這個軟件時我才發現這點的——因為它沒有 AppData，也沒有“顯示技術包”設置。

更不幸的事實是，如果你在 KDE 下你不能説“用 Apper 就行了”，因為……

Apper 對安裝本地軟件包的支持大約在 Fedora 19 時就中止了，幾乎兩年了。我喜歡關注細節與質量。
