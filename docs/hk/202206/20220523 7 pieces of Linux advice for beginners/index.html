給 Linux 初學者的 7 條建議 ​

我們諮詢了我們社區作者們，分享了他們的初學經驗。

對 Linux 的新用户有什麼建議？我們請社區的作者們分享了他們初學時的最佳經驗。

1、用好 Linux 資源 ​

我哥們兒告訴我，Linux 就像一個“軟件積木搭建套裝”（這是一個過時的詞彙，指的是上世紀五六十年代流行的建築積木玩具），這個比喻比較恰當。在 2001、2002 年那時，我曾經利用 Windows 3.1 和 Windows NT，嘗試搭建一個安全、有用的 K12 學區網站，當時網上可用的資料不多。其中被推薦的《ROOT 用户指南》是一本“大部頭”專業教程，信息豐富，但是有一定上手難度。

於我而言，Mandrake Linux 的線上課程是最有用的資源。該課程對使用和管理 Linux 桌面或服務器進行了詳細的解讀。我學習了該課程，並同時利用紅帽公司維護的一個郵件列表服務，有問題時就在社區提問尋求幫助。

—— Don Watkins

2、在 Linux 社區尋求幫助 ​

我的建議是要多問，你可以從網上搜索信息開始，看看其他人類似的問題（甚至是更好的提問）。問什麼和如何問，需要花一定時間熟悉。

一旦你對 Linux 更加熟悉了，查看你感興趣的各種相關論壇，在提問前，先看看是否有人已經提過相同問題，並獲得了答案。

加入郵件列表也很有用，最後你會發現自己也能專業地答覆提問。正如他們説的，通過回答他人的問題也會學到更多知識。

同時，你會越來越熟悉這個操作系統內部運行機制，再也不是初學時的一無所知。

—— Greg Pittman

我的建議是利用 man、info 等幫助命令獲取信息。另外，儘可能花時間熟悉命令列界面，且真正理解 UNIX 的設計理念。事實上，我最喜歡的書之一就是一本 80 年代的 UNIX 書籍，對理解文件、目錄、設備、基礎命令等非常有幫助。

—— Alan Formy-Duval

我最好的建議是充分相信社區的答覆、手冊頁的詳細信息、介紹不同選項的 HOW-TO 文檔。不管怎麼説，我是在 2009 年左右開始學習的，當時有很多可用的工具和資源。有一個叫 “Linux from Scratch（LFS）”的項目 —— 從源碼開始創建 Linux 系統，在這個項目我學會了很多內部原理知識，以及如何創建一個 LFS 鏡像。

—— Sumantro Mukherjee

我的建議是泛讀。利用像 “Ask Fedora”、“Fedora Matrix chat” 等論壇，閲讀他人的經驗觀點，並且嘗試實踐。我通過閲讀他人的網上爭論學習到很多東西，然後我會嘗試找出問題的原因。

—— Steve Morris

3、安裝雙操作系統 ​

我在 90 年代末就開始安裝雙操作系統（Windows 和 Linux），雖然我真正想使用的是 Linux 操作系統，但我最終還是啓動了 Windows 系統，以便在熟悉的桌面環境中工作。最好的建議之一是改變計算機系統啓動順序，所以每次我都反應不夠快，自動進入了 Linux 系統。: )

—— Heike Jurzik

我的團隊裏的一個人挑戰我，要做一個知識交換。

他是我們的 Linux 系統管理員，利用 Joomla 搭建了一個網站（我們的 Web 團隊擅長這個，他想學習更多知識），而我則安裝了 Linux（以前一直是用 Windows）。我們一開始就用了雙啓動，因為我還有一堆依賴於操作系統的軟件需要用於業務，但這讓我對 Linux 的使用有了一個飛躍。

在我們各自學習新系統時，對方作為專家來互相幫助有助於共同成長，“一個都不能少！”，堅持不懈是一個很大的挑戰。

我經歷一個相當尷尬的低級錯誤後，在顯示器上貼了一個大便籤，上面寫着“在使用任何 rm 操作前，首先要思考一下”。管理員給我寫了一個命令列大全（網上有很多類似的），對於熟悉基礎操作非常有用。我開始使用 Ubuntu 的 KDE 桌面環境時，發現對習慣於使用圖形界面的初學者很有幫助。

從那以後我就開始長期使用 Linux（除了我的工作計算機），而那位管理員仍然在用 Joomla，看起來我倆都得到了成長。

—— Ruth Cheesley

4、為了安全請先備份 ​

我的建議是使用一個帶有簡單且強大的備份軟件的發行版。Linux 新用户會創建、編輯、破壞和恢復系統配置。當操作系統無法啓動、丟失數據時，會讓他們非常沮喪。

有了備份軟件，他們的數據就有了保障。

我們都喜愛 Linux，因為它能讓我們自由飛翔，但這是“雙刃劍”，使用不當也有可能發生非常嚴重的錯誤。

—— Giuseppe Cassibba

5、分享你的 Linux 經驗 ​

我的建議是分享你的 Linux 使用經驗。我曾經認為有一些發行版更適合新用户，所以當他們諮詢使用 Linux 時，我總是推薦這些為“新用户準備的”發行版。但是當我坐在他們的計算機前，看起來卻像是我從未用過 Linux 一樣，因為一些新功能我也不熟悉。現在當有人諮詢時，我會推薦自己使用的發行版，雖説這不一定是初學者的“最佳”版本，但畢竟我熟悉，他們遇到的問題我能夠快速解決（當然我自己也會在分享中學到新東西）。

—— Seth Kenlon

以前有句俗話叫“不要隨便使用雜誌封面上宣傳的發行版，使用你朋友都在用的，當你遇到問題時才能更好地需求幫助”。將關鍵詞“雜誌封面”替換為“互聯網”，這句話依然有效 : -) 。我從未聽從過這個建議，因為我是方圓五十公里內唯一使用 Linux 的人，周圍的人都在用 FreeBSD、IRIX、Solaris 和 Windows 3.11 等操作系統，最後，我就是那個被人們尋求 Linux 幫助的人。

—— Peter Czanik

6、堅持學習 Linux ​

在到 Red Hat 工作前，我是一名分銷商合作伙伴，我有幾個提供旅行護士的家庭健康代理機構客户，他們使用了一個叫“Carefacts”的軟件包，最初用於 DOS，在旅行筆記本電腦和中心資料庫同步中總是出錯。

早期我聽到的最好建議是認真研究一下開源運動。開源在 2022 年是主流思想，但在一代人以前，從 Red Hat 的零售商購買 Linux 安裝光盤是帶有革命性的創新行為。開源打破了常規，我認為要客觀看待開源，但確實驚歎到了相當一部分人。

我的公司在 20 世紀 90 年代中期搭建了第一個客户防火牆，那是基於 Windows NT 和 Altavista 的一個產品，但是經常發生錯誤崩潰。我們自己又搭建了一個基於 Linux 的防火牆，再也沒有出問題了。因此，我們用 Linux 替換了客户的那套 Altavista 系統，穩定地運行了多年。我們在 1999 年底搭建了另一個客户防火牆，當時我花三週讀完了一本關書，介紹了數據包過濾和 ipchains 的正確使用，當我完成時感覺超讚，它解決了所有問題。在接下來的 15 年，我搭建安裝了數百個防火牆系統，主要採用 iptables 技術，有些利用橋接或 ARP 代理以及 QOS 保障視頻會議傳輸，有些利用 IPSEC 和 OpenVPN 隧道。我靠管理個人防火牆和一些雙機熱備系統賺取生活費，非常不錯，而以前都是用的 Windows 系統。我甚至還建了一些虛擬防火牆。

但是技術在高速發展，2022 年，iptables 已過時，我以前的防火牆技術也成了美好的回憶。

目前的經驗之談？永遠不要停止探索。

—— Greg Scott

7、享受過程 ​

耐心點，Linux 和之前你熟悉的操作系統不太相同，準備擁抱一個充滿無限可能的新世界，盡情享受吧。

—— Alex Callejas
