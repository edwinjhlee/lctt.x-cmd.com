內向者的 DevOps ​

我們邀請 Opensource.com 的 DevOps 團隊，希望他們能夠談一談作為 DevOps 內向者的休驗，同時給 DevOps 外向者一些建議。下面是他們的回答。

我們邀請我們的 DevOps 團隊 談一談他們作為一個內向者的體驗，並給外向者們一些建議。但是在我們開始瞭解他們的回答之前，讓我們先來定義一下這些詞彙。

“內向者”是什麼意思？ ​

內向者通常指的是一部分人羣，當他們和別人相處的時候，會使他們的能量耗盡，而不是激發他們更多的能量。當我們思考我們是如何恢復能量時，這是一個非常有用的詞彙：內向者通常需要更多的獨處時間來恢復能量，特別是和一羣人在一起很長時間後。關於內向者的一個非常大的誤解就是他們一定是“害羞的”，但是科學表明，那不過是另一種不同的性格特徵。

內向性與外向性是通過 Myers Briggs 類型指標 而為人所知的，現在也常常被稱作一個 光譜 的兩端。雖然這個世界看起來好像外向者比內向者要多，但是心理學者則傾向於認為大部分人在光譜上的位置是落在 中間性格或偏內向性格的。

現在，我們來看看問答。

DevOps 技術主管可以通過哪些方式來讓內向者感覺他們是團隊的一部分並且願意分享他們的想法？ ​

“每個人都會不大一樣，所以觀察敏鋭就很重要了。從 GitLab 過來的一個人告訴我，他們的哲學就是如果他們沒有提供任何意見，那麼他們就是被排除在外的。如果有人在一個會議上沒有提供任何的意見，那就想辦法讓他們加入進來。當我知道一個內向者對我們將要討論的會議論題感興趣的時候，我會提前請他寫一些書面文本。有非常多的會議其實是可以避免的，只要通過把討論放到 Slack 或者 GitLab 上就行了，內向者會更願意參與進來。在站立會議中，每個人都會交代最新的進展，在這個環境下，內向者表現得很好。有時候我們在其實會議上會重複做一些事情，僅僅是為了保證每個人都有時間發言。我同時也會鼓勵內向者在工作小組或者社區小組面前發言，以此來鍛鍊他們的這些技能。”—— 丹·巴克

“我覺得別人對我做的最好的事情，就是他們保證了當重大問題來臨的時候，我擁有必要的技能去回答它。彼時，我作為一名非常年輕的入伍空軍的一員，我需要給我們部隊的高級領導做狀態簡報的彙報。我必須在任何時候都有一些可用的數據點，以及在實現我們確立的目標的過程中，產生延誤以及偏差的背後的原因。那樣的經歷推動着我從一個‘幕後人員’逐漸變得更加願意和別人分享自己的觀點和想法。”—— 克里斯·肖特

“通過文化去領導。為你的同僚一起設計和嘗試儀式。你可以為給你的小組或團隊設計一個小的每週儀式，甚至給你的部門或組織設計一個年度的大儀式。它的意義在於去嘗試一些事物，並觀察你在其中的領導角色。去找到你們文化當中的代溝以及對立。回顧團隊的信仰和行為。你能從哪裏觀察到對立？你們的文化中缺失了什麼？從一個小陳述開始‘我從 X 和 Y 之間看到了對立’，或者‘我的團隊缺少了 Z’。接着，將代溝與對立轉換為問題：寫下三個‘我們如何能……(How might we's, HMWs)’。”—— 凱瑟琳·路易斯

“內向者不是一個不同的羣體，他們要麼是在分享他們的想法之前想得太多或等得太久的一些人，要麼就是一些根本不知道發生了什麼的人。我就是第一種，我想太多了，有時候還擔心我的意見會被其他人嘲笑，或者沒有什麼意思，或者想偏了。形成那樣的思維方式很難，但它同時也在吞噬着我學習更好事物的機會。有一次，我們團隊在討論一個實現問題。我當時的老大一次又一次地問我，為什麼我沒有作為團隊中更具經驗的人蔘與進來，然後我就（集齊了全宇宙的力量之後）開口説我想説的大家都已經説過了。他説，有時候我可以重複説一次，事情紛繁，如果你能夠重複一遍你的想法，即使它已經被討論過了，也會大有裨益。好吧，雖然它不是一種特別信服的方式，但是我知道了至少有人想聽聽我怎麼説，它給了我一點信心。

“現在，我所使用的讓團隊中的人發言的方法是我經常向內向的人求助，即使我知道解決方法，並且在團隊會議和討論中感謝他們來建立他們的自信心，通過給他們時間讓他們一點一點的從他們寡言的本性中走出來，從而跟團隊分享很多的知識。他們在外面的世界中可能仍然會有一點點孤立，但是在團隊裏面，有些會成為我們可以信賴的人。”—— 阿布希什克·塔姆拉卡爾

“我給參加會議的內向者的建議是，找一個同樣要參加會議的朋友或者同事，這樣到時你就會有人可以跟你一起舒服地交談，在會議開始之前，提前跟其他的與會者（朋友、行業聯繫人、前同事等等）約着見個面或者吃頓飯，要注意你的疲勞程度，並且照顧好自己：如果你需要重新恢復能量，就跳過那些社交或者夜晚的活動，在事後回顧中記錄一下自己的感受。”—— 伊麗莎白·約瑟夫

和一個內向者傾向的同事一起工作時，有什麼提高生產效率的小建議？ ​

“在保證質量時，生產效率會越來越具備挑戰性。在大多數時候，工作中的一個小憩或者輕鬆隨意的交談，可能正是我們的創造性活動中需要的一個火花。再説一次，我發現當你的團隊中有內向者時， Slack 和 Github 會是一個非常有用的用於交換想法以及和其他人互動的媒介。我同時也發現，結對編程對於大部分的內向者也非常有用，雖然一對一的交流對於他們來説，並不像交税那麼頻繁，但是生產質量和效率的提升卻是重大的。但是，當一個內向者在獨自工作的時間，團隊中的所有人都不應該去打斷他們。最好是發個郵件，或者使用沒有那麼強的侵入性的媒介。”—— 丹·巴克

“給他們趁手的工具，讓他們工作並歸檔他們的工作。讓他們能夠在他們的工作上做到最好。要足夠經常地去檢查一下，保證他們沒有走偏路，但是要記住，相比外向者而言，這樣做是更大的一種讓人分心的困擾。”—— 克里斯·肖特

“當我低着頭的時候，不要打斷我。真的，別打斷我！當我沉浸在某件事物中時，這樣做會造成我至少需要花費兩個小時，才能讓我的大腦重新回到之前的狀態。感覺很痛苦。真的。你可以發個郵件讓我去有白板的地方。然後從客户的角度而不是你的角度——通過畫圖的方式——分享下有什麼問題。要知道，可能同時會有十幾個客户問題纏繞在我的腦海中，如果你的問題聽起來就是‘這樣子做會讓我在我的領導面前顯得很好’的那一類問題，那麼相比我腦袋中已經有的真正的客户問題而言，它不會得到更多的關注的。畫個圖，給我點時間思考。當我準備分享我的看法的時候，保證有多支馬克筆可以使用。準備好接受你對問題的假設有可能完全是錯誤的。”—— 凱瑟琳·路易斯

“感謝和鼓勵就是解決的方法，感謝可能不是一份工作評估，但是感謝能讓人舒服地感受到自己並不僅僅是一個活着的獨立實體，因而每個人都能夠感覺到自己是被傾聽的，而不是被嘲笑或者低估的。”—— 阿布希什克·塔姆拉卡爾

結語 ​

在與內向的 DevOps 愛好者的這次交談中，我們最大的啓迪就是平等：其他人需要被怎樣對待，就怎樣對待他們，同時你想被怎樣對待，就去要求別人怎樣對待你。無論你是內向還是外向，我們都需要承認我們並非全以相同的一種方式體驗這個世界。我們的同事應當被給予足夠的空間以完成他們的工作，通過討論他們的需求作為了解如何支持他們的開始。我們的差異正是我們的社區如此特別的原因，它讓我們的工作對更多的人更加的有用。與別人溝通最有效的方式，就是對於你們兩者而言都可行的方式。
