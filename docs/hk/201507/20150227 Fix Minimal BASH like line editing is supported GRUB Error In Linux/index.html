修復Linux中的“提供類似行編輯的袖珍BASH...”的GRUB錯誤 ​

這兩天我安裝了Elementary OS和Windows雙系統，在啓動的時候遇到了一個Grub錯誤。命令列中呈現如下信息：

Minimal BASH like line editing is supported. For the first word, TAB lists possible command completions. anywhere else TAB lists possible device or file completions.

提供類似行編輯的袖珍 BASH。TAB鍵補全第一個詞，列出可以使用的命令。除此之外，TAB鍵補全可以列出可用的設備或文件。

事實上這並不是Elementary OS獨有的錯誤。這是常見的Grub錯誤，會在Ubuntu，Fedora，Linux Mint等Linux操作系統上發生。

通過這篇文章裏我們可以學到基於Linux系統如何修復Ubuntu中出現的“minimal BASH like line editing is supported” Grub錯誤。

你可以參閲這篇教程來修復類似的常見問題，錯誤：分區未找到Linux grub救援模式。

先決條件 ​

要修復這個問題，你需要達成以下的條件：

  • 一個包含相同版本、相同OS的LiveUSB或磁盤
  • 當前會話的Internet連接正常工作

在確認了你擁有先決條件了之後，讓我們看看如何修復Linux的死亡黑屏（如果我可以這樣的稱呼它的話 😉 ）。

如何在基於Ubuntu的Linux中修復“minimal BASH like line editing is supported” Grub錯誤 ​

我知道你一定疑問這種Grub錯誤並不侷限於在基於Ubuntu的Linux發行版上發生，那為什麼我要強調在基於Ubuntu的發行版上呢？原因是，在這裏我們將採用一個簡單的方法，用個叫做Boot Repair的工具來修復我們的問題。我並不確定在其他的諸如Fedora的發行版中是否有這個工具可用。不再浪費時間，我們來看如何修復“minimal BASH like line editing is supported” Grub錯誤。

步驟 1: 引導進入lives會話 ​

插入live USB，引導進入live會話。

步驟 2: 安裝 Boot Repair ​

等你進入了lives會話後，打開終端使用以下命令來安裝Boot Repair：

sudo add-apt-repository ppa:yannubuntu/boot-repair
sudo apt-get update
sudo apt-get install boot-repair

注意：推薦這篇教程如何修復 apt-get update 無法添加新的 CD-ROM 的錯誤，如果你在運行以上命令是遭遇同樣的問題。

步驟 3: 使用Boot Repair修復引導 ​

裝完Boot Repair後，在命令列運行如下命令啓動：

boot-repair &

其實操作非常簡單直接，你僅需按照Boot Repair工具提供的説明操作即可。首先，點擊Boot Repair中的Recommended repair選項。

Boot Repair需要花費一些時間來分析引導和Grub中存在的問題。然後，它會提供一些可在命令列中直接運行的命令。將這些命令一個個在終端中執行。我這邊屏幕上顯示的是：

在這一過程結束後，它會提供一個由boot repair的日誌組成的網頁網址。如果你的引導問題這樣都沒有修復，你就可以去社區或是發郵件給開發團隊並提交該網址作為參考。很酷！不是嗎？

在boot repair成功完成後，關閉你的電腦，移除USB並再次引導。我這就能成功的引導了，但是在Grub畫面上會多出額外的兩行。相比於看到系統能夠再次正常引導的喜悦這些對我來説並不重要。
