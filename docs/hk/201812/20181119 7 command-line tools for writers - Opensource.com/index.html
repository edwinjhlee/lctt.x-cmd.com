給寫作者們的 7 個命令列工具 ​

扔掉你的文字編輯器，然後使用這些開源工具在命令列上寫作吧。

對於大多數人（尤其是非技術人員），寫作意味着在 LibreOffice Writer 或者其他帶圖形界面的文字處理應用上編輯文本。但是還有許多可行的方法可以讓任何人通過文本傳遞他們的信息，尤其是越來越多的作者選擇擁抱純文本。

在使用圖形界面寫作的世界同樣有命令列工具的一席之地。這些命令列工具可以幫助他們進行寫作，檢查他們的拼寫等等 —— 無論是在寫一篇文章、Blog或者故事；寫一個 README 文件；或者準備一份技術文檔的時候。

下面是一些在任何寫作情況下都有用的命令列工具。

編輯器 ​

沒錯，你可以在命令列進行真正的寫作。我知道一些寫作者會使用 Nano、Vim、Emacs、以及 Jove 等編輯器在終端窗口中進行工作。而這些編輯器並非屈指可數。文本編輯器的優勢在於它們簡單易用以及更專注於文本。非常適合用於編輯任何文本的初稿甚至完成一個漫長而複雜的寫作項目。

如果你想在命令列中獲得更像文字編輯器的體驗，不妨瞭解一下 WordGrinder。它是一款簡單但擁有足夠的編寫和發佈功能的文字編輯器。它支持基本的格式和樣式，並且你可以將你的文字以 Markdown、ODT、LaTeX 或者 HTML 等格式導出。

拼寫檢查 ​

每個寫作者在完成他們的工作前至少要（或者説應該要）進行一次拼寫檢查。為什麼呢？在寫作的世界裏有個永恆的定律，無論你檢查了多少次手稿，拼寫錯誤和錯字依然會存在。

我曾經詳細介紹過我最喜歡的命令列拼寫檢查工具 GNU Aspell。交互式檢測文本文檔的 Aspell 不僅能夠高亮顯示拼寫錯誤還能在拼寫錯誤的上方提供正確的拼寫建議。Aspell 在進行拼寫檢查時同樣能夠忽略許多語法標記。

另一個夠老但仍然有用的代替品是 Ispell。雖然它比 Aspell 稍慢一點，但它們都以相同的方式工作。當你在你的文本文件上工作時，Ispell 將提供正確的建議。Ispell 同樣也對英語以外的語言提供了良好的支持。

文章 linter ​

軟件開發人員使用 linter 來檢查他們的代碼是否存在錯誤或者 bug。同樣也有用於檢查文本樣式或語法錯誤的 linter；而該命令列工具會認為這些錯誤是樣式元素。任何寫作者都可以（也應該）使用它，一個文章 linter 對於要求文檔風格和樣式一致的文檔團隊項目而言尤其有用。

Proselint 是一款全能的實時檢查工具。它會找出行話、大話、不正確日期和時間格式、濫用的術語等等。它也很容易運行並忽略文本中的標記。

Alex 是一個簡單但有用的文章 linter。 對明文文本或者格式為 Markdown 或 HTML 的文檔使用它。Alex 會對“性別偏好、極端主義、種族相關、宗教，或者文章中其他不平等的措辭”產生警告。如果你想要試試看 Alex，這裏有一個在線 demo。

其他工具 ​

有時候你找不到一個單詞的恰當的同義詞。但你不需要去呆板的詞庫中抓取或者去專門的網站完善你的單詞完整。僅僅需要對你想要替換的單詞運行 Aiksaurus，然後它就會為你完成這個工作。但是，這個程序最大的缺點是它只支持英語。

即使是隻會很少（甚至只有一項）技術技能的寫作者都能接受 Markdown 來快速而簡單地格式化他們的作品。但是，有時候你也需要將使用 Markdown 格式的文件轉換成其他格式。這就是 Pandoc 的用武之地。你可以用它來將你的文檔轉換成 HTML、Word、LibreOffice Writer、LaTeX、EPUB 以及其他格式。你甚至可以用 Pandoc 來生成書籍和研究論文。

你有最喜歡的命令列寫作工具嗎？在社區發表評論分享它吧。
