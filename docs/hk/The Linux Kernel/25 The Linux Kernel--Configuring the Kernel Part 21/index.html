戴文的Linux內核專題：25 配置內核 (21) ​

大家好！本篇我們將會配置Linux內核的網絡文件系統支持。網絡文件系統是一個可以通過網絡遠程訪問計算機的遠程文件系統。

首先，"NFS client support"驅動允許linux系統使用NFS網絡文件系統。這裏還有3個不同版本的NFS - (NFS client support for NFS version 2)、 (NFS client support for NFS version 3)、 (NFS client support for NFS version 4) 和 (NFS client support for NFSv4.1)。如果你有一個使用NFS的網絡，找出你正在使用NFS的版本，或者啓用所有的NFS驅動。

交換空間並不需要總在本地存儲單元上。這個驅動允許Linux使用NFS作為遠程交換空間(Provide swap over NFS support)。

NFS系統可以通過緩存系統加速 (Provide NFS client caching support)。這是一個本地緩存。

啓用這個驅動允許NFS服務器使用DNS解析器(Use the legacy NFS DNS resolver)。

"NFS server support"給予需要滿足這個需求的服務器提供了NFS的特性。其他一些NFS驅動包括(NFS server support for NFS version 3) 和 (NFS server support for NFS version 4)。

"NFS server manual fault injection"驅動是一個調試驅動，它允許開發者讓NFS服務器認為在NFS上發生了一個錯誤。特別地，這用於測試服務器如何處理NFS錯誤。

"Secure RPC: Kerberos V mechanism"被用於RPC安全調用。由於安全原因，沒有這個特性，NFS無法被加入到內核中。

這是一個RPC的特殊驅動(RPC: Enable dprintk debugging)。

Linux內核支持Ceph文件系統(Ceph distributed file system)。

CIFS是一個用於Samba和Windows服務器的虛擬文件系統(CIFS support (advanced network filesystem, SMBFS successor))。CIFS代表的是"Common Internet FileSystem"(通用網絡文件系統)

有兩個特性被用於調試或監視CIFS驅動(CIFS statistics) 和 (Extended statistics)。

要在服務器上支持LANMAN安全需要一個特定的驅動(Support legacy servers which use weaker LANMAN security)。LANMAN或者LM哈希是一種較弱的特殊的密碼哈希函數。

CIFS在被掛載到安全服務器上之前需要Kerberos票據(Kerberos/SPNEGO advanced session setup)。這個驅動提供了CIFS使用能夠提供票據的用户空間工具的能力。

像其他文件系統一樣，CIFS有一些擴展功能(CIFS extended attributes) 和 (CIFS POSIX Extensions)。

這個驅動從CIFS服務器上獲取訪問控制列表(ACL)(Provide CIFS ACL support)。

CIFS有兩個其他的調試工具(Enable CIFS debugging routines) 和 (Enable additional CIFS debugging routines)。

CIFS有"DFS feature support"，它允許共享在被移除後仍可以訪問。DFS代表"Distributed FileSystem"(分佈式文件系統)。

SMB2是CIFS的一個提升替代品(SMB2 network file system support)。SMB2代表的是"Server Message Block version 2"(服務器消息塊第2版)。

用這個驅動客户端可以存儲CIFS緩存(Provide CIFS client caching support)。

Novell NetWare客户端需要這個驅動訪問NetWare卷 (NCP file system support (to mount NetWare volumes))。NCP代表"NetWare Core Protocol"(NetWare核心協議)。NCP是一種允許客户端與服務器主機上的NetWare卷通信的協議。

如果啓用這個驅動，NetWare服務器可以使用NFS命名空間(Use NFS namespace if available)。

如果啓用這個驅動，NetWare服務器可以使用OS/2長命名空間(Use LONG (OS/2) namespace if available)。

如果啓用這個驅動，那麼由DOS創建或者DOS系統上的存儲單元上的文件名將被轉換成小寫(Lowercase DOS filenames)。

許多文件系統依賴於本地語言支持 (Use Native Language Support)。特別地，本地語言支持(Native Language Support (NLS))在文件名中使用不同的字符集。

這個驅動允許NCP文件系統支持執行標誌和符號鏈接(Enable symbolic links and execute flags)。

Linux內核提供對Coda文件系統的支持(Coda file system support (advanced network fs))。Coda是眾多網絡文件系統中的一種。

Linux內核可以支持Andrew文件系統(Andrew File System support (AFS))。然而，Linux內核只能以不安全的方式只讀這個文件系統。這個驅動目的是讓Linux系統訪問AFS。如果你的網絡只包含了Linux系統，那麼選擇一個不同的Linux完全支持的網絡系統。

Linux內核有一個實驗性的驅動，通過9P2000協議訪問Plan 9資源(Plan 9 Resource Sharing Support (9P2000))。內核也有緩存支持(Enable 9P client caching support)和控制列表(9P POSIX Access Control Lists)，用於支持先前提到的Plan 9特性。

配置完網絡文件系統後，內核的下面一部分設置是"Native Language Support"(本地語言支持)。這整個菜單包含了大多數或者全部的字符集和編碼驅動。啓用這些編碼讓這些字符集可以被系統和應用使用。UTF-8是最常用的編碼，但是這並不是唯一的一個。大多數應用和驅動需要UTF-8，因此這個編碼已經被設置到內核中了。

在那個菜單後，可以配置"Distributed Lock Manager (DLM)"。DLM被用於保存共享資源並表現良好。這個驅動管理用户空間和內核空間的應用，它們訪問或者操作共享內存(就像網絡文件系統)。集羣強烈依賴於這個驅動。

現在，我們已經完全配置完了文件系統和相關的特性，我們可以進入使用內核配置工具(當使用"make menuconfig")的第一屏"Kernel hacking"菜單。我正在使用ncurses接口(見截圖)，它由"make menuconfig"命令初始化，所以其他的接口可能會有一點不一樣。"kernel hacking"菜單中的很多特性和設置包含了關於內核本身的很多設置。這些特性是調試工具，並有一些控制着內核的行為。

第一個設置增加printk時間戳到syslog系統調用輸出中(Show timing information on printks)。

下面的3個特性控制着3個不同調試特性(Default message log level (1-7))、 (Enable __deprecated logic) 和 (Enable __must_check logic)。

下面的特性是一個調試特性，並在編譯時有效((1024) Warn for stack frames larger than (needs gcc 4.4))。如果棧幀大於指定的大小，那麼編譯器會警告用户。

"Magic SysRq key"會啓用Magic SysRq鍵的支持，這允許用户按下Alt+PrintScreen後發送給內核特殊的命令。這個在大多數情況下都有效而不管內核的狀態。然而，有例外的存在。強烈建議啓用Magic SysRq Key。

在編譯器件，在連接是彙編器的符號鏈接會被移除以減少get_wchan()的輸出(Strip assembler-generated symbols during link)。

下面的一個特性用於調試目的(Generate readable assembler code)。如果啓用，一些內核優化將被禁止，那麼一些彙編就會變成人可讀的。這回損害內核的速度。如果你有特殊原因這麼做時才啓用它。

這個設定分會啓用/禁用普遍不需要或者廢除的符號 (Enable unused/obsolete exported symbols)。然而，一些模組可能需要這些符號。啓用這個會增加內核的大小。Linux用户很少會需要這些符號。通常上，禁用這個特性，除非你瞭解一個重要的模組需要這個符號。

如果啓用這個設施，內核會在用户內核頭上執行健康檢查(Run 'make headers_check' when building vmlinux)。

在編譯期，這個特性會檢查無效的引用(Enable full Section mismatch analysis)。

內核可以被配置來檢測軟件或硬件加鎖(Detect Hard and Soft Lockups)。當系統被凍結超過20s並且其他任務無法執行時，這個稱之為軟件加鎖。如果CPU在循環中超過了20s並且中斷無法割到執行時間，那麼這個稱之為硬件加鎖。

下面特性分為讓內核在硬件和軟件加鎖時重啓 (Panic (Reboot) On Hard Lockups) 和 (Panic (Reboot) On Soft Lockups)。

當內核遇到嚴重的問題時，它可以發出一個"kernel panic"(內核崩潰)(Panic on Oops)。強烈建議啓用這個設置。這會幫助防止內核造成系統損害和數據丟失。

內核可以被設置來檢測被掛起的任務(Detect Hung Tasks)。這指的是進程被鎖住或者凍結了。特別是在程序變成不可中斷的時候。下面的設置允許用户定義在進程被視為"掛起"前需要等待多長時間(Default timeout for hung task detection (in seconds))。

內核可以被設置成在進程掛起時重啓(Panic (Reboot) On Hung Tasks)。通常上，用户並不希望這樣。你希望你的系統每次在程序凍結後重啓麼？

"Kernel memory leak detector"找出並記錄內存泄漏。

內核使用幀指針幫助更有效地報告錯誤並且還包含了更多的信息(Compile the kernel with frame pointers)。不言自明，我會跳過很多調試工具。

如眾多Linux用户所知，當系統啓動時，boot消息顯示得太快了而不來不及閲讀。這個特性會設置延遲時間來給用户更多的時間來閲讀消息(Delay each boot printk message by N milliseconds)。

這是一個特殊的開發特性用於測試回溯代碼(Self test for the backtrace code)。回溯代碼是一個自我測試。

可以增加塊設備的數量(Force extended block device numbers and spread them)。然而，這可能會引起啓動問題，因此小心使用。

下一篇，我們會繼續配置內核本身。我希望你們喜歡這邊文章。謝謝！
