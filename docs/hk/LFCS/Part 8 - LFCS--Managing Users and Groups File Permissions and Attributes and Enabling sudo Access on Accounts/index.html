LFCS 系列第八講：管理用户和用户組、文件權限和屬性以及啓用賬户 sudo 訪問權限 ​

去年八月份，Linux 基金會發起了全新的 LFCS（Linux Foundation Certified Sysadmin，Linux 基金會認證系統管理員）認證，旨在讓世界各地的人能夠參與到中等水平的 Linux 系統的基本管理操作的認證考試中去，這項認證包括：維護正在運行的系統和服務的能力、全面監控和分析的能力以及何時向上遊團隊請求支持的決策能力。

第八講： Linux 基金會認證系統管理員

請看以下視頻，裏邊將描述 LFCS 認證程序。

注：youtube視頻

本講是系列教程的第八講，在這一講中，我們將引導你學習如何在 Linux 管理用户和用户組權限的設置，這些內容是 LFCS 認證的必備知識。

由於 Linux 是一個多用户的操作系統（允許多個用户通過不同主機或者終端訪問一個獨立系統），因此你需要知道如何才能有效地管理用户：如何添加、編輯、禁用和刪除用户賬户，並賦予他們足以完成自身任務的必要權限。

（LCTT 譯註：本篇原文章節順序有誤，根據理解做了調整。）

添加用户賬户 ​

添加新用户賬户，你需要以 root 運行以下兩條命令中的任意一條：

# adduser [new_account]
# useradd [new_account]

當新用户賬户添加到系統時，會自動執行以下操作：

  1. 自動創建用户家目錄（默認是 /home/username）。

  2. 自動拷貝下列隱藏文件到新建用户的家目錄，用來設置新用户會話的環境變量。

    	.bash_logout
 .bash_profile
 .bashrc

  3. 自動創建郵件緩存目錄 /var/spool/mail/username。

  4. 自動創建於用户名相同的用户組。

####理解 /etc/passwd 中的內容####

/etc/passwd 文件中存儲了所有用户賬户的信息，每個用户在裏邊都有一條對應的記錄，其格式（每個字段用冒號隔開）如下：

[username]:[x]:[UID]:[GID]:[Comment]:[Home directory]:[Default shell]
  • 字段 [username] 和 [Comment] 是不言自明的。
  • 第二個字段中 x 表明通過用户名 username 登錄系統是有密碼保護的， 密碼保存在 /etc/shadow 文件中。
  • [UID] 和 [GID] 字段用整數表示，代表該用户的用户標識符和對應所在組的組標誌符。
  • 字段 [Home directory] 為 username 用户家目錄的絕對路徑。
  • 字段 [Default shell] 指定用户登錄系統時默認使用的 shell。

####理解 /etc/group 中的內容####

/etc/group 文件存儲所有用户組的信息。每行記錄的格式如下：

[Group name]:[Group password]:[GID]:[Group members]
  • [Group name] 為用户組名稱。
  • 字段 [Group password] 為 x 的話，則説明不使用用户組密碼。
  • [GID] 與 /etc/passwd 中保存的 GID 相同。
  • [Group members] 用户組中的用户使用逗號隔開。

添加用户賬户

修改用户信息 ​

添加用户賬户之後，你可以使用 usermod 命令來修改用户信息中的部分字段，該命令基本語法如下：

# usermod [options] [username]

設置賬户的過期時間

通過 –expiredate 標記後邊接 年-月-日 格式的日期，如下：

# usermod --expiredate 2014-10-30 tecmint

將用户添加到其他組

使用 -aG 或者 –append –groups 選項，後邊跟着用户組，如果有多個用户組，每個用户組之間使用逗號隔開。

# usermod --append --groups root,users tecmint

改變用户家目錄的默認位置

使用 -d 或者 –home 選項，後邊跟着新的家目錄的絕對路徑。

# usermod --home /tmp tecmint

改變用户的默認 shell

使用 –shell 選項，後邊跟着新 shell 的路徑。

# usermod --shell /bin/sh tecmint

下面，我們一次運行上述命令：

# usermod --expiredate 2014-10-30 --append --groups root,users --home /tmp --shell /bin/sh tecmint

####鎖定和解鎖賬户####

對於已有用户賬户，我們還可以：

通過鎖定密碼來禁用賬户

使用 -L （大寫 l）或者 –lock 選項來鎖定用户密碼。

# usermod --lock tecmint

解鎖用户密碼

使用 –u 或者 –unlock 選項來解鎖我們之前鎖定的賬户。

# usermod --unlock tecmint

鎖定用户賬户

####刪除用户賬户####

你可以通過 userdel --remove 命令來刪除用户賬户。這樣會刪除用户擁有的家目錄和家目錄下的所有文件，以及郵件緩存目錄。

# userdel --remove [username]

用户組管理 ​

每次添加新用户，系統會為該用户創建同名的用户組，此時用户組裏邊只有新建的用户，其他用户可以隨後添加進去。建立用户組的目的之一，就是為了通過對指定資源設置權限來完成對這些資源和文件進行訪問控制。

比如，你有下列用户：

  • user1 (主組 user1)
  • user2 (主組 user2)
  • user3 (主組 user3)

他們都需要對你係統裏邊某個位置的 common.txt 文件，或者 user1 用户剛剛創建的共享進行讀寫。你可能會運行下列命令：

# chmod 660 common.txt
或
# chmod u=rw,g=rw,o= common.txt [注意最後那個 = 號和文件名之間的空格]

然而，這樣僅僅給文件所屬的用户和用户組（本例為 user1）成員的提供了讀寫權限。你還需要將 user2 和 user3 添加到 user1 組，打這樣做也將 user1 用户和用户組的其他文件的權限開放給了 user2 和 user3。

這時候，用户組就派上用場了，下面將演示怎麼做。

顯示用户所屬的用户組

# groups tecmint
# id tecmint

為需要對指定文件進行讀寫的多個用户建立用户組

運行下列幾條命令來完成：

# groupadd common_group # 添加新用户組
# chown :common_group common.txt # 將 common.txt 的用户組修改為 common_group
# usermod -aG common_group user1 # 添加用户 user1 到 common_group 用户組
# usermod -aG common_group user2 # 添加用户 user2 到 common_group 用户組
# usermod -aG common_group user3 # 添加用户 user3 到 common_group 用户組

####刪除用户組####

通過以下命令刪除用户組：

# groupdel [group_name]

屬於這個 group_name 用户組的文件是不會被刪除的，而僅僅是刪除了用户組。

Linux 文件權限 ​

除了我們在 LFCS 系列第三講：歸檔/壓縮文件及目錄、設置文件屬性和搜索文件 中説到的基本的讀取、寫入和執行權限外，文件還有一些不常用卻很重要的的權限設置，有時候把它當做“特殊權限”。

就像之前我們討論的基本權限，這裏同樣使用八進制數字或者一個字母（象徵性符號）表示該權限類型。

理解 Setuid 位

當為可執行文件設置 setuid 位之後，用户運行程序時會繼承該程序屬主的有效特權。由於這樣做會引起安全風險，因此設置 setuid 權限的文件及程序必須儘量少。你會發現，當系統中有用户需要訪問屬於 root 用户的文件是所運行的程序就帶有了 setuid 權限。

也就是説，用户不僅僅可以運行這個可執行文件，而且能以 root 權限來運行。比如，讓我們來看看 /bin/passwd 的權限，這個可執行文件用於改變賬户的密碼，修改 /etc/shadow 文件。超級用户可以改變任意賬户的密碼，但是其他用户只能改變自己賬户的密碼。

passwd 命令例示

因此，所有用户都有權限運行 /bin/passwd，但只有 root 用户可以指定改變指定用户賬户的密碼。其他用户只能改變其自身的密碼。

修改用户密碼

# chmod o+u [filename]

以八進制形式來設置 setuid 位，在當前基本權限（或者想要設置的權限）前加上數字 4 就行了。

# chmod 4755 [filename]

理解 Setgid 位

設置 setgid 位之後，真實用户的有效 GID 變為屬組的 GID。因此，任何用户都能以屬組用户的權限來訪問文件。另外，當目錄置了 setgid 位之後，新建的文件將繼承其所屬目錄的 GID，並且新建的子目錄會繼承父目錄的 setgid 位。通過這個方法，你能夠以一個指定的用户組身份來訪問該目錄裏邊的文件，而不必管文件屬主的主屬組。

# chmod g+s [filename]

以八進制形式來設置 setgid 位，在當前基本權限（或者想要設置的權限）前加上數字 2 就行了。

# chmod 2755 [filename]

給目錄設置 Setgid 位

給命令設置 setgid 位

理解黏連（Sticky）位

文件設置了黏連（Sticky）位是沒有意義，Linux 會忽略該位。如果設置到目錄上，會防止其內的文件被刪除或改名，除非你是該目錄或文件的屬主、或者是 root 用户。

# chmod o+t [directory]

以八進制形式來設置 sticky 位，在當前基本權限（或者想要設置的權限）前加上數字 1 就行了。

# chmod 1755 [directory]

若沒有黏連位，任何有權限讀寫目錄的用户都可刪除和重命名其中的文件。因此，黏連位通常出現在像 /tmp 之類的目錄，這些目錄是所有人都具有寫權限的。

給目錄設置黏連位

Linux 特殊文件屬性 ​

文件還有其他一些屬性，用來做進一步的操作限制。比如，阻止對文件的重命名、移動、刪除甚至是修改。可以通過使用 chattr 命令 來設置，並可以使用 lsattr 工具來查看這些屬性。設置如下：

# chattr +i file1
# chattr +a file2

運行這些命令之後，file1 成為不可變狀態（即不可移動、重命名、修改或刪除），而 file2 進入“僅追加”模式（僅在追加內容模式中打開）。

通過 Chattr 命令來包含文件

訪問 root 賬户並啓用 sudo ​

訪問 root 賬户的方法之一，就是通過輸入：

$ su

然後輸入 root 賬户密碼。

倘若授權成功，你將以 root 身份登錄，工作目錄則是登錄前所在的位置。如果是想要一登錄就自動進入 root 用户的家目錄，請運行：

$ su -

然後輸入 root 賬户密碼。

用户通過 su 切換

執行上個步驟需要普通用户知道 root 賬户的密碼，這樣會引起非常嚴重的安全問題。於是，系統管理員通常會配置 sudo 命令來讓普通用户在嚴格控制的環境中以其他用户身份（通常是 root）來執行命令。所以，可以在嚴格控制用户的情況下，又允許他運行一條或多條特權命令。

  • 擴展閲讀：Difference Between su and sudo User

普通用户通過他自己的用户密碼來完成 sudo 授權。輸入命令之後會出現輸入密碼（並不是超級用户密碼）的提示，授權成功（只要賦予了用户運行該命令的權限）的話，指定的命令就會運行。

系統管理員必須編輯 /etc/sudoers 文件，才能為 sudo 賦予相應權限。通常建議使用 visudo 命令來編輯這個文件，而不是使用文本編輯器來打開它。

# visudo

這樣會使用 vim（你可以按照 LFCS 系列第二講：如何安裝和使用純文本編輯器 vi/vim 裏邊説的來編輯文件）來打開 /etc/sudoers 文件。

以下是需要設置的相關的行：

Defaults    secure_path="/usr/sbin:/usr/bin:/sbin"
root        ALL=(ALL) ALL
tecmint     ALL=/bin/yum update
gacanepa    ALL=NOPASSWD:/bin/updatedb
%admin      ALL=(ALL) ALL

來更加深入瞭解這些項：

Defaults    secure_path="/usr/sbin:/usr/bin:/sbin:/usr/local/bin"

這一行指定 sudo 將要使用的目錄，這樣可以阻止使用某些用户指定的目錄，那樣的話可能會危及系統。

下一行是用來指定權限的：

root        ALL=(ALL) ALL

  • 第一個 ALL 關鍵詞表明這條規則適用於所有主機。

  • 第二個 ALL 關鍵詞表明第一個字段中所指定的用户能以任何用户身份的權限來運行相應命令。

  • 第三個 ALL 關鍵詞表明可以運行任何命令。

    tecmint ALL=/bin/yum update

如果 = 號後邊沒有指定用户，sudo 則默認為 root 用户。本例中，tecmint 用户能以 root 身份運行 yum update 命令。

gacanepa    ALL=NOPASSWD:/bin/updatedb

NOPASSWD 關鍵詞表明 gacanepa 用户不需要密碼，可以直接運行 /bin/updatedb 命令。

%admin      ALL=(ALL) ALL

% 符號表示該行應用於 admin 用户組。其他部分的含義與對於用户的含義是一樣的。本例表示 admin 用户組的成員可以通過任何主機連接來運行任何命令。

通過 sudo -l 命令可以查看，你的賬户擁有什麼樣的權限。
