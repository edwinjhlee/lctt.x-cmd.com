在Linux中使用Openswan搭建站點到站點的IPsec VPN 隧道 ​

虛擬私有網絡（VPN）隧道是通過Internet隧道技術將兩個不同地理位置的網絡安全的連接起來的技術。當兩個網絡是使用私有IP地址的私有局域網絡時，它們之間是不能相互訪問的，這時使用隧道技術就可以使得兩個子網內的主機進行通訊。例如，VPN隧道技術經常被用於大型機構中不同辦公區域子網的連接。

有時，使用VPN隧道僅僅是因為它很安全。服務提供商與公司會使用這樣一種方式架設網絡，他們將重要的服務器（如，資料庫，VoIP，銀行服務器）放置到一個子網內，僅僅讓有權限的用户通過VPN隧道進行訪問。如果需要搭建一個安全的VPN隧道，通常會選用IPsec，因為IPsec VPN隧道被多重安全層所保護。

這篇指導文章將會告訴你如何構建站點到站點的 VPN隧道。

拓撲結構 ​

這邊指導文章將按照以下的拓撲結構來構建一個IPsec 隧道。

安裝軟件包以及準備VPN服務器 ​

一般情況下，你僅能管理A點，但是根據需求，你可能需要同時管理A點與B點。我們從安裝Openswan軟件開始。

基於Red Hat的系統（CentOS，Fedora，或RHEL）:

# yum install openswan lsof

在基於Debian的系統（Debian，Ubuntu或Linux Mint):

# apt-get install openswan

現在禁用VPN的重定向功能，如果有服務器，可以執行下列命令：

# for vpn in /proc/sys/net/ipv4/conf/*;
# do echo 0 > $vpn/accept_redirects;
# echo 0 > $vpn/send_redirects;
# done

接下來，允許IP轉發並且禁重定向功能。

 # vim /etc/sysctl.conf 

net.ipv4.ip_forward = 1
net.ipv4.conf.all.accept_redirects = 0
net.ipv4.conf.all.send_redirects = 0

重加載 /etc/sysctl.conf文件：

 # sysctl -p

在防火牆中啓用所需的端口，並保證不與系統當前的規則衝突。

# iptables -A INPUT -p udp --dport 500 -j ACCEPT
# iptables -A INPUT -p tcp --dport 4500 -j ACCEPT
# iptables -A INPUT -p udp --dport 4500 -j ACCEPT

最後，我們為NAT創建防火牆規則。

 # iptables -t nat -A POSTROUTING -s site-A-private-subnet -d site-B-private-subnet -j SNAT --to site-A-Public-IP

請確保上述防火牆規則是持久有效的（LCTT 譯註：你可以save這些規則或加到啓動腳本中）。

注意： ​

  • 你可以使用MASQUERAD替代SNAT(iptables)。理論上説它也能正常工作，但是有可能會與VPS發生衝突，所以我仍然建議使用SNAT。
  • 如果你同時在管理B點，那麼在B點也設置同樣的規則。
  • 直連路由則不需要SNAT。

準備配置文件 ​

我們將要用來配置的第一個文件是ipsec.conf。不論你將要配置哪一台服務器，總是將你這端的服務器看成是左邊的，而將遠端的看作是右邊的。以下配置是在站點A的VPN服務器做的。

# vim /etc/ipsec.conf 

## general configuration parameters ##
 
config setup
        plutodebug=all
        plutostderrlog=/var/log/pluto.log
        protostack=netkey
        nat_traversal=yes
        virtual_private=%v4:10.0.0.0/8,%v4:192.168.0.0/16,%v4:172.16.0.0/16
        ## disable opportunistic encryption in Red Hat ##
        oe=off
 
## disable opportunistic encryption in Debian ##
## Note: this is a separate declaration statement ##
include /etc/ipsec.d/examples/no_oe.conf
 
## connection definition in Red Hat ##
conn demo-connection-redhat
        authby=secret
        auto=start
        ike=3des-md5
        ## phase 1 ##
        keyexchange=ike
        ## phase 2 ##
        phase2=esp
        phase2alg=3des-md5
        compress=no
        pfs=yes
        type=tunnel
        left=<siteA-public-IP>
        leftsourceip=<siteA-public-IP>
        leftsubnet=<siteA-private-subnet>/netmask
        ## for direct routing ##
        leftsubnet=<siteA-public-IP>/32
        leftnexthop=%defaultroute
        right=<siteB-public-IP>
        rightsubnet=<siteB-private-subnet>/netmask
 
## connection definition in Debian ##
conn demo-connection-debian
        authby=secret
        auto=start
        ## phase 1 ##
        keyexchange=ike
        ## phase 2 ##
        esp=3des-md5
        pfs=yes
        type=tunnel
        left=<siteA-public-IP>
        leftsourceip=<siteA-public-IP>
        leftsubnet=<siteA-private-subnet>/netmask
        ## for direct routing ##
        leftsubnet=<siteA-public-IP>/32
        leftnexthop=%defaultroute
        right=<siteB-public-IP>
        rightsubnet=<siteB-private-subnet>/netmask

有許多方式實現身份驗證。這裏使用預共享密鑰，並將它添加到文件 /etc/ipsec.secrets。

 # vim /etc/ipsec.secrets 

siteA-public-IP  siteB-public-IP:  PSK  "pre-shared-key"
## in case of multiple sites ##
siteA-public-IP  siteC-public-IP:  PSK  "corresponding-pre-shared-key"

啓動服務並排除故障 ​

目前，服務器已經可以創建站點到站點的VPN隧道了。如果你可以管理B站點，請確認已經為B服務器配置了所需的參數。對於基於Red Hat的系統，使用chkconfig命令以確定這項服務以設置為開機自啓動。

 # /etc/init.d/ipsec restart

如果所有服務器沒有問題的話，那麼可以打通隧道了。注意以下內容後，你可以使用ping命令來測試隧道。

  1. A點不可達B點的子網，當隧道沒有啓動時ping不通。
  2. 隧道啓動後，在A點直接ping B點的子網IP，是可以ping通的。

並且，到達目的子網的路由也會出現在服務器的路由表中。（LCTT譯註：這裏“子網”指的是site-B，“服務器”指的是site-A）

 # ip route 

[siteB-private-subnet] via [siteA-gateway] dev eth0 src [siteA-public-IP]
default via [siteA-gateway] dev eth0

另外，我們可以使用命令來檢測隧道的狀態。

 # service ipsec status 

IPsec running  - pluto pid: 20754
pluto pid 20754
1 tunnels up
some eroutes exist

 # ipsec auto --status

日誌文件/var/log/pluto.log記錄了關於身份驗證，密鑰交換以及隧道處於不同時期的一些信息。如果你的隧道無法啓動了，可以查看這個文檔。

如果你確信所有配置都是正確的，但是你的隧道任然無法啓動，那麼你需要檢查以下的事件。

  1. 很多ISP會過濾IPsec端口。確認你的網絡ISP允許使用UDP 500， TCP/UDP 4500端口。你可以試着在遠端通過telnet連接服務器的IPsec端口。
  2. 確認所用的端口在服務器防火牆規則中是允許的。
  3. 確認兩端服務器的預共享密鑰是一致的。
  4. 左邊和右邊的參數應該正確配置在兩端的服務器上
  5. 如果你遇到的是NAT問題，試着使用SNAT替換MASQUERADING。

總結，這篇指導重點在於使用Openswan搭建站點到站點IPsec VPN的流程。管理員可以使用VPN使得一些重要的資源僅能通過隧道來獲取，這對於加強安全性很有效果。同時VPN確保數據不被監聽以及劫持。
