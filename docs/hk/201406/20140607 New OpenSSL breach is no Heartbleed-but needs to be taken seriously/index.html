新的OpenSSL分支未包含Heartbleed漏洞，但需要認真看待 ​

摘要：當被最新的OpenSSL安全問題困擾時，你最好解決它，雖然它並不像Heartbleed那樣糟糕。

這一週對於開源的Secure Socket Layer （SSL）來説真是糟糕的一週。

首先，GnuTLS低調的宣稱，存在一個不大但確實存在的缺陷。然後，大範圍流行的OpenSSL被發現包含一個中間人漏洞。在Heartbleed漏洞慘劇後，OpenSSL要醒醒了。

這個漏洞，根據谷歌高級軟件工程師Adam Langley描述，已經至少存在了15年時間。可惜Core Infrastructure Initiative(CII)提供了讓更多的程序員來拯救OpenSSL的資金，卻尚未來得及發揮作用。

也就是説這個漏洞依然是和Heartbleed漏洞一樣糟糕。對於一些新手，攻擊者需要在系統和瀏覽器或其它啓用了SSL的客户端之間來利用這個安全漏洞。

儘管它只是可能被利用，你依然需要儘可能快的通過升級來解決這個漏洞。就像NTT Com Security的評估服務負責人Chris Camejo在郵件採訪裏説的，“這很糟糕，因為已經存在了這麼長的時間，看起來傳播範圍相當廣泛。”

他補充到：“如果利用它，攻擊者可以解密流量。從SSL的設計目的看，這是一個很嚴重的問題。SSL被廣泛地用來在網站和郵件中保護很多的密碼，信用卡卡號和其他的敏感信息。”

在另外一個採訪中，Red Hat的產品安全高級負責人Mark Cox詳細深入地介紹了[細節][7]。Cox説，OpenSSL已修正了一些安全缺陷，但是我們需要想辦法告訴人們不要因為Heartbleed而陷入恐慌。

Cox解釋説，Heartbleed漏洞在公佈之前得到了修補，但利用此漏洞的消息在修補程序之前傳開，因此在這個問題上招致了許多抱怨。最新的情況，已有七個安全問題得到了修補，但其中只有兩項需要管理員和用户的關注。

Cox繼續説道，第一個，是數據報傳輸層安全 (DTLS)的bug。到目前為止，還沒有已知的攻擊，但是存在針對它攻擊成功的潛在性。

因此，雖然DTLS使用不廣泛，如果您確實在使用它，它應儘快修補。

Cox然後説，“這個問題的實際上是中間人攻擊”。實際上，真的要有個“在中間的”人，來利用易受攻擊的服務器和客户端之間的漏洞。

但如果有人真的這樣做到了，他們就能“繞過SSL並拿到原始數據...這是一個相當嚴重的問題”。

但是，如同從理論上講任何人都可以利用Heartbleed漏洞來攻擊SSL服務器。攻擊並利用此漏洞需要能接觸到客户端和服務器之間的通信網絡。例如，成功的攻擊可能需要架設一個假的公開Wi-Fi接入點，才能攻擊到使用這個WIFI的Android版本的Chrome網絡瀏覽器與未安裝修補程序的Web服務器之間的SSL通訊。幸運的是，谷歌[已經發布了更新的版本的瀏覽器][8]，35.0.1916.141，以消除此問題。

Cox繼續説，最易受攻擊的系統是未安裝修補程序的Android設備使用一個假的Wi-Fi接入點。Morrell補充説因為Android用户並沒有被他們的手機供應商和電信公司重視，安全漏洞更新前他們可能會受漏洞影響相當長的時間。

幸運的是，如果他們用連接的服務器已經更新，他們也不會受到攻擊。

OpenSSL安全社區自5月初以來已經知道這個問題。社區與Red Hat、其他主要Linux和開源社團和硬件供應商，要解決這個問題，不只是簡單修補bug，而且要測試修復，以便他們可以確認漏洞已經修復，大家都已經安全了，而沒有引入任何新的安全問題，並可在大多數 OpenSSL服務器和客户端的組合上工作。

現在，這個補丁已經有了，OpenSSL試着通過補丁解決安全缺陷，向公眾表明對這些問題不必有任何不必要的恐慌。Cox補充説，主要的Linux供應商，如Red Hat和Ubuntu，已經有可用的修補程序。

所有的管理員都需要給服務器下載並安裝補丁，而不是放任安全漏洞。
