混合雲的變化 ​

圍繞雲計算的概念和術語仍然很新，但是也在不斷的改進。

不管怎麼看，雲計算也只有十多年的發展時間。一些我們習以為常的雲計算的概念和術語仍然很新。美國國家標準與技術研究所（NIST）文檔顯示，一些已經被熟悉的術語定義在 2011 年才被髮布，例如基礎設施即服務（IaaS），而在此之前它就以草案的形式廣泛流傳。

在該文檔中其它定義中，有一個叫做混合雲hybrid cloud。讓我們回溯一下該術語在這段期間的變化是很有啓發性的。雲基礎設施已經超越了相對簡單的分類。此外，它還強調了開源軟件的使用者所熟悉的優先級，例如靈活性、可移植性、選擇性，已經被運用到了混合雲上。

NIST 對混合雲最初的定義主要集中於雲爆發cloud bursting，你能使用內部的基礎設施去處理一個基本的計算負荷，但是如果你的負荷量暴漲，可以將多出來的轉為使用公有云。與之密切聯繫的是加強私有云與公有云之間 API 的兼容性，甚至是創造一個現貨市場來提供最便宜的容量。

Nick Carr 在 The Big Switch 一書中提出一個概念，雲是一種計算單元，其與輸電網類似。這個故事不錯，但是即使在早期，這種類比的侷限性也變得很明顯。計算不是以電流方式呈現的一種物品。需要關注的是，公有云提供商以及 OpenStack 一類的開源雲軟件激增的新功能，可見許多用户並不僅僅是尋找最便宜的通用計算能力。

雲爆發的概念基本上忽略了計算是與數據相聯繫的現實，你不可能只移動洪水般突如其來的數據而不承擔巨大的帶寬費用，以及不用為轉移需要花費的時間而操作。Dave McCrory 發明了 “數據引力data gravity”一詞去描述這個限制。

那麼既然混合雲有如此負面的情況，為什麼我們現在還要再討論混合雲？

正如我説的，混合雲的最初的構想是在雲爆發的背景下誕生的。雲爆發強調的是快速甚至是即時的將工作環境從一個雲轉移到另一個雲上；然而，混合雲也意味着應用和數據的移植性。確實，如之前 2011 年我在 CNET 的文章中寫到：“我認為過度關注於全自動的工作轉換給我們自己造成了困擾，我們真正應該關心的是，如果供應商不能滿意我們的需求或者嘗試將我們鎖定在其平台上時，我們是否有將數據從一個地方到另一個地方的遷移能力。”

從那以後，探索雲之間的移植性有了進一步的進展。

Linux 是雲移植性的關鍵，因為它能運行在各種地方，無論是從裸機到內部虛擬基礎設施，還是從私有云到公有云。Linux 提供了一個完整、可靠的平台，其具有穩定的 API 接口，且可以依靠這些接口編寫程序。

被廣泛採納的容器進一步加強了 Linux 提供應用在雲之間移植的能力。通過提供一個包含了應用的基礎配置環境的鏡像，應用在開發、測試和最終運行環境之間移動時容器提供了可移植性和兼容性。

Linux 容器被應用到要求可移植性、可配置性以及獨立性的許多方面上。不管是預置的雲，還是公有云，以及混合雲都是如此。

容器使用的是基於鏡像的部署模式，這讓在不同環境中分享一個應用或者具有全部基礎環境的服務集變得容易了。

在 OCI 支持下開發的規範定義了容器鏡像的內容及其所依賴、環境、參數和一些鏡像正確運行所必須的要求。在標準化的作用下，OCI 為許多其它工具提供了一個機會，它們現在可以依靠穩定的運行環境和鏡像規範了。

同時，通過 Gluster 和 Ceph 這類的開源技術，分佈式存儲能提供數據在雲上的可移植性。 物理約束限制瞭如何快速簡單地把數據從一個地方移動到另一個地方；然而，隨着組織部署和使用不同類型的基礎架構，他們越來越渴望一個不受物理、虛擬和雲資源限制的開放的軟件定義儲存平台。

尤其是在數據存儲需求飛速增長的情況下，由於預測分析，物聯網和實時監控的趨勢。2016 年的一項研究表明，98% 的 IT 決策者認為一個更敏捷的存儲解決方案對他們的組織是有利的。在同一個研究中，他們列舉出不恰當的存儲基礎設施是最令他們組織受挫的事情之一。

混合雲表現出的是提供在不同計算能力和資源之間合適的移植性和兼容性。其不僅僅是將私有云和公有云同時運用在一個應用中。它是一套多種類型的服務，其中的一部分可能是你們 IT 部門建立和操作的，而另一部分可能來源於外部。

它們可能是軟件即服務（SaaS）應用的混合，例如郵件和客户關係管理（CRM）。被 Kubernetes 這類開源軟件協調在一起的容器平台越來越受新開發應用的歡迎。你的組織可能正在運用某一家大型雲服務提供商來做一些事情。同時你也能在私有云或更加傳統的內部基礎設施上操作一些你自己的基礎設施。

這就是現在混合雲的現狀，它能被歸納為兩個選擇，選擇最合適的基礎設施和服務，以及選擇把應用和數據從一個地方移動到另一個你想的地方。
