Linux 上的開源日誌工具 ​

如果你是一位 Linux 系統管理員，你進行故障排除的第一個工具就是日誌文件。這些文件會保留關鍵的信息，可以在很長一段時間內幫你去解決影響你桌面和服務器的問題。對於許多系統管理員（特別是對於老手），在命令列上沒有什麼比檢查日誌文件更好的方式了。但是對於那些想要更高效（也可能是更現代）的排除故障的人，這裏也有許多的選擇。

在這篇文章中，我將會羅列一些在 Linux 平台上一些值得一用的工具。一些特定於某項服務（例如 Kubernetes 或者 Apache）的日誌工具將不會出現在該清單中，取而代之的將會是那些能夠挖掘寫入 /var/log 的所有神奇信息深度的工具。

什麼是 /var/log? ​

如果你是剛開始使用 Linux ，你可能不知道 /var/log 目錄都包含了些什麼。然而，這個名字已經説明了一切。這個目錄收容了所有系統以及安裝在系統上的主要服務（如 Apache，MySQL，MariaDB 等）的日誌信息。打開一個終端窗口鍵入 cd /var/log 命令，接着鍵入 ls 命令，您將看到所有可以查看的日誌文件。（圖 1）

圖 1：ls 命令顯示在 /var/log 下可用的日誌。

經許可使用

如果你想查看 syslog 日誌文件。運行 less syslog 命令，你就可以滾動查看特定日誌的所有細節。但是如果標準的終端不適合你？你還有什麼選擇呢？其實有很多。讓我們來看看以下幾個選擇。

Logs ​

如果你使用 Gnome 桌面（或是其他的桌面，Logs 不僅能安裝在 Gnome），你就已經有了這樣的一個工具了，它僅僅在日誌文件上加上了一個輕量的圖形化界面，卻使得查看日誌的過程更加簡單和高效。（從標準庫中）安裝完成後，從桌面菜單中打開 Logs，然後你將看到一個（圖 2 的）界面，在這裏允許你從各種類型的日誌中進行選擇（重要、所有、系統、安全和硬件），也可以選擇一個啓動時段 (從頂部中間的下拉菜單中），甚至是從所有可用的日誌中進行搜索。

圖 2：Gnome 日誌工具是你可以找到的為 Linux 最簡易的日誌圖形化軟件之一。

經許可使用

Logs 是一個非常好的工具，特別是如果你不想要太多花裏胡哨，妨礙你查看日誌的功能，Logs 對於你查看系統日誌來説就是一個很好的工具。

KSystemLog ​

KSystemLog 是 KDE 的，Logs 是 GNOME 的，但是有許多功能都融合到了裏面。儘管兩者都使得查看系統的日誌文件變得非常簡單，但只有 KsystemLog 有彩色的日誌行、分頁查看、複製日誌行到桌面剪貼板、內置直接發送日誌信息到系統的功能、詳細閲讀每行日誌的信息、以及更多。KSystemLog 查看的所有日誌都可以從 Gnome 的 Logs 中找到，只是各有不同的格式。

從主窗口上（圖 3），你可以看到許多不同的日誌（來自於系統日誌，認證日誌，X.org 日誌，Journald 日誌），通過日期、擁有者、進程、信息選擇一個日誌優先級可以過濾日誌。

圖 3：KSystemLog 主界面

經許可使用

如果你點擊窗口菜單，你可以打開一個新的標籤，你可以在裏面選擇一個不同的日誌/篩選組合去查看。在同一個標籤中，你甚至可以複製當前標籤。你可以通過以下操作，手動添加一個日誌到一個文件中。

  1. 打開 KSystemLog。

  2. 點擊文件的標籤 > 添加日誌入口

  3. 創建你的日誌入口（圖 4）。

  4. 點擊 OK。

圖 4：使用 KystemLog 創建一個手冊日誌

經許可使用

KsystemLogs 使得在 KDE 下查看日誌變為一個非常簡單的操作。

Logwatch ​

Logwatch 不是一個花俏的圖形化工具。相反，Logwatch 允許你設置一個日誌記錄系統 e-mail 給你重要的警告。你可以通過一個 SMTP 服務 e-mail 這些重要通知，或者你可以只是在本地機器上查看。你可以在幾乎所有發行版的標準庫中找到 Logwatch，所以可以使用一個簡單的命令完成安裝：

sudo apt-get install logwatch

或者:

sudo dnf install logwatch

在安裝期間，你需要選擇一個發送警告的方式（圖 5）。如果你選擇僅以本地郵件的方式發達，你需要安裝 mailutils（這樣你就能通過 mail 命令查看本地郵件）。

圖 5：配置 Logwatch 警告發送方式

經許可使用

所有的 Logwatch 配置文件都被放在一個文件中。可以使用 sudo nano /usr/share/logwatch/default.conf/logwatch.conf 命令編輯該文件。你可能想要編輯 MailTo = 選項。如果你是在本地查看日誌，設置這項為你想要為你想要接收日誌的 Linux 用户名（例如 MailTo = jack）。如果你想要發送這些日誌到一個外部的郵件地址，你需要修改 MailTo = 為一個正確的郵件地址。在同一個配置文件中你還可以設置日誌的細節層級和發送範圍。保存並關閉該文件。設置成功後，你就可以使用以下命令發送你的第一封郵件：

logwatch --detail Med --mailto ADDRESS --service all --range today
Where ADDRESS is either the local user or an email address.

使用 man logwatch 可以查看更多有關使用 Logwatch 的信息。通過閲讀手冊頁可以看到這個工具的不同選項。

Rsyslog ​

Rsyslog 是一個發送遠程客户端的日誌到集羣服務的簡便方式。你只有一台服務器，但你想收集在你數據中心的其他 Linux 服務的日誌。有了 Rsyslog，這可以很方便的實現。Rsyslog 必須被安裝在所有的客户端和集羣服務上（通過運行sudo apt-get install rsyslog）。 安裝完成後，在集羣服務上創建 /etc/rsyslog.d/server.conf 文件，包含以下內容：

# Provide UDP syslog reception
$ModLoad imudp
$UDPServerRun 514

# Provide TCP syslog reception
$ModLoad imtcp
$InputTCPServerRun 514

# Use custom filenaming scheme
$template FILENAME,"/var/log/remote/%HOSTNAME%.log"
*.* ?FILENAME

$PreserveFQDN on

保存並退出這個文件。現在，在任意一台客户端機器上，創建這個文件 /etc/rsyslog.d/client.conf，包含以下內容：

$PreserveFQDN on
$ActionQueueType LinkedList
$ActionQueueFileName srvrfwd
$ActionResumeRetryCount -1
$ActionQueueSaveOnShutdown on
*.* @@SERVER_IP:514

SERVER_IP 處是你的集羣服務的 IP 地址。保存並關閉該文件。使用以下命令在所有機器上重啓 rsyslog。

sudo systemctl restart rsyslog

你現在可以使用以下命令（運行在集羣服務器上）查看集羣日誌文件。

tail -f /var/log/remote/*.log

tail 命令允許你實時查看寫入這些文件中的內容。你應該可以看到包含主機名的日誌條目（圖 6）。

圖 6：Rsyslog 為一個已連接的客户端顯示條目。

經許可使用

如果你想要為你的 Linux 服務器上的所有用户，創建單一的日誌查看入口點， Rsyslog 是一個非常好的工具。

瞭解更多 ​

這篇文章僅僅蒐集了為 Linux 平台創建的日誌記錄工具的一點皮毛。上述每個工具都能夠比此處概述的內容做到更多。這篇梗概應該會對你開始你漫長的日誌記錄歷程有一點幫助。

你可以從 Linux 基金會和 edx 的免費課程 "Introduction to Linux" 瞭解更多。
