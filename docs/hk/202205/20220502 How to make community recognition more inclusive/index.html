如何使社區認可更加包容 ​

拋開具體的工作量，我們認為所有的貢獻都彌足珍貴。當所有社區貢獻者都能獲得家庭般的讚賞時，他們會更傾向於繼續為社區添磚加瓦。

給予一個優秀的工作足夠的認同和讚賞是我作為一個社區管理員最喜歡做的事。我不但有機會能夠對貢獻者表示感激，同時還能為社區設立一個優秀的榜樣。認同和讚賞可以是為了慶祝一個成就，例如有人幫助其他成員加入社區、減少技術債務或者貢獻了激動人心的新功能。

但是，用來確定貢獻量的規則可能會有難以預料的後果。例如某些社區管理員利用如下圖所示的圖表來表彰貢獻，過度地強調了拉取請求（PR）以及對代碼庫的貢獻量。

使用這樣的方法進行表彰會產生三個問題。

首先，這樣過度關注了對代碼庫的貢獻。早年間，開源項目主要吸引開發者參與，所以自然而然許多貢獻是圍繞代碼的。現在，越來越多的非開發者正在積極參與社區項目（例如通過用户組、會議和用户生產的內容），他們的大多數貢獻在代碼庫以外的地方。這些貢獻將不會出現在諸如 年度合併 PR 數量 這樣的表格上。

其次，過度關注貢獻指標（指那些易於用數字統計的），最終會演變為獎勵數量而不是質量，甚至影響力。在上圖的 貢獻組織排行榜 中，大型組織因為具有更多的可用人力，相對於小型組織就會有更為顯著的優勢。通過對大型組織在數量上的表彰將可能導致小型組織的人感到權利被剝奪了。

最後，儘管本意並非如此，但許多人都會把這些數據看做對個人或組織影響力的排名。

基於此，我們最好避免僅僅通過指標數量來表彰對社區的貢獻。

令社區表彰更有意義 ​

如何讓社區表彰更為包容並且能夠覆蓋不同的貢獻形式呢？諸如 Discord、IRC、郵件列表和Slack 等交流渠道可以很好的表明一個成員的活躍度及其感興趣的領域。例如每當我看到一些人熱衷於解答問題或者幫助新用户時，我會十分開心。這些貢獻並不會出現在社區的數據板上，但是讓這些貢獻得到應有的認同和感謝並廣為人知是十分重要的。

社區數據板顯然是開源社區重要的工具。但是我提醒大家不要花費太多時間在建設數據板上。遲早你會發現，不是所有的東西都可以有清晰的標準進行度量，即便你能夠想出規則量化一件事，你也依然會發現這些規則具有侷限性。

為了獲取更多的關於貢獻的信息，我經常會安排社區成員茶話會。這些對話經常能夠告訴我他們做出貢獻的原因、有多少工作量以及誰同時也參與進來了等等。

當我第一次與他們對話時，我經常聽到他們提及找到回饋社區的方法十分重要，而他們也在尋找方法來提供力所能及的幫助。許多人甚至因不能在代碼方面做出貢獻而感到內疚，而我會向他們強調代碼不再是開源唯一重要的東西。有時這些對話能讓我有機會接觸到同一城市或同一行業的社區成員，或者發現更多共同的興趣點。維護這些關係將有助於提升歸屬感。

令社區表彰更具影響力 ​

除了尋找更多的活動形式，我們也可以讓這些活動以更具影響力的形式呈現。例如在看到優質貢獻時及時讚美。一個快速的感謝回覆會比一兩個月之後的正式感謝更有效。許多人包括我自己，都會強調給予更為正式而合理的表彰和獎勵，但我們應當謹記，獎勵並非社區成員貢獻的主要動力。認可好的工作並努力去接觸貢獻者會令貢獻者感到受重視。

讓其他成員參與到認可的過程中也是一個很好的主意。一旦社區達到了一定的規模，便很難事無鉅細地知曉一切細節。如果引入一個成員提名機制則會很好地讓大家注意到優秀的貢獻。如果你的社區擁有十分正式的獎項，例如在年度會議或聚會上頒發的獎項，請讓社區成員參與提名和投票。這不僅提供了成員參與進來的平台，也令這些來自成員投票的獎項更有意義。

最後給予認同和感謝也是一個認識成員並加深瞭解的重要機會。有時候頒獎彷彿在進行交易：“你做了某件事，所以我們給你頒發了某個獎勵”。多在介紹成員上花些時間，將令成員感到更受重視並加強歸屬感。

社區認可令社區更為健康 ​

在提高開源社區的多樣性、包容性和歸屬感方面，我們仍有許多工作亟待改善。更好的社區認可將在其中起着不可或缺的作用。確保所有的貢獻都受到重視，讓每一位貢獻者都感到家庭般氛圍和讚賞，將鼓勵他們繼續為社區貢獻。
