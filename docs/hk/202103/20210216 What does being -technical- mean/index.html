“技術”是什麼意思？ ​

用“技術”和“非技術”的標籤對人們進行分類，會傷害個人和組織。本文作為本系列的第 1 篇，將闡述這個問題。

“技術technical”一詞描述了許多項目和學科：技術淘汰賽、技術性犯規、攀巖比賽的技術課程和花樣滑冰運動的技術得分。廣受歡迎的烹飪節目 “The Great British Bake-Off” 包括一個“烘焙技術挑戰”。任何參加過劇院演出的人都可能熟悉技術周，即戲劇或音樂劇首演前的一週。

如你所見，技術一詞並不嚴格適用於軟件工程和軟件操作，所以當我們稱一個人或一個角色為“技術”時，我們的意思是什麼，為什麼使用這個術語？

在我 20 年的技術生涯中，這些問題引起了我的興趣，所以我決定通過一系列的採訪來探討這個問題。我不是工程師，也不寫代碼，但這並不意味着我是非技術型的。但我經常被貼上這樣的標籤。我認為自己是技術型的，通過這個系列，我希望你會明白為什麼。

我知道我不是孤獨一個人。羣眾討論是很重要的，因為如何定義和看待一個人或一個角色會影響他們做好工作的信心和能力。如果他們感到被壓垮或不受尊重，就會降低他們的工作質量，擠壓創新和新思想。你看，這一切都是循序漸進的，那麼我們怎樣才能改善這種狀況呢？

我首先採訪了 7 個不同角色的人。

在本系列中，我將探討“技術”一詞背後的含義、技術的連續性、將人分類為技術型或非技術型的意外副作用，以及通常被認為是非技術性的技術角色。

定義技術和非技術 ​

首先，我們需要做個名詞解釋。根據字典網，“技術/技術性的”是一個具有多重含義的形容詞，包括：

  • 屬於或與藝術、科學等學科有關的
  • 精通或熟悉某一特定的藝術或行業的實際操作
  • 技術要求高或困難（通常用於體育或藝術）

而“非技術性”一詞在科技公司中經常被用來描述非工程人員。但是“非技術性”的定義是“不涉及、不具有某個特定活動領域及其術語的特點，或不熟練”。

作為一個寫作和談論技術的人，我認為自己是技術型的。如果你不熟悉這個領域和術語，就不可能書寫或談論一個技術主題。有了這種理解，每個從事技術工作的人都是技術人員。

為什麼要分配標籤？ ​

那麼，為什麼劃分技術與非技術？這在技術領域有什麼意義呢？我們試圖通過分配這些標籤來實現什麼？有沒有一個好的理由？而我們有沒有重新評估這些理由？讓我們討論一下。

當我聽到人們談論技術人員和非技術人員時，我不禁想起 Seuss 教授寫的童話故事 《The Sneetches》。Sneetches 有沒有星星被演化為一種渴望。Sneetches 們進入了一個無限循環，試圖達到正確的狀態。

標籤可以起到一定的作用，但當它們迫使一個羣體的等級被視為比另一個更好時，它們就會變得危險。想想你的組織或部門：銷售、資源、營銷、質控、工程等，哪一組的在重要性上高於或低於另一組？

即使它不是直接説的或寫在什麼地方，也可能是被人們默認的。這些等級劃分通常也存在於規章制度中。技術內容經理 Liz Harris 表示，“在技術寫作界存在着一個技術含量的評級，你越是偏技術的文章，你得到的報酬就越高，而且往往在技術寫作社區裏你得到的關注就越多。”

術語“技術”通常用於指一個人在某一主題上的深度或專業知識水平。銷售人員也有可能會要求需要懂技術以更好的幫助客户。從事技術工作的人，他們是技術型的，但是也許更專業的技術人員才能勝任這個項目。因此，請求技術支援可能是含糊不清的表述。你需要一個對產品有深入瞭解的人嗎？你需要一位瞭解基礎設施堆棧的人員嗎？還是需要一個能寫下如何配置 API 的步驟的人？

我們應該要把技術能力看作是一個連續體，而不是把人簡單的看作技術型的或非技術型的。這是什麼意思？開發人員關係主管 Mary thengwall 描述了她如何對特定角色所需的不同深度的技術知識進行分類。例如，項目可能需要一個開發人員、一個具有開發人員背景的人員，或一個精通技術的人員。就是那些被歸類為精通技術的人也經常被貼上非技術的標籤。

根據 Mary 的説法，如果“你能解釋（一個技術性的）話題，你知道你的產品工作方式，你知道該説什麼和不該説什麼的基本知識，那麼你就是技術高手。你不必有技術背景，但你需要知道高層次的技術信息，然後還要知道向誰提供更多信息。”

標籤帶來的問題 ​

當我們使用標籤來具體説明我們需要完成一項工作時，它們可能會很有幫助，比如“開發人員”、“有開發人員背景”和“技術達人”。但是當我們使用標籤的範圍太廣時，將人們分為兩組中的一組可能會產生“弱於”和“優於”的感覺

當一個標籤成為現實時，無論是有意還是無意，我們都必須審視自己，重新評估自己的措辭、標籤和意圖。

高級產品經理 Leon Stigter 提出了他的觀點：“作為一個集體行業，我們正在構建更多的技術，讓每個人都更容易參與。如果我們對每個人説：‘你不是技術型的’，或者説：‘你是技術型的’，然後把他們分成幾個小組，那些被貼上非技術型標籤的人可能永遠不會去想：‘其實我自己就能完成這個項目’，實際上，我們需要所有這些人真正思考我們行業和社區的發展方向，我認為每一個人都應該有這個主觀能動性。”

身份 ​

如果我們把我們的身份貼在一個標籤上，當我們認為這個標籤不再適用時會發生什麼？當 Adam Gordon Bell 從一個開發人員轉變為一個管理人員時，他很糾結，因為他總是認為自己是技術人員，而作為一個管理人員，這些技術技能沒有被使用。他覺得自己不再有價值了。編寫代碼並不能提供比幫助團隊成員發展事業或確保項目按時交付更大的價值。所有角色都有價值，因為它們都是確保商品和服務的創建、執行和交付所必需的。

“我想我成為一名經理的原因是，我們有一支非常聰明的團隊和很多非常有技能的人，但是我們並不總是能完成最出色的工作。所以技術不是限制因素，對吧？”Adam 説：“我想通常不是技術限制了團隊的發揮”。

Leon Stigter 説，讓人們一起合作並完成令人驚歎的工作的能力是一項很有價值的技能，不應低於技術角色的價值。

自信 ​

冒充者綜合症Impostor syndrome 是指無法認識到自己的能力和知識，從而導致信心下降，以及完成工作和做好工作的能力下降。當你申請在會議上發言，向科技刊物提交文章，或申請工作時，冒充者綜合症就會發作。冒充者綜合症是一種微小的聲音，它説：

  • “我技術不夠勝任這個角色。”
  • “我認識更多的技術人員，他們在演講中會做得更好。”
  • “我在市場部工作，所以我無法為這樣的技術網站寫文章。”

當你把某人或你自己貼上非技術型標籤的時候，這些聲音就會變得更響亮。這很容易導致在會議上聽不到新的聲音或失去團隊中的人才。

刻板印象 ​

當你認為某人是技術人員時，你會看到什麼樣的印象？他們穿什麼？他們還有什麼特點？他們是外向健談，還是害羞安靜？

Shailvi Wakhlu 是一位高級數據總監，她的職業生涯始於軟件工程師，並過渡到數據和分析領域。“當我是一名軟件工程師的時候，很多人都認為我不太懂技術，因為我很健談，很明顯這就意味着你不懂技術。他們認為你不孤獨的待在角落就是不懂技術。”她説。

我們對誰是技術型與非技術型的刻板印象會影響招聘決策或我們的社區是否具有包容性。你也可能冒犯別人，甚至是能夠幫助你的人。幾年前，我在某個展台工作，問別人我能不能幫他們。“我要找最專業的人幫忙”他回答説。然後他就出發去尋找他的問題的答案。幾分鐘後，攤位上的銷售代表和那位先生走到我跟前説：“Dawn，你是回答這個人問題的最佳人選。”

污名化 ​

隨着時間的推移，我們誇大了“技術”技能的重要性，這導致了“非技術”的標籤被貶義地使用。隨着技術的蓬勃發展，編程人員的價值也隨之增加，因為這種技能為市場帶來了新產品和新的商業方式，並直接幫助了盈利。然而，現在我們看到人們故意將技術角色凌駕於非技術角色之上，阻礙了公司的發展和成功。

人際交往技能通常被稱為非技術技能。然而，它們有着高度的技術性，比如提供如何完成一項任務的分步指導，或者確定最合適的詞語來傳達信息或觀點。這些技能往往也是決定你能否在工作中取得成功的更重要因素。

通讀“城市詞典Urban Dictionary”上的文章和定義，難怪人們會覺得自己的標籤有道理，而其他人會患上冒充者綜合症，或者覺得自己失去了身份。在線搜索時，“城市詞典”定義通常出現在搜索結果的頂部。這個網站大約 20 年前開始是一個定義俚語、文化表達和其他術語的眾包詞典，現在變成了一個充滿敵意和負面定義的網站。

這裏有幾個例子：“城市詞典”將非技術經理定義為“不知道他們管理的人應該做什麼的人”

提供如何與“非技術”人員交談技巧的文章包括以下短語：

  • “如果我抗爭，非技術人員究竟是如何應對的？”
  • “在當今的職業專業人士中，開發人員和工程師擁有一些最令人印象深刻的技能，這些技能是由多年的技術培訓和實際經驗磨練而成的。”

這些句子意味着非工程師是低人一等的，他們多年的訓練和現實世界的經驗在某種程度上沒有那麼令人印象深刻。對於這樣的説辭，我可以舉一個反例：Therese Eberhard，她的工作被許多人認為是非技術性的。她是個風景畫家。她為電影和戲劇畫道具和風景。她的工作是確保像甘道夫的手杖這樣的道具看起來栩栩如生，而不是像塑料玩具。要想在這個角色上取得成功，需要有很多解決問題和實驗化學反應的方法。Therese 在多年的實戰經驗中磨練了這些技能，對我來説，這相當令人印象深刻。

守門人行為 ​

使用標籤會設置障礙，並導致守門人行為，這決定誰可以進入我們的組織，我們的團隊，我們的社區。

據一位開源開發者 Eddie Jaoude 所説，“技術’、開發人員‘或`測試人員’的頭銜在不應該出現的地方製造了障礙或權威。我們應該將重點放在誰能為團隊或項目增加價值，而頭銜是無關緊要的。”

如果我們把每個人看作一個團隊成員，他們應該以這樣或那樣的方式貢獻價值，而不是看他們是否編寫文檔、測試用例或代碼，那麼我們將根據真正重要的東西來重視他們，並創建一個能完成驚人工作的團隊。如果測試工程師想學習編寫代碼，或者程序員想學習如何在活動中與人交談，為什麼要設置障礙來阻止這種成長呢？擁抱團隊成員學習、改變和向任何方向發展的渴望，為團隊和公司的使命服務。

如果有人在某個角色上失敗了，與其把他們説成“技術不夠”，不如去看看問題到底是什麼。你是否需要一個精通 JavaScript 的人，而這個人又是另一種編程語言的專家？並不是説他們不專業，是技能和知識不匹配。你需要合適的人來扮演合適的角色。如果你強迫一個精通業務分析和編寫驗收標準的人去編寫自動化測試用例，他們就會失敗。

如何取消標籤 ​

如果你已經準備好改變你對技術性和非技術性標籤的看法，這裏有幫助你改變的提示。

尋找替代詞 ​

我問我採訪過的每個人，我們可以用什麼詞來代替技術和非技術。沒有人能回答！我認為這裏的挑戰是我們不能把它歸結為一個詞。要替換術語，你需要使用更多的詞。正如我之前寫的，我們需要做的是變得更加具體。

你説過或聽到過多少次這樣的話：

  • “我正在為這個項目尋找技術資源。”
  • “那個候選人技術不夠。”
  • “我們的軟件是為非技術用户設計的。”

技術和非技術詞語的這些用法是模糊的，不能表達它們的全部含義。更真實、更詳細地瞭解你的需求那麼你應該説：

  • “我想找一個對如何配置 Kubernetes 有深入瞭解的人。”
  • “那個候選人對 Go 的瞭解不夠深入。”
  • “我們的軟件是為銷售和營銷團隊設計的。”

擁抱成長心態 ​

知識和技能不是天生的。它們是經過數小時或數年的實踐和經驗形成的。認為“我只是技術不夠”或“我不能學習如何做營銷”反映了一種固定的心態。你可以向任何你想發展的方向學習技能。列一張清單，列出你認為哪些是技術技能，或非技術技能，但要具體（如上面的清單）。

認可每個人的貢獻 ​

如果你在科技行業工作，你就是技術人員。在一個項目或公司的成功中，每個人都有自己的作用。與所有做出貢獻的人分享榮譽，而不僅僅是少數人。認可提出新功能的產品經理，而不僅僅是開發新功能的工程師。認可一個作家，他的文章在你的公司迅速傳播併產生了新的線索。認可在數據中發現新模式的數據分析師。
