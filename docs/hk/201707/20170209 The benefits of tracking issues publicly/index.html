開放組織公開追蹤問題的好處 ​

在開放組織中，在線追蹤問題可以將客户轉變成夥伴。

一個公開的問題追蹤器是開放組織的重要溝通工具，和在公開渠道中開展工作相比，沒有比這種方式更透明和包容的方式了。因此，讓我們來探討一下在開放組織中使用問題跟蹤器的一些最佳實踐。

在開始之前，我們先來定義“問題追蹤器issue tracker”的含義。簡單地説，問題跟蹤器是一個共享的待辦事項列表。想像一下一張胡亂寫的待辦事項列表：購買麪包、郵件打包、歸還圖書館書籍。當你在城裏開車時，把列表上的每一項劃掉的感覺很好。現在，將它擴展到你需要在組織中完成的工作，並增加合適的軟件協作能力。這樣你就有一個問題追蹤器了！

無論你使用的是 GitHub 還是其他的，如 Bitbucket、GitLab 或 Trello，問題跟蹤器都是與你的夥伴進行協調的正確工具。這對將外部人員_變成_夥伴是至關重要的，這是開放組織的特徵之一。那麼這是如何工作的？我很高興你問了這個問題。

使用問題追蹤器的最佳實踐 ​

使用公共問題跟蹤器將外部人員轉換為夥伴的最佳實踐是基於過去五年來我們在 Gratipay 的經驗。我們幫助公司和其他組織為開源買單，我們喜歡使用我們的問題跟蹤器與我們的社區合作。這就是我們所學到的。

0、 隱私優先。 在這篇文章中談論公共問題追蹤器的隱私看上去是一個奇怪的開始。但是我們必須記住，開放本身並不是目的，任何真誠和真正的開放是建立在安全和認可的堅實基礎之上的。不要公開發布客户或其他第三方私下給你的信息，除非你明確提出了要求並且得到了他們的明確同意。採納一個隱私政策並培訓你的人員。這篇 Gratipay 的政策可供參考。好的！現在這部分清楚之後，讓我們繼續。

1、 默認採用公開決策。 如果你私下做決策，你就會失去運行一個開放組織的好處，比如表達多樣化的想法、招募有活力的人才、實現更大的責任感。即使你的全職員工是最初使用你的公共問題跟蹤器的唯一員工，那也要這麼做。 避免將你的公共問題追蹤器視為二等公民。如果你在辦公室進行對話，請在公共問題跟蹤器上發佈摘要，並在最終決策之前給你的社區留出時間來響應。這是使用問題跟蹤器解鎖你組織開放權力的第一步：如果它不在問題追蹤器中，那就沒用！

2、 關聯其他工具。 我們許多人都喜歡 IRC 和 Slack，這並不是什麼秘密。或者你的組織已經使用 Trello，但是你也想開始使用 GitHub。這沒問題！在 GitHub issue 中放入 Trello 卡片的鏈接很容易，反之亦然。交叉關聯保證了被一個或另一個問題困住的外部人員能夠發現幫助它們充分理解這個問題的更多相關信息。對於聊天服務，你可能需要配置公共日誌記錄才能維護關聯（隱私注意事項：當你這麼做時，請務必在你的頻道描述中宣傳該事實）。也就是説，你應該在私人 Slack 或其他私人渠道中對話，就像在辦公室裏面對面的對話一樣。換句話説，一定要總結公眾問題跟蹤器上的對話。看看上面説的：無論離線或在線，如果不在問題跟蹤器中，那就沒用！

3、 將談話導向追蹤器中。 社交媒體很快就能獲得很多反饋，尤其是發現問題，但這不是解決問題的地方。問題跟蹤器為深入的對話和分析根本原因留出了空間。更重要的是，它們是為了完成任務而優化的，而不是無限拖延。當問題解決後點擊“關閉”按鈕的感覺真的很好！現在將公共問題跟蹤器作為你的主要工作場所，你可以開始邀請在社交媒體上與你接觸的外部人員在追蹤器中進一步地討論。簡單的如，“感謝您的反饋！聽起來像是（某個公共問題的鏈接）？” ，這可以在很大程度上向外界傳達你的組織沒有隱藏的內容，並歡迎他們的參與。

4、 設置一個“元”追蹤器。 在一開始，你的問題追蹤器很自然聚焦在_具體產品_上。當你準備好開放到一個新的水平時，考慮設置一個關於你的_組織_本身的問題跟蹤。在 Gratipay，我們有一個稱之為 “Inside Gratipay”的公共問題追蹤器，我們願意在其中討論我們組織的任何方面，從我們的預算到我們的法律結構到我們的名字。 是的，這有時有點混亂 —— 重命名組織是一個特別激烈的爭議話題！但對我們來説，在社區參與方面的好處是值得的。

5、 將你的元追蹤器用於加入過程。 一旦你有一個元問題追蹤器，就有了一個新的加入過程：邀請潛在的夥伴創建自己的入場券。如果他們以前從未使用過你的特定的問題追蹤器，那麼這將是他們學習的極好機會。註冊帳號並提交問題應該很簡單（如果不是，請考慮切換工具！）。這將讓你的新夥伴儘早跨過門檻，開始分享參與感，並在組織內部擁有一席之地。當然，沒有問題是愚蠢的，尤其是在某個人的入場券中更是如此。這是你的新夥伴熟悉組織工作方式時詢問任何問題的地方。你需要確保快速回復他們的問題，讓他們參與並幫助他們融入你的組織。這也是一個很好的方法來記錄你最終授予這個人的各種系統的訪問權限。至關重要的是，這可以在僱傭他們之前開始。

6、 雷達項目。 大多數問題跟蹤器包括一些組織和排序任務的方法。例如，GitHub 有里程碑和項目。這些通常旨在使組織成員的工作重點相一致。在 Gratipay，我們發現使用這些工具可以幫助協作者擁有並排序各自的工作重點。與其它的問題跟蹤器通常提供的將問題分配給特定個人的做法不同，我們發現這一點提供了不同的價值。 我可能會關心別人正在積極工作的問題，或者我可能有興趣開始某些事情，但別人先提出來我也很高興。擁有自己的項目空間來組織我對該組織的工作的看法是與我的夥伴們溝通“我的雷達上有什麼”的強大方式。

7、 使用機器人自動化任務。 最終，你可能會發現某些任務會一再出現。這表明自動化可以簡化你的工作流程。在 Gratipay，我們構建了一個機器人幫助我們完成一些重複的任務。誠然，這是一個有點高級的用法。如果你達到了這一點，你能完全使用公共問題追蹤器來開放你的組織！

如 Jim Whitehurst 所説 “吸引社區內外參與” ，這些是我們在 Gratipay 內使用我們的問題跟蹤器的一些最有用的做法。也就是説，我們一直在學習。如果你有自己的經驗分享，請發表評論！
