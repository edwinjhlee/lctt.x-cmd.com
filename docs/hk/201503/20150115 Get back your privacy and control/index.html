權威指南：構建個人私有云，拿回你的數據隱私的控制權！ ​

8年裏40000多次搜索！這是我的Google搜索歷史。你的呢？（可以在這裏自己找一下）有經過這麼長時間積累下來的這麼多數據點，Google已經能非常精確的推測你對什麼感興趣、曾經的想法、擔憂過的事情，以及從你第一次獲得Google帳號後這些年裏所有這些的變化！

很多非常私人的信息不受自己控制地存儲在世界範圍內的服務器上 ​

比如説你也像我一樣從2006年到2013年都是Gmail用户，意味着你收到了30000封以上的電子郵件，以及在這7年裏寫了差不多5000封電子郵件。這些發送或收到的電子郵件裏有很多是非常私人的，私人到你甚至不希望自己的家人或好友可以系統地查看。也許你還寫過一些草稿郵件，因為最後一分鐘改變主意而從沒發出去。但是儘管你從未發出去，這些郵件仍然保存在服務器上的某個地方。結論是，説Google服務器比你最親密的朋友或家人都更瞭解你的個人生活一點也不過分。

從統計數據來看，我可以很保險地打賭你擁有一部智能手機。如果不使用聯繫人應用的話手機將基本沒法用，而它默認會將你的聯繫人信息保存到Google服務器上的Google聯繫人裏。所以，現在Google不僅知道了你的電子郵件，還有了你的離線聯繫人：你喜歡打給誰、誰來過電話、你發過短信給誰，以及發了些什麼。你也不需要聽我的片面之詞，可以自己檢查一下，看看你開放給類似Google Play服務的一些應用的權限，用來讀取來電信息以及收到的短信。你是否還會用到手機裏自帶的日曆應用？除非你在設置日程的時候明確地去掉同步，那麼Google將精確地知道你將要做什麼，一天裏的每個時段、每一天、每一年。用iPhone代替Android手機也是一樣的，只是Apple會代替Google來掌握你的往來郵件、聯繫人和日程計劃。

你是否還會非常小心地同步自己的聯繫人信息，在你朋友，同事或家人換工作或換服務商的時候更新他們的電子郵件地址和手機號？這給Google提供了一副你的社交網絡的非常精確的、最新的描繪。還有你非常喜歡手機的GPS功能，經常配合Google地圖使用。這意味着Google不僅能從日程裏知道你在幹什麼，還知道你在哪兒、住在哪兒、在哪兒工作。然後再關聯用户之間的GPS位置信息，Google還能知道你現在可能正在和哪些人來往。

這種泄漏自己私人信息的日常愛好會以一種甚至沒人能夠預測的方式影響你的生活 ​

總結一下，如果你是一個普通的因特網用户，Google擁有過去差不多10年裏你最新的、深度的信息，關於你的興趣、憂慮、熱情、疑問。它還收集了一些你很私人的信息（電子郵件、短信），精確到小時的你的日常活動和位置，一副你社交網絡的高精度的描繪。關於你的如此私密的數據，很可能已經超越了你最親密的朋友，家人或愛人對你的瞭解。

不敢想像把這些深度的個人信息交給完全陌生的人，就好像把這些信息拷到一個U盤裏，然後隨便放到某個咖啡廳的桌上，留張紙條説“Olivier Martin的個人數據，請隨便”。誰知道什麼人會拿到它以及用來幹嘛？然而，我們毫不猶豫地把自己的主要信息交給那些對我們的數據很感興趣的IT公司的陌生人（這是他們製造麪包的材料）以及世界級的數據分析專家手裏，也許只是因為我們在點擊那個綠色的'接受'按鈕時根本沒有想這麼多。

有這麼多的高質量信息，這麼多年裏，Google可能會比你希望自我瞭解的更瞭解你自己：尼瑪，回想我過去的數字生活，5年前發出的郵件裏有一半我已經不記得了。我很高興能重新發現早在2005年對xxx主義的興趣以及第二年加入了ATTAC（一個致力於通過徵收金融交易税來限制投機和改善社會公平的組織）。天知道為什麼我竟然在2007年這麼喜歡跳舞。這些都是無關緊要的信息（你不指望我能爆出什麼猛料，是吧？;-）。但是，連接起這些高質量數據點，關於你生活的方方面面（做什麼、什麼時候、和誰一起、在哪裏，...），並跨越這麼長時間間隔，應該能推測出你的未來狀態。比如説，根據一個17歲女孩的購物習慣，超市甚至可以在他父親聽説之前斷定這個女孩懷孕了（這是一個真實的故事）。誰知道通過像Google所掌握的這些遠遠超出購物習慣的高質量數據能做些什麼？連接起這些點，也許有人能預測你未來幾年裏口味或觀點的變化。如今，你從未聽過的公司聲稱擁有你500項數據點，包括宗教信仰、性取向和政治觀點。提到政治，如果説你決定今後10年內進入政壇會怎麼樣？你的生活會改變，你的觀點也一樣，甚至你有時候會有所遺忘，但是Google不會。那你會不會擔心你的對手會接觸一些可以從Google訪問你數據的人並會從你過去這些年裏積累的個人數據深淵裏挖出一些猛料呢？就像最近Sony被黑一樣，多久以後會輪到Google或Facebook，以致讓你的個人信息最終永遠暴露？

我們大多數人把自己的個人數據託付給這些公司的一個原因就是它們提供免費服務。但是真的免費嗎？一般的Google帳號的價值根據評估方式不同會有些差別：你花在寫郵件上的時間佔到1000美元/年，你的帳號對於廣告產業的價值差不多在220美元/年到500美元/年之間。所以這些服務並不是真的免費：會通過廣告和我們的數據在未來的一些未知使用來間接付費。

我寫的最多的是Google，這是因為這是我託付個人數字信息的，以及目前我所知道做的最好的公司。但是我也提到過Apple或Facebook。這些公司通過它們在設計、工程和我們（曾經）喜歡每天使用的服務方面的神奇進步實實在在地改變了世界。但是這並不是説我們應該把所有我們最私人的個人數據堆積到它們的服務器上並把我們的數字生活託付給它們：潛在的危害實在太大了。

只要5小時，拿回自己以及關心的人的隱私權 ​

但是事實並不是一定必須這樣的。你可以生活在21世紀，拿着智能手機，每天都用電子郵件和GPS，卻仍然可以保留自己的隱私。你所需要的就是拿回自己個人數據的控制權：郵件、日程、聯繫人、文件，等等。Prism-Break.org網站上列出了一些能幫你掌握個人數據命運的軟件。除此以外，控制自己個人數據的最安全和最有效的方式是架設自己的服務器並搭建自己的雲。不過你也許只是沒有時間或精力去研究具體該怎麼做以及如何讓它能流暢工作。

這也是這篇文章的意義所在。僅僅5個小時內，我們將配置出一台服務器來支撐你的郵件、聯繫人、日程表和各種文件，為你、你的朋友和你的家人。這個服務器將設計成一個個人數據中心或雲，所以你能時刻保留它的完整控制。數據將自動在你的台式機/筆記本、手機和平板之間同步。從根本上來説，我們將建立一個系統來代替Gmail、Google文件/Dropbox、Google聯繫人、Google日曆和Picasa。

為自己做這件事情已經是邁出很大一步了。但是，你個人信息的很大一部分將仍然泄漏出去並保存到硅谷的一些主機上，只是因為和你日常來往的太多人在用Gmail和使用智能手機，所以最好是帶上你一些比較親近的人加入這次探險。

我們將構建的系統能夠：

  • 支持任意數目的域名和用户。這樣就能輕易地和你的家人朋友共享這台服務器，所以他們也能掌控自己的個人數據，並且還能和你一起分攤服務費用。和你一起共享服務器的人可以使用他們自己的域名或者共享你的。
  • 允許你從任意網絡發送和接收電子郵件，需要成功登錄服務器之後。這樣，你可以通過任意的郵件地址、任意設備（台式機、手機、平板）、任意網絡（家裏、公司、公共網絡、...）來發送電子郵件。
  • 在發送和接收郵件的時候加密網絡數據，這樣，你不信任的人不能釣出你的密碼，也不能看到你的私人郵件。
  • 提供最先進的反垃圾郵件技術，結合了已知垃圾郵件黑名單、自動灰名單、和自適應垃圾郵件過濾。如果郵件被誤判了只需要簡單地把它拖入或拖出垃圾目錄就可以重新調校垃圾郵件過濾器。而且，服務器還會為基於社區的反垃圾郵件努力做出貢獻。
  • 一段時間裏只需要幾分鐘的維護，基本上只是安裝安全更新和簡單地檢查一下服務器日誌。添加一個新的郵件地址只需要在資料庫中插入一條記錄。除此之外，你可以忘記它的存在過自己的生活。我在14個月之前搭建了本文描述的這個系統，從那以後就一直順利運行。所以我完全把它給忘了，直到我最近覺得隨便按下手機上的‘檢查郵件’會導致電子信號一路跑到冰島（我放置服務器的地方）再回來的想法有點好笑才想起來。

要完成這篇文章裏的工作，你需要一點基本的技術能力。如果你知道SMTP和IMAP的區別，什麼是DNS，以及對TCP/IP有基本瞭解的話，就夠了。你還將需要一點基本的Unix知識（在命令列下和文件一起工作，基本的系統管理）。然後你需要花總共5小時時間來搭建。

下面是我們將要做的事情的概述。

  • 申請一個虛擬私人服務器，一個域名，並把它們配置好
  • 設置postfix和dovecot來收發電子郵件
  • 阻止垃圾郵件進入你的收件箱
  • 確保你發出的郵件能通過垃圾郵件過濾器
  • 使用Owncloud提供日曆，聯繫人，文件服務並配置webmail
  • 在雲上同步你的設備

這篇文章是受之前工作的啓發並以之為基礎 ​

本文很大程度參考了兩篇文章，由Xavier Claude和Drew Crawford寫的關於架設私有郵件服務器的介紹。

本文覆蓋了Xavier和Drew的文章裏所描述的所有功能，除了3個地方Drew有而我沒有：郵件推送支持（我喜歡由我主動檢查郵件，而其他時候都不會被打擾），郵件全文檢索（我一直都沒用過），以及使用加密方式存儲郵件（我的郵件和數據還沒那麼重要到要把它們加密後再存到本地服務器上）。如果你需要這些功能，只需要按照Drew的文章裏相應部分的説明做就好了，和本文的內容兼容。

和Xavier和Drew的成果比起來，本文有下面幾個主要改進：

  • 根據我自己按Drew文章操作的經驗以及原文的大量回復，修改了一些問題和文字錯誤。我也把本文所介紹的內容仔細檢查了幾遍，從頭開始設定了幾次服務器做重複驗證以確保能正常工作。
  • 低維護：和Xavier的方式比起來，本文增加了在服務器上支持多個郵件域名。這樣做是為了儘可能地減少服務器維護工作：基本上，要添加一個域名或用户，只需要往mysql資料庫表裏增加一行就好了（不需要增加過濾腳本，等等）。
  • 我增加了webmail。
  • 我增加了設定雲服務器的部分，不僅能收發郵件還能管理文件，地址本/聯繫人（郵件地址，電話號碼，生日，等等等），日程表和圖片，供所有設備訪問使用。

申請一個虛擬私人服務器，一個域名，並把它們配置好 ​

讓我們從設置基礎設施開始：我們的虛擬私人主機和我們的域名。

我用過1984.is和Linode提供的虛擬私人主機（VPS），體驗非常好。在本文中，我們將使用Debian Wheezy，這個在1984和Linode都提供了已經做好的映像文件可以直接佈置到你的VPS上。我喜歡1984是因為它的服務器在冰島，也是唯一使用可再生能源（地熱和水力發電）的地方，目前還沒有影響過氣候變化，不像大多數美國數據中心目前大多數依賴於燒煤的火力發電站。而且，他們注重民權，透明，自由以及免費軟件。

最好是在服務器上創建一個文件用來保存後面要用到的各種密碼（用户賬號、郵件賬號、雲帳號、資料庫帳號）。當然最好是加密一下（可以用GnuPG），這樣就算用來設定服務器的電腦被偷了或被入侵了，你的服務器就不會那麼容易被攻擊。

關於註冊域名，我已經使用grandi的服務超過10年了，也很滿意。在本文中，我們將開闢一個叫jhausse.net的域名。然後在上面增加一個叫cloud.jhausse.net的二級域名，並綁定MX紀錄。在完成之後，設置比較短的紀錄生存時間（TTL）比如300秒，這樣你在設置服務器的時候，可以修改你的域並很快測試到結果。

最後，設置PTR紀錄（反向DNS），這樣IP地址可以反向映射回它的域名。如果你不理解前面這句話，看下這篇文章來獲得相關背景知識。如果你使用Linode的服務，你可以在遠程訪問這一欄的控制面板裏設置PTR紀錄。如果是1984，聯繫一下技術支持來幫你搞定。

在服務器上，我們從添加一個普通用户開始，這樣我們不用從頭到尾一直用root賬號。另外，用root登陸也需要額外多一層安全措施。

adduser roudy

然後，在文件/etc/ssh/sshd_config中設置

PermitRootLogin no

然後重啓ssh服務

service ssh reload

然後，我們要修改服務器的主機名。編輯文件/etc/hostname，只有一行就是自己的主機名，我們這個例子中是

cloud

然後，編輯ssh服務的公鑰文件/etc/ssh/ssh_host_rsa_key.pub, /etc/ssh/ssh_host_dsa_key.pub, /etc/ssh/ssh_host_ecdsa_key.pub，這樣文件末尾可以反映你的主機名，比如root@cloud。然後重啓系統保證主機名在系統的每個需要它的角落都生效了。

reboot

我們將更新系統並移除不必要的服務以降低遠程攻擊的風險。

apt-get update
apt-get dist-upgrade
service exim4 stop
apt-get remove exim4 rpcbind
apt-get autoremove
apt-get install vim

我喜歡使用vim遠程編輯配置文件。打開vim 的自動語法高亮會很有幫助。添加下面這一行到~/.vimrc文件中。

syn on

設置postfix和dovecot來收發電子郵件 ​

apt-get install postfix postfix-mysql dovecot-core dovecot-imapd dovecot-mysql mysql-server dovecot-lmtpd postgrey

在Postfix的配置菜單裏，選擇Internet Site，設置這個系統的郵件名稱為jhausse.net。

現在開始添加一個數據庫用於保存主機上管理的域名列表，和每個域名下的用户列表（同時也包括他們各自的密碼），以及郵件別名列表（用於從一個地址往另一個地址轉發郵件）。

mysqladmin -p create mailserver
mysql -p mailserver
mysql> GRANT SELECT ON mailserver.* TO 'mailuser'@'localhost' IDENTIFIED BY 'mailuserpass';
mysql> FLUSH PRIVILEGES;
mysql> CREATE TABLE `virtual_domains` (
  `id` int(11) NOT NULL auto_increment,
  `name` varchar(50) NOT NULL,
  PRIMARY KEY (`id`)
  ) ENGINE=InnoDB DEFAULT CHARSET=utf8;
mysql> CREATE TABLE `virtual_users` (
  `id` int(11) NOT NULL auto_increment,
  `domain_id` int(11) NOT NULL,
  `password` varchar(106) NOT NULL,
  `email` varchar(100) NOT NULL,
  PRIMARY KEY (`id`),
  UNIQUE KEY `email` (`email`),
  FOREIGN KEY (domain_id) REFERENCES virtual_domains(id) ON DELETE CASCADE
  ) ENGINE=InnoDB DEFAULT CHARSET=utf8;
mysql> CREATE TABLE `virtual_aliases` (
  `id` int(11) NOT NULL auto_increment,
  `domain_id` int(11) NOT NULL,
  `source` varchar(100) NOT NULL,
  `destination` varchar(100) NOT NULL,
  PRIMARY KEY (`id`),
  FOREIGN KEY (domain_id) REFERENCES virtual_domains(id) ON DELETE CASCADE
  ) ENGINE=InnoDB DEFAULT CHARSET=utf8;

這裏我們為jhausse.net域名提供郵件服務。如果還需要加入其他域名，也沒問題。我們也會為每個域名設置一個郵件管理地址（postmaster），轉寄給roudy@jhausse.net。

mysql> INSERT INTO virtual_domains (`name`) VALUES ('jhausse.net');
mysql> INSERT INTO virtual_domains (`name`) VALUES ('otherdomain.net');
mysql> INSERT INTO virtual_aliases (`domain_id`, `source`, `destination`) VALUES ('1', 'postmaster', 'roudy@jhausse.net');
mysql> INSERT INTO virtual_aliases (`domain_id`, `source`, `destination`) VALUES ('2', 'postmaster', 'roudy@jhausse.net');

現在已經添加了一個本地郵件賬號roudy@jhausse.net。首先，為它生成一個密碼的哈希串：

doveadm pw -s SHA512-CRYPT

然後把哈希值加入到資料庫中

mysql> INSERT INTO `mailserver`.`virtual_users` (`domain_id`, `password`, `email`) VALUES ('1', '$6$YOURPASSWORDHASH', 'roudy@jhausse.net');

現在我們的域名、別名和用户列表都設置好了，然後開始設置postfix（這是一個SMTP服務器，用來發送郵件）。把文件/etc/postfix/main.cf替換為下面的內容：

myhostname = cloud.jhausse.net
myorigin = /etc/mailname
mydestination = localhost.localdomain, localhost
mynetworks_style = host

# We disable relaying in the general case
smtpd_recipient_restrictions = permit_mynetworks, reject_unauth_destination
# Requirements on servers that contact us: we verify the client is not a
# known spammer (reject_rbl_client) and use a graylist mechanism
# (postgrey) to help reducing spam (check_policy_service)
smtpd_client_restrictions = permit_mynetworks, reject_rbl_client zen.spamhaus.org, check_policy_service inet:127.0.0.1:10023

阻止垃圾郵件進入你的收件箱 ​

為了過濾垃圾郵件，我們已經使用了實時黑名單（RBL）和灰名單（postgrey）。現在我們將增加自適應垃圾郵件過濾來讓我們的垃圾郵件過濾能力提高一個等級。這意味着我們將為我們的郵件服務器增加人工智能，這樣它就能從經驗中學習哪些郵件是垃圾哪些不是。我們將使用dspam來實現這個功能。

apt-get install dspam dovecot-antispam postfix-pcre dovecot-sieve

dovecot-antispam是一個安裝包，可以在我們發現有郵件被dspam誤分類了之後讓dovecot重新更新垃圾郵件過濾器。基本上，我們所需要做的就只是把郵件放進或拿出垃圾箱。dovecot-antispam將負責調用dspam來更新過濾器。至於postfix-pcre和dovecot-sieve，我們將分別用它們來把接收的郵件傳遞給垃圾郵件過濾器以及自動把垃圾郵件放入用户的垃圾箱。

在配置文件/etc/dspam/dspam.conf裏，為以下參數設置相應的值：

TrustedDeliveryAgent "/usr/sbin/sendmail"
UntrustedDeliveryAgent "/usr/lib/dovecot/deliver -d %u"
Tokenizer osb
IgnoreHeader X-Spam-Status
IgnoreHeader X-Spam-Scanned
IgnoreHeader X-Virus-Scanner-Result
IgnoreHeader X-Virus-Scanned
IgnoreHeader X-DKIM
IgnoreHeader DKIM-Signature
IgnoreHeader DomainKey-Signature
IgnoreHeader X-Google-Dkim-Signature
ParseToHeaders on
ChangeModeOnParse off
ChangeUserOnParse full
ServerPID               /var/run/dspam/dspam.pid
ServerDomainSocketPath  "/var/run/dspam/dspam.sock"
ClientHost      /var/run/dspam/dspam.sock

然後，在配置文件/etc/dspam/default.prefs裏，把以下參數改為：

spamAction=deliver         # { quarantine | tag | deliver } -> default:quarantine
signatureLocation=headers  # { message | headers } -> default:message
showFactors=on

現在我們需要把dspam連接到postfix和dovecot上，在配置文件/etc/postfix/master.cf最後添加這樣兩行：

dspam     unix  -       n       n       -       10      pipe
  flags=Ru user=dspam argv=/usr/bin/dspam --deliver=innocent,spam --user $recipient -i -f $sender -- $recipient
dovecot   unix  -       n       n       -       -       pipe
  flags=DRhu user=mail:mail argv=/usr/lib/dovecot/deliver -f ${sender} -d ${recipient}

現在我們將告訴postfix通過dspam來過濾所有提交給服務器端口25（一般的SMTP通信）的新郵件，除非該郵件是從服務器本身發出（permit_mynetworks）。注意下我們通過SASL鑑權提交給postfix的郵件不會通過dspam過濾，因為我們在前面部分裏為這種方式設定了獨立的提交服務。編輯文件/etc/postfix/main.cf將選項smtpd_client_restrictions改為如下內容：

smtpd_client_restrictions = permit_mynetworks, reject_rbl_client zen.spamhaus.org, check_policy_service inet:127.0.0.1:10023, check_client_access pcre:/etc/postfix/dspam_filter_access

在文件末尾，還需要增加：

# For DSPAM, only scan one mail at a time
dspam_destination_recipient_limit = 1

現在我們需要指定我們定義的過濾器。基本上，我們將告訴postfix把所有郵件（如下用 /./ 代表）通過unix套接字發給dspam。創建一個新文件/etc/postfix/dspam_filter_access並把下面一行寫進去：

/./   FILTER dspam:unix:/run/dspam/dspam.sock

這是postfix部分的配置。現在讓我們為dovecot設置垃圾過濾。在文件/etc/dovecot/conf.d/20-imap.conf裏，修改imap mail_plugin插件參數為下面的方式：

mail_plugins = $mail_plugins antispam

  mail_plugins = $mail_plugins sieve

plugin {
  ...
  # Antispam (DSPAM)
  antispam_backend = dspam
  antispam_allow_append_to_spam = YES
  antispam_spam = Junk;Spam
  antispam_trash = Trash;trash
  antispam_signature = X-DSPAM-Signature
  antispam_signature_missing = error
  antispam_dspam_binary = /usr/bin/dspam
  antispam_dspam_args = --user;%u;--deliver=;--source=error

  antispam_dspam_notspam = --class=innocent
  antispam_dspam_result_header = X-DSPAM-Result

然後在文件/etc/dovecot/conf.d/90-sieve.conf裏指定默認的sieve腳本，這個將對服務器上所有用户有效：

sieve_default = /etc/dovecot/default.sieve

什麼是sieve以及為什麼我們需要為所有用户設置一個默認腳本？sieve可以在IMAP服務器上為我們自動處理任務。在我們的例子裏，我們想讓所有被確定為垃圾的郵件移到垃圾箱而不是收件箱裏。我們希望這是服務器上所有用户的默認行為；這是為什麼我們把這個腳本設為默認腳本。現在讓我們來創建這個腳本，建立一個新文件/etc/dovecot/default.sieve並寫入以下內容：

require ["regex", "fileinto", "imap4flags"];
# Catch mail tagged as Spam, except Spam retrained and delivered to the mailbox
if allof (header :regex "X-DSPAM-Result" "^(Spam|Virus|Bl[ao]cklisted)$",
          not header :contains "X-DSPAM-Reclassified" "Innocent") {
  # Mark as read
  # setflag "\\Seen";
  # Move into the Junk folder
  fileinto "Junk";
  # Stop processing here
  stop;
}

現在我們需要編譯這個腳本好讓dovecot能運行它。我們也需要給它合適的權限。

確保你發出的郵件能通過垃圾郵件過濾器 ​

這個部分我們的目標是讓我們的郵件服務器能儘量乾淨地出現在世界上，並讓垃圾郵件發送者們更難以我們的名義發郵件。作為附加效果，這也有助於讓我們的郵件能通過其他郵件服務器的垃圾郵件過濾器。

發送者策略框架（SPF） ​

發送者策略框架（SPF）是你添加到自己服務器區域裏的一份記錄，聲明瞭整個因特網上哪些郵件服務器能以你的域名發郵件。設置非常簡單，使用microsoft.com上的SPF嚮導來生成你的SPF記錄，然後作為一個TXT記錄添加到自己的服務器區域裏。看上去像這樣：

jhausse.net.	300 IN	TXT	v=spf1 mx mx:cloud.jhausse.net -all

反向PTR ​

我們之前在本文裏討論過這個問題，建議你為自己的服務器正確地設置反向DNS，這樣對服務器IP地址的反向查詢能返回你服務器的實際名字。

OpenDKIM ​

當我們激活OpenDKIM後，postfix會用密鑰為每封發出去的郵件簽名。然後我們將把這個密鑰存儲在DNS域中。這樣的話，世界上任意一個郵件服務器都能夠檢驗郵件是否真的是我們發出的，或是由垃圾郵件發送者偽造的。讓我們先安裝opendkim：

apt-get install opendkim opendkim-tools

然後按如下方式編輯/etc/opendkim.conf文件的配置：

##
## opendkim.conf -- configuration file for OpenDKIM filter
##
Canonicalization        relaxed/relaxed
ExternalIgnoreList      refile:/etc/opendkim/TrustedHosts
InternalHosts           refile:/etc/opendkim/TrustedHosts
KeyTable                refile:/etc/opendkim/KeyTable
LogWhy                  Yes
MinimumKeyBits          1024
Mode                    sv
PidFile                 /var/run/opendkim/opendkim.pid
SigningTable            refile:/etc/opendkim/SigningTable
Socket                  inet:8891@localhost
Syslog                  Yes
SyslogSuccess           Yes
TemporaryDirectory      /var/tmp
UMask                   022
UserID                  opendkim:opendkim

我們還需要幾個額外的文件，需保存在目錄/etc/opendkim裏：

mkdir -pv /etc/opendkim/
cd /etc/opendkim/

讓我們建立新文件/etc/opendkim/TrustedHosts並寫入以下內容

127.0.0.1

建立新文件/etc/opendkim/KeyTable並寫入以下內容

cloudkey jhausse.net:mail:/etc/opendkim/mail.private

這會告訴OpenDKIM我們希望使用一個名叫'cloudkey'的加密密鑰，它的內容在文件/etc/opendkim/mail.private裏。我們建立另一個名叫/etc/opendkim/SigningTable的文件然後寫入下面這一行：

*@jhausse.net cloudkey

這會告訴OpenDKIM每封從jhausse.net域發出的郵件都應該用'cloudkey'密鑰簽名。如果我們還有其他域希望也能簽名，我們也可以在這裏添加。

下一步是生成密鑰並修改OpenDKIM配置文件的權限。

opendkim-genkey -r -s mail [-t]
chown -Rv opendkim:opendkim /etc/opendkim
chmod 0600 /etc/opendkim/*
chmod 0700 /etc/opendkim

一開始，最好使用-t開關，這樣會通知其他郵件服務器你只是在測試模式下，這樣他們就不會丟棄基於你的OpenDKIM簽名的郵件（目前來説）。你可以從mail.txt文件裏看到OpenDKIM密鑰：

cat mail.txt

然後把它作為一個TXT記錄添加到區域文件裏，應該是類似這樣的

mail._domainkey.cloud1984.net.	300	IN TXT	v=DKIM1; k=rsa; p=MIGfMA0GCSqG...

最後，我們需要告訴postfix來為發出的郵件簽名。在文件/etc/postfix/main.cf末尾，添加：

# Now for OpenDKIM: we'll sign all outgoing emails
smtpd_milters = inet:127.0.0.1:8891
non_smtpd_milters = $smtpd_milters
milter_default_action = accept

然後重啓相關服務：

service postfix reload
service opendkim restart

現在讓我們測試一下是否能找到我們的OpenDKIM公鑰並和私鑰匹配：

opendkim-testkey -d jhausse.net -s mail -k mail.private -vvv

這個應該返回：

opendkim-testkey: key OK

這個你可能需要等一會直到域名服務器重新加載該區域（對於Linode，每15分鐘會更新一次）。你可以用dig來檢查區域是否已經重新加載。

如果這個沒問題，讓我們測試一下其他服務器能驗證我們的OpenDKIM簽名和SPF記錄。要做這個，我們可以用Brandon Checkett的郵件測試系統。發送一封郵件到Brandon的網頁上提供的測試地址，我們可以在服務器上運行下面的命令

mail -s CloudCheck ihAdmTBmUH@www.brandonchecketts.com

在Brandon的網頁上，我們應該可以在'DKIM Signature'部分裏看到result = pass的文字，以及在'SPF Information'部分看到Result: pass的文字。如果我們的郵件通過這個測試，只要不加-t開關重新生成OpenDKIM密鑰，上傳新的密鑰到區域文件裏，然後重新測試檢查是否仍然可以通過這些測試。如果可以的話，恭喜！你已經在你的服務器上成功配置好OpenDKIM和SPF了！

使用Owncloud提供日曆，聯繫人，文件服務並通過Roundcube配置網頁郵件 ​

既然我們已經擁有了一流的郵件服務器，讓我們再為它增加在雲上保存通訊錄，日程表和文件的能力。這些是Owncloud所提供的非常讚的服務。在這個弄好後，我們還會設置一個網頁郵件，這樣就算你沒帶任何電子設備出去旅行時，或者説在你的手機或筆記本沒電的情況下，也可以通過網吧來檢查郵件。

$rcmail_config['default_host'] = 'ssl://localhost';

        </Directory>

在雲上同步你的設備 ​

在Owncloud的文檔裏描述瞭如何與雲端同步你的日程表和聯繫人。在Android系統中，我用的是CalDAV-Sync，CardDAV-Sync應用橋接了手機上Android自帶日曆以及聯繫人應用和Owncloud服務器。

對於文件，有一個叫Owncloud的Android應用可以訪問你手機上的文件，然後自動把你拍的圖片和視頻上傳到雲中。在你的Mac/PC上訪問雲端文件也很容易，在Owncloud文檔裏有很好的描述。

最後一點提示 ​

在上線後的前幾個星期裏，最好每天檢查一下日誌/var/log/syslog和/var/log/mail.log以保證一切都在順利運行。在你邀請其他人（朋友，家人，等等）加入你的服務器之前這很重要。他們信任你能很好地架設個人服務器維護他們的數據，但是如果服務器突然崩潰會讓他們很失望。

要添加另一個郵件用户，只要在資料庫mailserver的virtual_users表中增加一行。

要添加一個域名，只要在virtual_domains表中增加一行。然後更新/etc/opendkim/SigningTable為發出的郵件簽名，上傳OpenDKIM密鑰到服務器區域，然後重啓OpenDKIM服務。

Owncloud有自己的用户數據庫，在用管理員帳號登錄後可以修改。

最後，萬一在服務器臨時崩潰的時候想辦法找解決方案很重要。比如説，在服務器恢復之前你的郵件應該送往哪兒？一種方式是找個能幫你做備份MX的朋友，同時你也可以當他的備份MX（看下postfix的配置文件main.cf裏relay_domains和relay_recipient_maps裏的設定）。與此類似，如果你的服務器被破解然後一個壞蛋把你所有文件刪了怎麼辦？對於這個，考慮增加一個常規備份系統就很重要了。Linode提供了備份選項。在1984.is裏，我用crontabs和scp做了一個基本但管用的自動備份系統。
