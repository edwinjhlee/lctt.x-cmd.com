Fedora 33 開始測試切換到 Btrfs ​

儘管距離 Fedora 的下一個穩定版本（Fedora 33）還有幾個月的距離，但仍有一些值得關注的變化。

在所有其他 Fedora 33 接受的系統範圍的更改中，最有趣的提議是將 Btrfs 作為桌面的默認文件系統，這個提議現在已經被批准了。

這是 Fedora 對該提案的評價：

對於安裝 Fedora 的筆記本電腦和工作站，我們希望以透明的方式向用户提供文件系統功能。我們希望添加新功能，同時減少處理磁盤空間不足之類的情況所需的專業知識。Btrfs 它的設計理念非常適合這個角色，讓我們將其設為默認設置。

值得注意的是，在測試的最終投票結果出來之前，這不是系統範圍內的更改。

但是，現在測試已經成功完成，投票結果也是贊成的 —— Fedora 33 版本已經接受了這個改動。

那麼，為什麼 Fedora 提出這一更改？這會有什麼用麼？這是糟糕的舉動嗎？對 Fedora 的發行有何影響？讓我們在這裏談論下。

它會影響哪些 Fedora 版本？ ​

根據提議，如果測試成功，那麼 Fedora 33 的所有桌面版本、spins 和 labs 都受此影響。

因此，你可以期望工作站版本將 Btrfs 作為 Fedora 33 上的默認文件系統。

實施此更改的潛在好處 ​

為了改進 Fedora 在筆記本和工作站的使用，Btrfs 文件系統提供了一些好處。

現在 Fedora 33 將成為默認文件系統 —— 讓我來指出使用 Btrfs 作為默認文件系統的好處：

  • 延長存儲硬件的使用壽命
  • 提供一個簡單的方案來解決用户耗盡根目錄或主目錄上的可用空間的情況
  • 不易造成數據損壞，易於恢復
  • 提供更好的調整文件系統大小的功能
  • 通過強制 I/O 限制來確保桌面在高內存壓力下的響應能力
  • 使複雜的存儲設置易於管理

如果你感到好奇，你可能想更深入地瞭解 Btrfs 及其總體優點。

不要忘記，Btrfs 已經是受支持的選項，它只是不是默認的文件系統而已。

但是，總的來説，感覺在Fedora 33上引入Btrfs作為默認文件系統是一個有用的變化。

Red Hat Enterprise Linux 會不會實現它？ ​

很明顯，Fedora 被認為是 Red Hat Enterprise Linux 的前沿版本。

因此，如果 Fedora 拒絕更改，那麼 Red Hat 將不會實施。另一方面，如果你希望 RHEL 使用 Btrfs，那麼 Fedora 應該首先同意更改。

為了讓你更加清楚，Fedora 對其進行了詳細介紹：

Red Hat 在許多方面都很好地支持 Fedora。但是 Fedora 已經與上游緊密合作，並依賴上游。這將是其中之一。這是該提案的重要考慮因素。社區有責任確保它得到支持。如果 Fedora 拒絕，那麼 Red Hat 將永遠不會支持 Btrfs。Fedora 必然需要成為第一個，並提出令人信服的理由，説明它比替代方案能解決更多的問題。它的負責人相信它確實如此，毫無疑問。

另外，值得注意的是，如果你不想在 Fedora 中使用 btrfs，你應該看看 OpenSUSE 和 SUSE Linux Enterprise。

總結 ​

即使這個更改看起來不會影響任何升級或兼容性，你也可以在 Fedora 項目的 Wiki 頁面中找到有關 Btrfs 的更改的更多信息。
