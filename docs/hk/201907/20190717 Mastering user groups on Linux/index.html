掌握 Linux 用户組 ​

在 Linux 系統中管理用户組並不費力，但相關命令可能比你所知的更為靈活。

在 Linux 系統中用户組起着重要作用。用户組提供了一種簡單方法供一組用户互相共享文件。用户組也允許系統管理員更加有效地管理用户權限，因為管理員可以將權限分配給用户組而不是逐一分配給單個用户。

儘管通常只要在系統中添加用户賬户就會創建用户組，關於用户組如何工作以及如何運用用户組還有很多需要了解的。

一個用户一個用户組？ ​

Linux 系統中多數用户賬户被設為用户名與用户組名相同。用户 jdoe 會被賦予一個名為 jdoe 的用户組，且成為該新建用户組的唯一成員。如本例所示，該用户的登錄名，用户 id 和用户組 id 在新建賬户時會被添加到 /etc/passwd 和 /etc/group 文件中：

$ sudo useradd jdoe
$ grep jdoe /etc/passwd
jdoe:x:1066:1066:Jane Doe:/home/jdoe:/bin/sh
$ grep jdoe /etc/group
jdoe:x:1066:

這些文件中的配置使系統得以在文本（jdoe）和數字（1066）這兩種用户 id 形式之間互相轉換—— jdoe 就是 1006，且 1006 就是 jdoe。

分配給每個用户的 UID（用户 id）和 GID（用户組 id）通常是一樣的，並且順序遞增。若上例中 Jane Doe 是最近添加的用户，分配給下一個新用户的用户 id 和用户組 id 很可能都是 1067。

GID = UID？ ​

UID 和 GID 可能不一致。例如，如果你用 groupadd 命令添加一個用户組而不指定用户組 id，系統會分配下一個可用的用户組 id（在本例中為 1067）。下一個添加到系統中的用户其 UID 會是 1067 而 GID 則為 1068。

你可以避免這個問題，方法是添加用户組的時候指定一個較小的用户組 id 而不是接受默認值。在下面的命令中我們添加一個用户組並提供一個 GID，這個 GID 小於用於用户賬户的 GID 取值範圍。

$ sudo groupadd -g 500 devops

創建賬户時你可以指定一個共享用户組，如果這樣對你更合適的話。例如你可能想把新來的開發人員加入同一個 DevOps 用户組而不是一人一個用户組。

$ sudo useradd -g staff bennyg
$ grep bennyg /etc/passwd
bennyg:x:1064:50::/home/bennyg:/bin/sh

主要用户組和次要用户組 ​

用户組實際上有兩種：主要用户組primary group和次要用户組secondary group。

主要用户組是保存在 /etc/passwd 文件中的用户組，該用户組在賬户創建時配置。當用户創建一個文件時，用户的主要用户組與此文件關聯。

$ whoami
jdoe
$ grep jdoe /etc/passwd
jdoe:x:1066:1066:John Doe:/home/jdoe:/bin/bash
             ^
             |
             +-------- 主要用户組
$ touch newfile
$ ls -l newfile
-rw-rw-r-- 1 jdoe jdoe 0 Jul 16 15:22 newfile
                   ^
                   |
                   +-------- 主要用户組

用户一旦擁有賬户之後被加入的那些用户組是次要用户組。次要用户組成員關係在 /etc/group 文件中顯示。

$ grep devops /etc/group
devops:x:500:shs,jadep
          ^
          |
          +-------- shs 和 jadep 的次要用户組

/etc/group 文件給用户組分配組名稱（例如 500 = devops）並記錄次要用户組成員。

首選的準則 ​

每個用户是他自己的主要用户組成員，並可以成為任意多個次要用户組成員，這樣的一種準則允許用户更加容易地將個人文件和需要與同事分享的文件分開。當用户創建一個文件時，用户所屬的不同用户組的成員不一定有訪問權限。用户必須用 chgrp 命令將文件和次要用户組關聯起來。

哪裏也不如自己的家目錄 ​

添加新賬户時一個重要的細節是 useradd 命令並不一定為新用户添加一個家目錄/home家目錄。若你只有某些時候想為用户添加家目錄，你可以在 useradd 命令中加入 -m 選項（可以把它想像成“安家”選項）。

$ sudo useradd -m -g devops -c "John Doe" jdoe2

此命令中的選項如下：

  • -m 創建家目錄並在其中生成初始文件
  • -g 指定用户歸屬的用户組
  • -c 添加賬户描述信息（通常是用户的姓名）

若你希望總是創建家目錄，你可以編輯 /etc/login.defs 文件來更改默認工作方式。更改或添加 CREATE_HOME 變量並將其設置為 yes：

$ grep CREATE_HOME /etc/login.defs
CREATE_HOME     yes

另一種方法是用自己的賬户設置別名從而讓 useradd 一直帶有 -m 選項。

$ alias useradd=’useradd -m’

確保將該別名添加到你的 ~/.bashrc 文件或類似的啓動文件中以使其永久生效。

深入瞭解 /etc/login.defs ​

下面這個命令可列出 /etc/login.defs 文件中的全部設置。下面的 grep 命令會隱藏所有註釋和空行。

$ cat /etc/login.defs | grep -v "^#" | grep -v "^$"
MAIL_DIR        /var/mail
FAILLOG_ENAB            yes
LOG_UNKFAIL_ENAB        no
LOG_OK_LOGINS           no
SYSLOG_SU_ENAB          yes
SYSLOG_SG_ENAB          yes
FTMP_FILE       /var/log/btmp
SU_NAME         su
HUSHLOGIN_FILE  .hushlogin
ENV_SUPATH      PATH=/usr/local/sbin:/usr/local/bin:/usr/sbin:/usr/bin:/sbin:/bin
ENV_PATH        PATH=/usr/local/bin:/usr/bin:/bin:/usr/local/games:/usr/games
TTYGROUP        tty
TTYPERM         0600
ERASECHAR       0177
KILLCHAR        025
UMASK           022
PASS_MAX_DAYS   99999
PASS_MIN_DAYS   0
PASS_WARN_AGE   7
UID_MIN                  1000
UID_MAX                 60000
GID_MIN                  1000
GID_MAX                 60000
LOGIN_RETRIES           5
LOGIN_TIMEOUT           60
CHFN_RESTRICT           rwh
DEFAULT_HOME    yes
CREATE_HOME         yes                 <===
USERGROUPS_ENAB yes
ENCRYPT_METHOD SHA512

注意此文件中的各種設置會決定用户 id 的取值範圍以及密碼使用期限和其他設置（如 umask）。

如何顯示用户所屬的用户組 ​

出於各種原因用户可能是多個用户組的成員。用户組成員身份給與用户對用户組擁有的文件和目錄的訪問權限，有時候這種工作方式是至關重要的。要生成某個用户所屬用户組的清單，用 groups 命令即可。

$ groups jdoe
jdoe : jdoe adm admin cdrom sudo dip plugdev lpadmin staff sambashare

你可以鍵入不帶任何參數的 groups 命令來列出你自己的用户組。

如何添加用户至用户組 ​

如果你想添加一個已有用户至別的用户組，你可以仿照下面的命令操作：

$ sudo usermod -a -G devops jdoe

你也可以指定逗號分隔的用户組列表來添加一個用户至多個用户組：

$ sudo usermod -a -G devops,mgrs jdoe

參數 -a 意思是“添加”，-G 指定用户組列表。

你可以編輯 /etc/group 文件將用户名從用户組成員名單中刪除，從而將用户從用户組中移除。usermod 命令或許也有個選項用於從用户組中刪除某個成員。

fish:x:16:nemo,dory,shark
           |
           V
fish:x:16:nemo,dory

提要 ​

添加和管理用户組並非特別困難，但長遠來看配置賬户時的一致性可使這項工作更容易些。
