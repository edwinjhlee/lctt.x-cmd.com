軟件在吞噬世界，但是開源軟件在吞噬自己 ​

在開源世界，大家都不安分

像Marc Andreessen posits所説，軟件可能在吞噬世界，但是開源軟件似乎在吞噬自己。伴隨着快速的步伐，軟件世界逐漸習慣產業化，他們的賣主開始為更多的利益投資（比如：在操作系統方面的微軟和資料庫方面的甲骨文）， 開源軟件的世界正邁向一個加速進化的時代，從來不滿足於既得的榮譽。

在快速變更的開源世界，企業如何投資？

開源超神了 ​

雖然Dirk Riehle對於開源項目增長的分析並不是特別過時，當然，一部分已經增長的趨勢除外：

現在大部分重要領域的技術-大數據，雲，移動-都是開源的。伴隨着Haddop、OpenStack等工具的活躍，我們應該期待開源軟件卯足了勁發展。

這是好是壞？

開源碼農競爭激烈 ​

舉個栗子，在系統配置領域。 Redmonk 的 Stephen O'Grady 挑了些數據用來衡量受歡迎程度，Chef、 Puppet、 Ansible 和 Salt，後面兩個是這個領域的新星，但是贏得了相當的社區熱情和採納度。

這讓O'Grady 推測：“ 看起來合理地去認為系統配置領域會和開源關係型資料庫一樣有相同的變革趨勢，伴隨着兩個突出的工程出現，這樣的觀點有點問題。”

O’Grady覺得：

從這些觀察中得出的最有趣的結論或許是 Ansible 和 Salt 的關聯。這些工程會有不錯的前景，比如在這個領域對解決方案的需求，和非常強的個人偏好的影響，例如，Salt 在 Python 開發者當中的親和力。

實際上，我必須承認最有趣的的結論是，沒有開源項目能保證長久。Puppet 在2005年退出，並且一直在和有固定期權的在職者競爭，現在和Chef競爭（4年後退出），Ansible（最新兩年）和 Salt（最新兩年）。

任何重要領域的在職者，總是會窮追不捨地吹毛求疵。但是在開源世界，比賽不會等待十億美元的市場在它產生影響的時候形成。由Chef 和 Puppet 鋪墊了的 Salt 和 Ansible 在市場的上升就是一個證明。

社區付出了，社區也拿走了 ​

你會發現同樣的動態在CMS中(Drupal 、Joomla 、 Alfresco 、 Wordpress 以及無數的其它 CMS)，在雲中(Eucalyptus 、 OpenStack 、 CloudStack 、 CloudFoundry 、 OpenShift 及其它)，在web 服務器中，在關係和非關係的資料庫中。

開源資料庫數量的膨脹伴隨着幾乎每天都產生的新對手，正如DB-Engines database tracking service中可以看到的一樣。或許最好玩的是開源關係資料庫領域，直到最近MySQL支配這個領域。Postgers 也是和 MySQL 賽跑，雖然是老二，但是排得非常後。

現在事情都在變化，或者騷動。很大程度因為 Oracle 的所謂的對 MySQL 社區的踐踏，Postggres 在最前沿的 MySQLer中炙手可熱。MariaDB 也是這樣。雖然還是一個小傢伙，比如RedHat Fedora和Ubuntu等Linux發行版內置資料庫更換成MariaDB了，Google換掉了MySQL等。

或許就像O'Grady説的，這歸結為開發者的偏好。如果開發者佔據主要地位，小小的可以阻礙他們向更合適自己的新項目轉換的障礙，會導致秩序混亂。如果這有道理，將會很好解釋開源為什麼拒絕長期壟斷。

很難讓開發者保持樂觀。

做一筆社區友好的生意 ​

對於想要對已有的開源項目投資的企業，這意味着什麼呢？一個簡單的、也許沒有不令人滿意的答案是企業應該投入到項目中，確定他們的可持續性，並且給予企業能力去支持他們自己。

但是大部分企業不想自己碼出最好的代碼。

相反，他們會去尋找受歡迎程度高的項目，非常適合企業的需求的，而且還有很強的社區的。如果項目在社區變得沒什麼意思的時候，歡迎程度可能會飛躍。最基礎的原因，Linux已經在操作系統之巔呆了很久了，已經適應社區影響和需求。

不幸的是，沒有什麼方法去真正衡量一個開源社區的活力。一些成功的項目，比如OpenStack，取決於強大的基礎。其他的，像Linux，取決於強大的個人和他的幫手。

但是所有成功的開源項目維持了他們強勁的熱度，每幾個月就會有一個發行版。快速發展的項目會非常難以供企業支持。

企業應該怎樣避免開源項目荒廢的風險呢?
