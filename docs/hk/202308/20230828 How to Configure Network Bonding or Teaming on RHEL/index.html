在 RHEL 上配置網絡綁定（成組） ​

網絡 綁定Bonding（成組Teaming） 是 Linux 的一項內核特性，它讓我們可以將多個網絡接口（例如 ens192、ens224）聚合為一個專有的虛擬網絡接口，被稱為通道綁定（bond0）。這樣做能夠提升吞吐量並增加冗餘備份。

網絡綁定一共支持 7 種模式，你可以根據實際需求進行設置。鏈接聚合控制協議Link Aggregation Control Protocol（LACP）， 即模式 4（802.3ad）因其支持鏈接聚合與冗餘而被廣泛應用。

在本篇文章中，我們將引導你學習如何在 RHEL 系統中配置網卡（網絡）綁定。

LACP 綁定的前置條件 ​

  • 網絡團隊需要在網絡交換機的端口上開啓 LACP（802.3ad）來實現鏈接的聚合。
  • 一個 Linux 系統應該配備至少兩個網絡接口。
  • 對於物理服務器，我們推薦在板載接口與 PCI 接口間進行綁定配置，以避免在主機端的網絡卡出現單點故障。

Bonding 模組 ​

你可以使用 lsmod 命令來確認你的 Linux 系統是否已經加載了 bonding 模組。

lsmod | grep -i bonding
bonding               12451  0

系統應該默認已加載。如果未看到，可以運用 modprobe 命令進行加載。

modprobe bonding

創建綁定接口 ​

在 /etc/sysconfig/network-scripts/ 路徑下，創建一個名為 ifcfg-bond0 的綁定接口文件。依據你的網絡情況，你可能需要修改諸如 IP、MASK 以及 GATEWAY 等值。

vi /etc/sysconfig/network-scripts/ifcfg-bond0
TYPE=Bond
DEVICE=bond0
NAME=bond0
BONDING_MASTER=yes
BOOTPROTO=none
ONBOOT=yes
IPADDR=192.168.1.100
NETMASK=255.255.255.0
GATEWAY=192.168.1.1
BONDING_OPTS="mode=4 miimon=100 lacp_rate=1"
參數描述
BONDING_MASTER=yes表示設備是一個綁定主設備。
mode=4綁定模式是 IEEE 802.3ad 動態鏈接聚合（LACP）。
miimon=100定義以毫秒單位的 MII 鏈路監測頻率，這決定了多久檢查每個從屬鏈路的狀態一次以尋找失敗的鏈路。0 值將禁用 MII 鏈路監測。100 是個不錯的初始值。
lacp_rate=1一個設置項，規定我們將以何種頻率要求我們的鏈路夥伴每秒鐘發送 LACPDU。默認為慢，即 0。

配置第一個子接口 ​

修改你希望添加到綁定中的第一個子接口。請根據你的實際環境使用合適的接口名。

vi /etc/sysconfig/network-scripts/ifcfg-ens192
TYPE=Ethernet
BOOTPROTO=none
DEVICE=ens192
ONBOOT=yes
MASTER=bond0
SLAVE=yes

配置第二個子接口 ​

修改你希望添加到綁定中的第二個子接口。請根據你的實際環境使用合適的接口名。

vi /etc/sysconfig/network-scripts/ifcfg-ens224
TYPE=Ethernet
BOOTPROTO=none
DEVICE=ens224
ONBOOT=yes
MASTER=bond0
SLAVE=yes

重啓網絡服務 ​

重啓網絡服務以激活綁定接口。

systemctl restart network

驗證綁定配置 ​

你可以藉助 ip 命令 來查看綁定接口以及其子接口的情況。可以看到，bond0 現在已啓動並在運行。

容錯/冗餘測試 ​

為了驗證容錯性和連接速度，你可以逐個斷開接口，然後檢查服務器是否仍舊可達。

  • 測試用例-1：當兩個子接口都啓動並運行時，使用 ethtool 命令 檢查鏈路速度。
  • 測試用例-2：斷開第一個子接口，然後嘗試訪問系統。
  • 測試用例-3：斷開第二個子接口，然後嘗試訪問系統。
